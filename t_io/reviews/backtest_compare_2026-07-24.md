## 三、回测链路 0 成交：根因与修复验证

### 根因（按发现顺序）

1. **恒宽松日线上下文**（主因）：`_build_daily_context` 原返回恒 range/恒 bull/无破位/无过热，实盘的 +20 regime 分、+20 破位分在回测中永远不存在，分数分布与实盘脱节，到不了推送阈值。
2. **冷却用真实时钟**：`_now()` 取真实时间，回测里第一笔交易的 30 分钟真实冷却封死整个回测期。→ `SIM_NOW` 逐分钟注入。
3. **`except: continue` 静默吞异常**：`ModuleNotFoundError: No module named 'tushare'` 等被吞掉，trial 表现为"正常但 0 成交"。→ 新增 n_signals/n_pushed/n_blocked_qty/n_exceptions/first_exc 诊断计数。
4. **虚拟成交账跨日累积**：`VIRTUAL_TRADES` 不清空，仓位计算被历史污染。→ 按日清空（与实盘每日重置一致）。
5. **节假日/无 tushare 单日缺失炸掉整个 trial**：`_load_cached` 下载路径无容错。→ try/except 按空数据处理。
6. **（V1.30b 补丁）config.py 顶层 `import akshare`**：托管 Python 无 akshare，trial 直接 FAILED。→ optimizer 内置 akshare mock（数据全部来自本地缓存，mock 无行为影响）。
7. **（V1.30b 补丁）无闭环一律 -9999**：温和市买分天然够不到推送阈、闭环稀少，所有 trial 同分 -9999，寻优失明。→ 有信号/推送的 trial 用未配对成交的盯市盈亏给弱分（-100±50 区间），无信号才 -9999。**仅改评分公式，未动任何买卖阈值。**

### 修复前后对比

| 口径 | 修复前 | 修复后 |
|---|---|---|
| 2025-06~08（3 个月） | 0 成交，composite=-9999 | n_signals=943 / n_pushed=42 / n_blocked=38 / n_exceptions=0 |
| 2025-06 单月（600176） | 0 成交，-9999 | n_signals=80 / n_pushed=20 / n_blocked=16 / 0 异常 |
| quick 3 trials | 2/3 FAILED（akshare/tushare 导入） | 无 FAILED，composite 梯度 -100.02 / -100.00 / -99.99 / -99.98 |
| best_params | 恒等于默认值 | 可区分优劣 |

说明：温和期闭环（卖→接回）稀少是**实盘真实现象**——买分天花板约 45-60，而全局买入推送阈 68、个股 40-43，大多数日子买入侧够不到推送阈；这不是回测故障。07-24 这种波动日才有密集闭环（见下节回放）。诊断计数现在能把"引擎无信号 / 推送阈过滤 / 仓控 0 股 / 异常"四层漏斗分开呈现。

### 方法

`replay_day.py` 在**完全相同的数据输入**下跑三组：

- 数据：实盘当日落盘的 1 分钟线 `t_io/cache/minute_{code}_2026-07-24.csv`（242 根）+ tushare_mins 历史 5 分钟线聚合日线（截至 07-23，无未来函数）；

  - **A 基线+实盘regime**：基线 worktree（847c691）代码 + regime 按实盘 decision_trace 重建的抖动时间线（09:42 uni_down → 10:13 range → 10:46 uni_down）；
  - **B 修复+实盘regime**：修复版代码 + 同一抖动时间线；
  - **C 修复+regime锁定**：修复版代码 + 全天锁定 07-23 EOD 判定（range）——即 `index_regime_intraday_lock` 生效后的实盘行为；

### 保真度说明（重要）

回放推送序列与实盘 13 次推送**不完全一致**（基线回放 54 推 vs 实盘 13 推），三个系统性原因：

1. 实盘扫描看到的是**形成中的当分钟 K 线**（如 09:43:27 价格 0.974），回放只有**已完成 K 线**（09:43 收 0.988），单根 K 线内 ±1.4% 的价格差可直接改变分数档位；
2. 实盘日线上下文来自 akshare 实时日线（180 天窗口），回放用本地 5 分钟线聚合（279 天），均线/破位标记略有差异；
3. 实盘每 2-3 分钟扫描一轮，回放每分钟评估。

分数量级与方向一致（锚点：600176 09:43 实盘卖分 64.3 vs 回放 56.6；000988 买分实盘峰值 53.2 vs 回放 46.4），但本报告不对逐 tick 对齐做承诺。**对照的科学性在于三组回放共享完全相同的输入，差异仅来自代码版本与编排逻辑**——这正是"修复是否生效"所需的隔离变量。

## 五、数据质量与遗留说明

1. **pre_close 陈旧（未修，同输入复现）**：实盘 holdings.json 的 pre_close 为 1.07/43.0/3.77/55.36/113.15，真实 07-23 收盘为 0.98/38.36/3.94/52.75/111.91。`today_ret` 因此被系统性放大（如 600176 按 -12% 计）。三组回放使用同一陈旧输入，不影响组间对比；建议后续用 `daily_prev_close_real` 校正 holdings 的 pre_close。
2. **+13018 伪影机制**：V1.28 的 record_trade_action 不带 price，账面记录 price 缺失/为 0 时以 avg_buy=0 参与利润公式，且 `_last_sig_price` 是引擎级单值、存在跨股票价格串扰。回放链路中 record_signal 总会先设置信号价，故无法复现该伪影；实盘侧已由 record_trade_action 的 price 参数（signal_engine.py:398）+ 审计价格守卫（main.py:745）+ 同步前校验（main.py:791）三层封堵。
3. **轮次上限的参数层级**：推送拦截处读全局 `PARAMS["max_t_cycles_per_stock"]=4`（main.py:1322），个股 588170=5 在此不生效。未强行改（涉及阈值语义），记录待决策。
4. **正 T 首买 max_buyable=0 的设计缺陷**：未动（未在本次范围内，sizer 买入逻辑保持原样）。
5. **买入推送阈与买分量纲**：温和期买分天花板 ~45-60，全局买入推送阈 68 下买入推送天然稀少——实盘真实现象，非故障，供后续参数决策参考。
6. **基线环境保留**：worktree `/e/06_T_baseline`（detached @ tag `baseline-2026-07-24-pre-fix`）保留，供随时复跑对照；确认无需后可 `git worktree remove` 清理。
7. **回放产物**：`E:\06_T\t_io\replay\{baseline_trace,fixed_trace,fixed_locked}\` 各含 events.jsonl + summary.json（修复版另含 shadow_signals_2026-07-24.jsonl）。
