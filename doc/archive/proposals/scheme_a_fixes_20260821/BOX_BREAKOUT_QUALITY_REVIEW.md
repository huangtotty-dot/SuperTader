# 箱体突破判定质量深度审查（2026-08-24）

## 一、现状问题诊断

### 1. GUI中的箱体检测（_detect_boxes）— 核心缺陷

**方法论问题：**
- **分位数定义不合理**（1346行）: 使用 88/12 分位数定义上下沿
  - 问题：高点落在88分位数的箱体其实不是"真箱体"，而是统计意义的箱型分布
  - 结果：生成的箱体边界易突破，不稳定
  - 应该：用 高点聚集度（N日内触及次数）而非分位数来定义稳定边界

- **触及认定太松散**（1334-1335行）:
  ```python
  _up_touches = np.sum(wh >= (ups * 0.992)[:, None], axis=1)  # 92.8% 以上算"触及"
  _dn_touches = np.sum(wl <= (dns * 1.008)[:, None], axis=1)  # 100.8% 以下算"触及"
  ```
  问题：容差0.8%-8.8%，导致**距离接近就算触及**，不够严格
  - 方案A验证（2026-08-19内存）：60min连续底背离才有效，说明单次信号质量很差
  - 建议：改为精确触及（exact touch = 在边界0.2%内，或明确回踩后回升）

- **置信分计算权重不当**（1350行）:
  ```python
  conf = (up_touch + dn_touch) * 1.5 + max(0, 1 - rel_slope / 0.005) * 3 + ...
  ```
  - 触及次数权重最大（×1.5），但触及本身就不严格 → 虚假高置信
  - 应该：触及质量（精确度）> 触及次数

- **横盘判定阈值太高**（1346行）: `rel_slope < 0.005` 即 0.5%/天
  - 这意味着30天窗口允许15%的振幅还算"箱体" → 太宽松
  - 实际有效箱体应该：<0.2%/天 的横盘度，或波动系数<3%

- **宽度范围3-22%太宽**（1346行）:
  - 3%的箱体和22%的箱体突破意义完全不同
  - 应该分类：微箱体(3-8%) / 正常箱体(8-15%) / 宽幅箱体(15-22%)
  - 不同宽度的突破质量权重应该不同

### 2. 突破判定（check_box_breakout）— 阈值生硬

**现状**（916行）:
```python
if 0.3 <= pct_above <= 8:
    return {"broken": True, ...}
```

问题：
- 0.3% 算"突破" → 太敏感，一个波动就触发
- 8% 的上限为什么设？没有数据支撑
- "突破"和"可靠突破"混淆 → 导致Hunter中判断质量差

建议分级：
- **信号级突破**（0.3-1%）：仅提示，不可作为建仓条件
- **可靠突破**（1-5%）：需辅助确认（量能/形态）
- **强势突破**（5%+）：高概率有后续，可以加分

### 3. 刚突破判定（rel=1）— 参数生硬

**现状**（1374行）:
```python
elif last_close > b["high"] and days_since <= 20 and (last_close - b["high"]) / b["high"] < 0.15:
    b["rel"] = 1  # 刚突破
```

问题：
- "刚突破"的定义：20天内 + 距高点<15%
- 20天是凭感觉，15%上限也没根据 → 很多真突破被误判为"历史箱体"
- 建议：改为动态，基于箱体宽度来定
  - 宽箱体：20天+20%
  - 窄箱体：10天+10%

### 4. 箱体合并（1384-1406）— 逻辑过度合并

**现状**:
```python
price_overlap > price_span * 0.5 and t_overlap  # 价格重叠>50% + 时间重叠
```

问题：
- 50%的价格重叠意味着：高度分别为100和100的两个箱体，只要低点差距>50就不合并
- 实际中可能把完全不同的两轮箱体（比如8月和7月）合并了
- 时间重叠条件也太松：`a["end"] > b["start"]` 只要时间线有交集就算

结果：
- 失去历史箱体的阶段性特征
- 无法区分"第一轮箱体"vs"第二轮箱体突破"

### 5. Hunter中的新高判定 — 简陋

**现状**（scorer.py）:
```python
D1: 最高 > 近150日最高  → 8分
D2: 近5日涨幅>20% && 最高>近20日最高  → 6分
D5: 最高 > 近10日最高  → 2分
```

问题：
- 无箱体概念，纯粹是"新高"判定
- "近N日最高"和"箱体上沿突破"是两个不同概念，混用了
- 没有质量评估（是否伴随量能、是否是强势形态等）

## 二、根本原因

1. **缺乏微观验证**：没有用实盘数据验证各参数的有效性（像方案A那样做divergence验证）
2. **参数来自经验，不来自数据**：0.3%, 8%, 20天, 15%, 45天, 88分位数都是"感觉"
3. **混淆两个概念**：
   - "箱体存在" vs "是否在箱体内" vs "突破质量"
   - "新高" vs "突破箱体" vs "有效突破"
4. **没有分级**：所有突破一视同仁，不区分强弱
5. **各系统独立**：GUI、Hunter、position_builder 箱体判定各自为政，导致互相矛盾

---

## 三、深度修复方案

### Phase 1: 理论统一 + 数据验证

**第1步：定义统一的箱体概念**
- 箱体 = 近期支撑+阻力区间，必须满足：
  1. 横盘度 < 0.2%/天（30日内涨跌幅<6%）
  2. 上下边界各被精确触及 ≥2 次（在边界0.2%内）
  3. 存在时间 ≥ 5 天
  4. 宽度 > 2%（太窄的箱体无意义）

**第2步：验证突破阈值**
- 用过去6个月的数据回测：
  - 定义"有效突破" = 突破后3日内继续上涨+5%（或不回踩）
  - 测试不同的突破幅度阈值（0.3%, 0.5%, 1%, 2%...）
  - 找出最优的灵敏度/特异度 trade-off

**第3步：分级突破质量**
- 基于：突破幅度、箱体宽度、是否伴随量能、是否创新高
- 输出：信号级 vs 可靠级 vs 强势级

### Phase 2: 重建检测算法

**新_detect_boxes逻辑**:
1. 30日滑窗 → 计算高/低的标准差而非分位数
2. 逐日检测边界是否被精确触及（in_range机制）
3. 用聚类（DBSCAN）合并价格相近的触及点，确认边界稳定性
4. 计算置信分 = (触及质量分 + 时间持久度 + 宽度合理性) / 3
5. 严格的时间分类：
   - 进行中（last 5-10日内最后一次触及）
   - 近期完成（>10日, ≤45日）
   - 历史（>45日）

**新check_box_breakout逻辑**:
1. 按箱体分类返回不同等级
2. 突破 = current > high + 0.5% 且保持 > high
3. 强势突破 = 突破 + 量能确认 + 无回踩
4. 加仓条件：仅用强势突破 + 高置信箱体

### Phase 3: 统一各系统

- **t_gui.py**: 改进_detect_boxes和check_box_breakout，参数数据驱动
- **Hunter**: 改用新的突破判定，分级评分
- **position_builder**: 用新的高置信突破作为加仓条件
