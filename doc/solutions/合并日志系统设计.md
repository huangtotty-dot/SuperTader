# 合并日志系统设计（自动 + 手动双通道）

> 版本：V1.0（2026-08-28）
> 背景：合并后系统同时跑两条交易链——**auto**（execution/auto，掘金新终端模拟盘自动交易）与
> **manual**（superTrader 人工辅助做T/建仓/加仓）。本文定义统一日志系统：一套事件底座、
> 双通道标注、单文件单写者纪律、统一复盘消费。
> 盘点依据：2026-08-28 两侧日志体系全量盘点（写入方/消费方/schema/量级逐文件核实）。

---

## 1. 现状对照（盘点结论）

| 功能 | manual（superTrader） | auto（goldminer → execution/auto） | 处置方向 |
|---|---|---|---|
| 事件总线 | 无 | `events_*.jsonl`（signal/order/fill/reject/risk/buyback_*，schema `event/time/code/_ts`） | **作统一底座**，manual 侧按同 schema 接入 |
| 心跳 | 无（靠 sys log mtime 间接判断） | `heartbeat.json`（覆写）+ `heartbeat_*.jsonl` + watcher 看门狗 | auto 沿用；manual 增补轻量心跳 |
| 决策审计轨迹 | `decision_trace`（~4200 行/日）+ `sizing_advice` + `shadow_signals` | `backtrace.jsonl`（no_signal 主导）+ `signals_*.jsonl` | **同构保留**，各写各的，复盘层并列消费 |
| 成交/委托 | 无（人工下单，`closure_audit` 事后推定） | `order/fill/reject` 事件 | auto 独有保留；manual 成交走 reconcile 快照，不进事件总线 |
| 日盈亏账 | `daily_pnl.jsonl` + `closure_audit.jsonl` | 无（由 heartbeat positions/cash 推） | manual 沿用；auto 由复盘层从事件桥+持仓推 |
| 推送留痕 | **无**（只有 `*_pushed.json` 去重标记） | `pushes_*.jsonl`（title/level/sent，watcher 每次推送落一条） | **移植到 manual 侧**（补缺口） |
| 推送去重 | `*_pushed.json` 文件 | watcher 内存去重 | 各保各的（文件级更抗重启，manual 不劣化） |
| 控制台落盘 | `t_trader_sys_{date}.log`（logging） | `strategy_{date}.log`（stdout tee） | 保留双文件，统一目录 |
| 风控开关 | 无 | `KILL_SWITCH` 文件 | auto 独有保留 |
| 大盘/情绪轨迹 | `sentiment_daily` / `index_regime` / `index_resonance` / `pivot_audit` / `preopen_trace` | heartbeat 内嵌两字段 | manual 独有保留，auto 只消费结论 |
| 数据质量 | `data_quality_*.jsonl` | 无 | manual 保留；P4-4 后 auto 数据链共享 provider 即共享此轨迹 |

死文件清理项（盘点发现）：goldminer 根目录 `live_log.txt`/`watcher_log.txt` 为 bootstrap_logging 之前的历史残留，无代码写入点，迁入归档时可删；`follow_log.jsonl` 两侧均不存在（旧复盘清单引用已失效）。

## 2. 目标架构

```
                        ┌──────────── 统一事件头 schema ────────────┐
                        │ {event, time, code?, channel, _ts, ...}   │
                        └───────────────────────────────────────────┘
                                          │
   auto 通道（execution/auto）             │             manual 通道（superTrader 主进程）
   t_io/bridge/                            │             t_io/traces/ + t_io/logs/
   · events_{date}.jsonl   （写者：auto）  │             · decision_trace / shadow_signals /
   · heartbeat.json + heartbeat_{date}     │               renko_t / position_builder /
   · signals_{date}.jsonl                  │               sizing_advice / data_quality /
   · pushes_{date}.jsonl                   │               index_resonance / preopen_trace …
   · KILL_SWITCH                           │             · manual_signals_{date}.jsonl ★新增
                                          │               （manual 侧需入总线的事件：建仓 signal
                                          │                推送、时机门 veto 触发——P3 同源核验点）
                                          │             · pushes_{date}.jsonl ★移植（推送留痕）
                                          │             · heartbeat_manual.json ★新增（轻量心跳）
                                          ▼
                        统一消费层（只读，不改写）
             · GUI 自动盘页（t_io/bridge/，已落地 P4-3）
             · GUI 手动页（t_io/traces|state，现有）
             · 复盘脚本（daily_review / 复盘清单 A/B/C 分区数据源）
             · watcher → 飞书（auto 事件；manual 推送仍走 main.py 直推）
```

### 2.1 硬纪律

1. **单文件单写者**：每个 jsonl/log 有且只有一个写入进程。`t_io/bridge/events_*` 只有 auto 写；
   manual 侧要进总线的事件一律写 `manual_signals_{date}.jsonl`（实施方案 P4-2 已定），不得写 events。
2. **channel 字段必填**：进统一消费层的事件必须带 `channel: "auto" | "manual"`，复盘/GUI 按通道分栏。
3. **只增不改**：jsonl 一律 append-only；状态类文件（heartbeat/holdings）才允许覆写。
4. **运行时产物不入库**：`t_io/bridge/`、`t_io/traces/`、`t_io/logs/` 全部 gitignore（P4-1-fix 已处理 execution/auto 下误入产物，同纪律）。
5. **schema 演化只加字段不改义**：已有事件字段语义冻结（goldminer 事件 schema 红线延续）。

### 2.2 通道各自补齐（最小新增）

| 项 | 侧 | 内容 | 时机 |
|---|---|---|---|
| `manual_signals_{date}.jsonl` | manual | manual 侧需对账的事件：建仓 signal 推送（含 verdict/veto/regime/score）、池分管拦截 | P4-6 接线时 |
| `pushes_{date}.jsonl` 移植 | manual | `send_feishu_payload` 每次调用落一条（title/level/sent/耗时）——补 manual 推送无留痕缺口 | 随手可做 |
| `heartbeat_manual.json` | manual | 主循环每轮覆写 `{time, pid, scan_count, last_scan_ts}`——补 manual 无心跳缺口，GUI/复盘可判活 | 随手可做 |
| auto 日志落位 | auto | 新终端策略 stdout tee → `t_io/logs/auto_strategy_{date}.log`（沿用 ops_guard 机制，路径迁 superTrader） | P4-4/P4-5 |

### 2.3 复盘消费对应（与《合并复盘体系统一设计》§3 分区衔接）

- 公共节 A-1 盈亏：manual=`daily_pnl.jsonl`+`closure_audit.jsonl`；auto=事件桥 fill + heartbeat 持仓推。
- auto 分区 B：events（reject/order/fill/risk）、pushes、backtrace（决策审计迁入后路径 `t_io/logs/auto_backtrace.jsonl`，保持单写者）、heartbeat 连续性。
- manual 分区 C：traces 全家桶（decision_trace/position_builder/sizing_advice/renko_t）+ manual_signals + 前瞻表 state。
- 一致性 A-2：`manual_signals` 与 auto `events` 中同池标的的 verdict 抽查（parity 机制的日内版本）。

## 3. 迁移步骤

1. **已就绪**（P4-1/4-2 已落地）：`t_io/bridge/` 目录 + writer 指向 + GUI 自动盘页读取——直接复用。
2. backtrace 迁入：auto 决策审计从 goldminer `gmcache/backtrace.jsonl` 改落 `t_io/logs/auto_backtrace.jsonl`（P4-4 适配时一并改，schema 不变）。
3. manual 侧三小件（manual_signals / pushes 留痕 / heartbeat_manual）：独立小 commit，不碰现有 traces 写入逻辑。
4. 新终端策略日志路径适配（P4-5 部署时）：stdout tee 落 `t_io/logs/auto_strategy_{date}.log`。
5. 复盘脚本数据源表更新（daily_review.py 等）：新增 auto 分区数据源，manual 数据源不变。

## 4. 明确不做的事

- **不改造 manual 现有 traces 的 schema/文件布局**——4200 行/日的 decision_trace 等链路在生产跑得稳，统一只发生在"事件头消费层"（复盘/GUI 按 channel 分栏），不动写入侧。
- 不给 manual 侧强加 auto 的事件总线写法（人工链路的"事件"粒度与频率不同，硬套只会造噪音）。
- 不在日志系统里做告警逻辑（告警仍归 watcher/GUI 横幅，日志只负责留痕）。
