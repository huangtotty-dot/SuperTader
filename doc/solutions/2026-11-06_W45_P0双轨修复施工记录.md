## 三、⑲＋㉒＋㉓：订单、额度与恢复

### 3.1 重要执行语义变化

**旧方案中“按涨停价预留并缩小委托数量”的尝试已废弃。** 新语义为：

- 参考价仍负责原有 sizing，保持原委托数量，不因涨停价预留而极端缩量。
- 实际 BUY 使用由参考价向下取到分的限价；允许 `bounded-not-filled`，即不成交也不追价。
- 不再以市价回退、保护价或事后 summary 冒充额度保证。
- 该变化会影响成交率：价格未触及限价时，原数量委托可以不成交。生产启用前必须知情接受这一语义。

Decimal 与整数分用于价格、数量和额度计算，删除 `cap+1e-7` 一类可能多出一手的做法。

### 3.2 日额度硬约束

对每笔买单分别记录：

- `actual`：真实成交数量 × 原始 VWAP；缺 VWAP 时不编造成交额。
- `reserved`：未成交余量 × 实际委托限价。
- `committed = actual + reserved`：当前实际成交与在途委托的合并占用。
- `budget_bound_breaches`：真实成交越过委托限价、恢复无法证明上界等异常。

新 BUY 只有在单票、日额度和现金三类约束都能容纳“原数量 × 实际限价”时才发送；余量不足则 `qty_placed=0`，不缩小数量凑单。真实成交若异常高于限价，保留真实价量费、记录 breach 并阻断后续 BUY，不篡改历史成交。

因此，硬顶来自**委托前的 committed 约束与柜台限价上界**。若真实柜台违反限价或字段无法核验，系统只能留痕、闭锁并对账，不能宣称事后把既有成交变回合规。

### 3.3 SDK 前意图、未知结果与重启恢复

新增 `execution/auto/oversold_gap_confirm/order_intents.py`：

- 每笔 SDK 调用前原子持久化唯一 `intent_id`、数量、参考价和实际限价上界。
- 意图或 ACK 落盘失败，当前及后续 BUY 闭锁；预留写失败时保证零 SDK。
- 下单或轮询发生 `TimeoutError`、其他异常、空 order ID 等无法证明柜台结果的情况，统一记为 `unresolved`，保留原数量、余量和预留，不再作为终态 `error` 释放。
- 重启先按 order ID 对账；无可靠 ID、恢复查询失败、结果仍未知或恢复写回失败，继续禁止新 BUY，不猜 poll、不重复下单。
- 只有取得可核验的成交、拒单、撤单或过期事实后，才按事实结算。

- raw 4/8 = rejected，5 = cancelled，12 = expired，6 = pending；按 `order_id + raw_status + terminal` 逐单处理，不按股票代码笼统释放。
