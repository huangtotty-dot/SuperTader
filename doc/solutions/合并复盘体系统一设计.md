# 合并复盘体系统一设计

> 版本：V1.0（2026-08-28）
> 背景：自动化（goldminer，旧掘金终端模拟盘）与人工（superTrader）两条交易链合并为一个系统。
> 两侧各有一套复盘体系，合并后**只保留一份清单**承载日复盘与周复盘；历史复盘全部保留作借鉴回顾。
> 上位文档：`合并实施方案.md`（2026-08-28 决策修正：旧 goldminer3 仓库冻结，改动一律落 superTrader 仓内）。

---

## 1. 现状盘点

### 1.1 两套复盘资产

| 侧 | 清单 | 历史复盘 | 特点 |
|----|------|----------|------|
| auto（goldminer） | `docs/每日复盘清单_掘金模拟盘.md`（K3 版，v1.3） | `docs/每日复盘/复盘_2026-07-27~08-27`、`docs/每周复盘/`（W31/W32）、`docs/回测复盘/`（fix1~fix8 审核报告、WP 施工手册）、`docs/backlog/` | 偏**执行质量与风控**：拒单归因、滑点、事件桥对账、心跳、KILL_SWITCH、费用口径、Phase A~D 进度、三分类处置（执行bug/结构问题/数值观察） |
| manual（superTrader） | `doc/review/日复盘/每日复盘清单.md`（V2.4）、`doc/review/周复盘/每周复盘清单.md` | `doc/review/日复盘/`（08-19 起）、`doc/review/周复盘/`（W33/W34） | 偏**信号质量演化**：六阶段逐一验收（S0~S5）、加仓/建仓前瞻表滚动结算、Renko 做T逐笔验证、新鲜度闸/水位线/转化漏斗、候选登记→周六管线 |

### 1.2 重叠与互补

- **重叠**：都有"当日异常归因""候选只登记不改参/阈值""周六聚合深度复盘"的纪律骨架——合并无冲突。
- **auto 独有**：拒单/滑点/费用/心跳/事件桥对账/飞书推送对账（C1 执行质量）、风控状态（C3）、三分类处置表、Phase 进度跟踪。
- **manual 独有**：六阶段时间流验收、前瞻表滚动结算机制、质量水位线、转化漏斗、实现健康检查（否决因子/数据不足/timing_gate 故障）。
- **结论**：两份清单是同一骨架上的两套"分区检查项"，合并 = 一个骨架 + 两个分区 + 公共节。

## 2. 归档方案（历史不丢弃）

```
doc/review/
├── 复盘清单.md                  # ★ 合并后唯一清单（本文 §3）
├── 日复盘/                      # manual 历史 + 合并日起的当日复盘（双侧内容合一份报告）
├── 周复盘/                      # manual 历史 + 合并日起的周复盘
└── archive/
    └── goldminer/               # 旧 goldminer docs/ 复盘资料整体迁入，只读归档
        ├── 每日复盘/            #   复盘_2026-07-27 ~ 08-27（含 evidence 目录若有）
        ├── 每周复盘/            #   W31/W32、regime 审计、Phase 提案
        ├── 回测复盘/            #   fix1~fix8 审核报告、WP 施工与验收手册、回放包说明
        ├── backlog/             #   WP-A1/B18/B22 方案、fix5 观察日志
        ├── 修复方案/
        └── 每日复盘清单_掘金模拟盘.md   # 旧清单原件存档（版本定格 v1.3）
```

纪律：

1. **归档只搬不改**：历史复盘文件内容一律不改写，保持原始语境（其中引用的旧路径、旧机制不再有效，阅读时以本文为准）。
2. 迁入用 `git mv` 等价操作保留可追踪性；旧仓库内对应目录留一个 `MOVED.md` 指针（注明新位置与冻结日期）。
3. 旧清单中仍有生命力的机制（三分类处置、红色判定标准、推送对账）**移植进新清单**（§3 标注来源），不以"看旧文件"为前提。

## 3. 统一清单结构（合并日复盘/周复盘唯一清单）

新清单落 `doc/review/复盘清单.md`，骨架如下（★=新增/合并节）：

```
〇、总判定与六阶段总览表（沿用 manual §0；auto 侧对应项并入 S2/S4）
一、盘前检查
   · 公共：持仓 reconcile、t_qty 铁律、日历事项
   · auto 分区：策略进程/watcher 在线、heartbeat 刷新、KILL_SWITCH 不存在、模拟账户隔夜一致（原 P-1~P-6）
   · manual 分区：竞价采集非空、preopen 焦点名单（S0）
二、收盘复盘主清单
   A. 公共节
      · A-1 当日盈亏分解（三栏归因口径：做T差价/风控损益/基线调整/止盈兑现，auto+manual 各一行 + 合计）
      · A-2 一致性：模拟 vs 回测 / 双侧同池标的 verdict 抽查（P3 parity 机制日检）
      · A-3 异常三分类处置（①执行bug随时修 ②结构问题进backlog ③数值只记录——移植自 auto 清单）
   B. auto 分区（执行质量与风控）
      · B-1 执行质量：拒单=0 且逐条归因 / 信号→委托延迟 / 滑点 / 尾盘归位 / 费用口径（原 C1）
      · B-2 事件桥对账：events 与飞书通知逐类对账、backtrace 落盘、推送留痕（原 C1-5/C1-6 + pushes 留痕）
      · B-3 信号与通道：通道分布、no_signal 可解释性、建仓闸 verdict 分布（原 C2；双通道观察项随 P4-6 接线改为时机门口径）
      · B-4 风控状态：仓位峰值/现金水位/止损/熔断/地板/绞肉机/MA5破位纪律（原 C3）
   C. manual 分区（信号质量演化）
      · C-1 加仓质量跟踪 + 前瞻表（原 §3）
      · C-2 建仓质量跟踪 + 前瞻表 + 实现健康检查（原 §4，含否决因子/数据不足/timing_gate 故障三项）
      · C-3 做T：系统指引 vs 用户操作 + Renko 逐笔验证（原 §4.5/§4.6）
      · C-4 持续质量层：新鲜度闸/水位线/转化漏斗（原 §8）
三、候选登记（只登记不改参，周六统一处置；红线沿用：单日现象不改阈值、单笔不驱动变更）
四、每日输出
   · 飞书简报一屏（双侧合并版式：auto 执行/风控一行 + manual 信号质量一行 + 异常逐条）
   · 本地存档：doc/review/日复盘/YYYY-MM-DD_复盘.md（含 auto 证据五件套与 manual 数据段）
```

周复盘：沿用 manual 周清单骨架，议程输入扩展为双侧——日清单的 auto 分区（拒单/滑点/regime 误判/通道分布聚合）与 manual 分区（水位线/漏斗/前瞻表结算汇总）共同喂周六议程；产出不变（模式甄别 + backlog 更新 + 下周关注 + 是否允许扩大跟随规模）。

## 4. 迁移步骤

1. 建 `doc/review/archive/goldminer/`，整体迁入旧仓库 `docs/` 下复盘资产（上表目录）；旧仓库留 `MOVED.md` 指针。
2. 写 `doc/review/复盘清单.md`（按 §3 结构；移植项标注来源与冻结版本号）。
3. 旧清单（`每日复盘清单_掘金模拟盘.md`、`日复盘/每日复盘清单.md`、`周复盘/每周复盘清单.md`）头部加一行作废指引（"2026-08-28 起由 doc/review/复盘清单.md 取代，本文件存档不更新"），正文不动。
4. 合并日起，日复盘/周复盘只认新清单；首周复盘时校验：旧两体系的关键检查项无遗漏（对照本文 §1.2 清单逐项打勾）。

## 5. 明确不做的事

- 不改写任何历史复盘内容（包括其中已过时的口径描述）——历史价值就在于原样。
- 不在迁移期并行跑两套清单（一份清单是硬约束，缺项走 §4-4 校验补进新清单）。
- auto 侧 Phase A~D 进度跟踪不并入日常清单（合并后 Phase 框架由合并实施阶段 P0~P5 取代；历史 Phase 结论已在归档中）。
