# 日线数据校准与通达信对照（2026-10-30）

> owner：「邵阳液压的数据很不正常。请对比同花顺的K线图。另外如何保证每天的数据的正确性？
> 请盘后对照通达信的数据做校准。」

## 0. 结论先说

301079 的问题**不是复权口径**，是两件数据事故叠在一起：

1. **缓存日期落后**：末行 10-26，而通达信/同花顺已是 10-30（26.40 → 28.33 → 34.00 → **36.79**）。
   图上最后一根于是被画成"从 26 跳到 36.79 的巨柱"——中间 4 根（约 +42%）全缺。
2. **盘中快照根被永久留档**：000006 的 10-27/28/29 三根量只有 23216 / 9454 / **0**，
   真实是 232279 / 158492 / 180127 手；收盘后真实值一直没回来（腾讯 `web.ifzq` 日线接口
   现在返回 **WAF 验证页**、GM 也不可达）。

全池实测（5531 只）：**5333 只尾部有问题**；另有 **5149 只历史偏短**
（301079 缓存 213 行 vs 通达信 1211 行，2021 起）——MA150/MA360/箱体/背离都会算错。

## 1. 校准工具

`core/tdx_calibrate.py` + `scripts/ops/tdx_calibrate_daily.py`

| 项 | 规则 |
|---|---|
| 数据源 | 通达信 `vipdoc/{sh,sz,bj}/lday/*.day`（32B/根；量是**股** ⇒ `/100` 得手） |
| 锚点 | 从末行往前第一个「缓存量 ∈ [0.8, 1.5]×通达信量」的重叠日（量不受复权影响；上限挡住 ETF/债券张·股单位差 100 倍） |
| 复权安全门 | 锚点比率 r=缓存收盘/通达信收盘，要求 \|r−1\| ≤ 2%，否则 `ratio_mismatch` 跳过（本次 11~12 只，全是 ETF） |
| 写入 | **锚点及更早一字不动**；锚点之后按 通达信×r **重写**（补缺失 + 修快照根）；备份 → 原子替换；`forming=[]` |

首轮：`fixed 5332 / ok 79 / ratio_mismatch 11 / no_clean_anchor 1 / no_tdx 108`。
二轮（验收）：`ok 5411` —— 全池尾部已与通达信一致。

## 2. 写路径加固（否则修完会被立刻盖回去）

`merge_daily_cache` 原来**无条件**用 incoming 覆盖同日行。实测：**002275** 在 17:07 校准后
开了次 K 线，`write_daily_history(forming_date=今日)` 又把盘中快照（vol 191932）写了回去。
现在：incoming 是 forming_date、旧行存在且**旧行不在 `forming` 里**（= 已确认）⇒ 跳过覆盖，
且不把这一天重新标回 `forming`；盘中 forming 根照旧逐轮刷新，语义不变。
测试见 `tests/phase3/test_daily_partial_bar_guard.py::TestConfirmedBarNotOverwrittenBySnapshot`。

⚠️ **该保护只在新进程里生效**：当前跑着的 GUI/main 是旧代码，开图仍可能把当日 bar 写回快照。

## 3. 每天怎么保证正确

1. `main.py` 阶段⑩：工作日 **15:40 后自动跑一次**通达信校准（`core.tdx_calibrate.run_daily_once`，
   跨进程 `.done` 标记去重，结果写日志与 `t_io/logs/tdx_calibrate_*.json`）。
2. 前提：**通达信客户端当天要下载过数据**（`tdx_last` 才会是今天）；没开就安全跳过、不改任何东西。
3. 可见性：摘要里 `behind / ratio_bad / short` 三个数每天都能看；`ratio_bad` 会点名（多为 ETF）。
4. 手动补跑：`python scripts/ops/tdx_calibrate_daily.py [--fix]`。

## 5. 历史偏短（5147 只）——修复路径与当前阻塞（2026-10-30 晚）

**为什么不能直接用通达信 `.day` 拼长历史**：通达信是不复权，缓存是前复权；想换算必须知道
每个除权日的因子。本机三个可能的来源全部实测不可用：

| 来源 | 实测结果 |
|---|---|
| 腾讯 `web.ifzq` fqkline | 返回 **WAF 验证页**（HTML），`daily_kline_raw` 全空 |
| 掘金 GM | `无法连接到终端服务器`（SDK 不可达） |
| tushare `daily` / `adj_factor` | **无接口权限**（`抱歉，您没有接口(daily)访问权限`） |
| akshare（东财） | `RemoteDisconnected` |
| 通达信 `T0002/hq_cache/gbbq`（权息档） | **已加密**：文件里找不到任何 ASCII 代码，29 字节明文格式解不出来（首个 4 字节是记录数 194422，其后并非 `B6sBIBffff`） |

**已实现的修复路径**（数据源恢复后自动生效）：
- `core/chart_cache.deepen_daily(codes, limit=600, days=800)`：先对一只**探针**取数，
  取不到就返回 `provider_down`（不逐个付超时）；⚠️ 探针还必须是**非缓存**来源
  （`facade.daily` 在 GM/腾讯都不可用时会原样返回磁盘缓存、`source=cache`——实测"看着成功、一行没多"）；可用则 `prefetch_daily(skip_current=False, days=800)` 分批拉长历史并 merge（不截短）。
- `prefetch_daily` 的全池默认深度 **200 → 800**：以后新落缓存的票一开始就是 800 行。
- `main.py` 阶段⑩：TDX 校准后，按"通达信行数 − 缓存行数"降序取前 600 只补长历史；
  5147 只约 9 天补齐（每天 600）。日志会打印 `日线补长历史：{requested/got/failed}` 或 `provider_down`。
