## 1. 策略定义（口径已冻结）

### 1.1 信号三段（`core/oversold_gap_confirm.py::signal_ok`）

```
① 超跌前提   osc_W1(D−1):  prev_close < MA20                    # 日线超跌（安全边际=便宜）
② 强开盘确认 osc_S10(D) :  bar0.low  >= prev_close              # 跳空高开、缺口未回补
              AND          bar0.close >  prev_close             # 站上昨收
              AND          bar0.close >  bar0.amount/bar0.volume # 站上分时均价(VWAP)
③ 强度       gap = bar0.close / prev_close − 1                  # 入场=10:00 收盘，无前视
```
排序 = `gap` 降序（同 gap 按 code），取 **top-N**（默认 4）。三条缺一不可，任一口径缺失
（prev_close/MA20/bar 关键价）⇒ **该票不进候选、不下单**。

判据的失败原因码（审计/日志可见）：`prev_close_missing` / `bar_missing` /
`not_weak(prev_close>=ma20)` / `gap_not_held(low<prev_close)` / `not_above_prev_close` /
`not_above_vwap`。

### 1.2 池级评估（`evaluate()`）

- 输入：`prev_close{code}`、`ma20{code}`、`bars{code:{low,close,amount,volume}}`、
  `board{code}`、`allowed_boards`、`top_n`。
- 输出：`pool_n`（有完整输入的票数）、`signals`（**含被板块过滤掉的**，可观测）、
  `picks`、`rejected_board`、`n_tradable`。
- **fail-closed 三处**：`pool_n < MIN_POOL(=3)` ⇒ picks 恒空；`top_n ≤ 0` ⇒ 空；
  缺输入 ⇒ 单票剔除。（`MIN_POOL`/`DEFAULT_TOP_N` 见 `core/oversold_gap_confirm.py:33-34`）

### 1.3 bar0 的两种数据源同构（**这是能离线研究的前提**）

| 口径 | bar0 定义 |
|---|---|
| GM 实盘 8 棒/天 | `1800s` 那根 **eob=10:00** 的棒 = 覆盖 09:30~10:00 整窗 |
| tushare 研究 9 棒/天 | `minlow2 = min(09:30 瞬时棒.low, 10:00 棒.low)` |

两者等价：GM 的 10:00 棒窗口已含 09:30；`vwap2 ≡ bar0.amount/bar0.volume`
（09:30 竞价量额可忽略）。故研究脚本与生产同构（`core/oversold_gap_confirm.py` docstring）。

### 1.4 纪律（勿破坏）

> **「改动常量/信号口径 = 换策略，须重做 exp 系列检验。」**
> —— `core/oversold_gap_confirm.py` 模块 docstring（另有同义表述：
> 「任何规则改动 = 换策略 ⇒ 预注册检验（量级预滤 0.2%、双向检验、OOS、BH-FDR）」，
> `doc/solutions/2026-10-09_账户级选股做T混合框架设计.md:17`）

信号定稿依据：`exp5`（超跌×强开盘交叉）+ `exp6`（出场规则），**两段样本均成立**。

## 2. 每日时间线（GM 实盘）

`on_bar` 由 `subscribe(frequency="60s", count=240)` 驱动（**逐票回调**，每次可能只有 1 根棒）。
整段先过一个**窗口闸**：`t < 09:30 或 11:30<t<13:00 或 t>15:00 ⇒ 直接 return`。
四个钩子都是**每日一次**（模块级 `_OSC_*_DONE_DATE` 标记，按日重置）+ **仅 MODE_LIVE**。

| 时刻 | 钩子 | 取数 | 决策 | 下单 | 产物 |
|---|---|---|---|---|---|
| **09:31** | `hooks.prepare` | facade `daily_many` × **8 批**（1551 只有分类的码 / 每批 200，40 根日线） | 涨停家数 top-5 板块 ∩ 昨收<MA20 | 无 | `context._osc_candidates` + audit `osc_prepare` |
| **10:00** | `hooks.try_morning_sell`（**先**） | `history(1800s, 09:25→now, high)` 一次批量 | `days_held==0` 的持仓 早盘 high ≥ 入场价×1.03 | SELL 全部可卖量 | `sells_morning_{date}.json` |
| **10:00** | `hooks.try_buy` | `history(1800s, 09:25→10:01)` 取 eob=10:00 那根 | 决策核 → top-N | BUY 逐票 | `fills_{date}.json` + `exec_report_{date}.json` + 入账本 |
| **14:50** | `hooks.try_sell` | `history(60s, 09:25→now, close)` 取每票**最新**收盘 | SL5只深 + 满 5 日到期 | SELL 全部可卖量 | `sells_close_{date}.json` |
| 14:57 | `_writeback_holdings` | 账户 `positions()` | — | 无 | 把实际 qty/cost 补丁回 `t_io/state/holdings_auto.json` |
| 每分钟 | 心跳（旁路） | `_get_holding` 多源对账 + `account().cash()` | — | 无 | `t_io/bridge/heartbeat.json` |

要点与陷阱：

1. **10:00 的先后顺序是刻意的**：先卖（回笼现金）再买，避免现金挤占。
2. **板块过滤在 10:00 不重复施加**：`run_buy_exec(..., allowed_boards=None)`——因为 09:31 预筛
   已把候选限定在 top-5 板块内，10:00 只做信号判定（`gm_main._osc_try_buy`）。
3. **`_osc_mode_on()` 是买/卖两侧的公共总闸**（`osc_enabled`）；卖侧另有 `osc_sell_enabled`。
   任一为 False ⇒ 对应钩子整段跳过。
4. **`KILL_SWITCH` 只拦买侧**（语义「禁止新开仓」）；卖侧照常（该卖的还是卖）。
5. ⚠️ **死参数**：`osc_exec_time_hhmm`（=1000）**无人读取**——买侧时点硬编码 `dtime(10, 0)`
   （`gm_main.py:1126`）。改它**静默无效**。同理早盘卖/收盘卖的时点读的是
   `osc_morning_sell_time_hhmm` / `osc_sell_time_hhmm`（这两个**真的在读**）。

## 3. 买侧口径（逐条）

### 3.1 两层漏斗（为什么不会逐股轮询）

owner 2026-10-10 强调「轮询速度是硬约束」。设计：**绝不逐股取数**。

```
全池 5382（watchlist_jiuyan）
  → 有主板块分类 1551（sym2board_map；25 个板块）
  → 前一日涨停家数(涨幅≥9.5%) top-5 板块内         ← 一次 daily_many 批量（31 批 × 200）
  → 昨收 < MA20 的超跌票（数十只）                  ← osC_W1 预筛
  → 10:00 一次 history(1800s) 批量取 bar0
  → 信号判定 → gap 降序 → top-4
```

⚠️ **候选宇宙只有 1551 只**（有韭研分类的），这是**覆盖上限**，不是 5382。未分类票永远不会被选中。

### 3.2 板块口径（易错点）

- 生产用**替身**：`_LU_THRESHOLD = 0.095`，「前一日涨幅 ≥9.5% 家数」最多的 top-N 板块
  （`core/oversold_gap_confirm_poll.py`）。
- **不是** `daily_summary.json` 的真实排名——exp15 里两种真实排名（涨停数/平均分）在 top-4
  组合都塌成负 Sharpe（池错配 + 候选饿死）；替身是唯一全窗可重建、且通过复验的口径。
- 板块名 = **韭研分类第一段**（含 `MERGES`：创新药/中药→医药），板块成员数中位 **56**（P25=32 / P75=93），
  最大「半导体」157 只，最小「北交所」6 只。
- 板块过滤在生产里的身份是**宇宙选择**（只轮询前 N 板块成分股），不是「信号内过滤」。

### 3.3 额度与截断（`build_buy_plan`，纯函数）

按 gap 顺序逐票：

```
cap        = min(single_budget, 剩余预算 × cash_headroom)   # 默认 min(10万, 剩余×0.95)
qty_target = floor(cap / px / 100) × 100
qty_place  = min(qty_target, floor(剩余现金 / px / 100) × 100)
```
- `剩余预算 = min(daily_budget, 账户可用现金)`（期初一次算出，逐票扣减）。
- `px` = 10:00 那根棒的 **close**（信号入场价口径）。
- 跳过条件：无价（`no_price(10:00收盘缺失)`）、**当日已持且 available=0**（`t1_locked`）、
  不足一手（`below_min_lot`）、现金不足截断到 0（`cash_insufficient`）。
- `truncated=True` 表示被现金截断（留痕）。

### 3.4 下单

- 走 `framework.GmGateway`（策略 id `osc`）：**先 `write_order`（事件桥，孤儿闸依赖）**
  → `order_volume` 市价单（`osc_limit_slippage_bp=0`；>0 时改限价 开盘价±bp）
  → `_mark_pending_recon` 登记待对账 → 解析同步拒单码 `(4,5,6,8,12)`。
- **归属硬锁**（§7）：被别的策略持有时**不下单、不落事件**，直接 `rejected`。
- 下单后轮询终态：`osc_order_poll_rounds=3` 次 × `osc_order_poll_sleep_sec=2.0` 秒。
- 每日一次标记在**下单前**就置位（`_OSC_BUY_DONE_DATE = today`）⇒ 当日不会重试
  （失败就当日不买，靠次日 picks 重评；fill 侧的拒单由 `on_order_status` 记 rejected）。

### 3.5 入账（成交后）

`register_buys_to_book`：把**非终态否决**的买单并入账本 `positions.json` 的 `open`，
字段 `entry_date / entry_price / qty / dev20 / gap / board / days_held=0 / last_check_date=None`。
- `dev20 = prev_close / ma20 − 1`（**卖侧 SL5 只深判据就靠它**）。
- 同日对同票再加仓 ⇒ 合并 qty 与加权入场价（不新增条目）。
- 拒单/被锁/错误状态 ⇒ **不入账**。

## 4. 卖侧三件套

### 4.1 次日早盘冲高卖（10:00，止盈）

`build_morning_sell_plan`：只判**次日**持仓（`entry_date != today` 且 `days_held == 0`），
早盘最高 ≥ `entry_price × (1 + osc_pop_target_pct=3%)` ⇒ 卖。
- 深/中/浅超跌**都适用**（这是止盈不是止损）。
- `days_held != 0` 的老持仓**不动**（交 14:50）。
- 时点与买侧同刻，**刻意排在买侧之前**（exp11：43% 的票 1 天就出）。

### 4.2 14:50 收盘止损（**SL5 只深**，owner 2026-10-10 拍板）

`build_sell_plan` 在 14:50 判定，优先级从上到下：

1. `entry_date == today` ⇒ 跳过（`t1_same_day`，A 股 T+1）。
2. 无价/入场价 ⇒ `no_price`。
3. **满 `osc_hold_days(=5)` 个交易日 ⇒ 到期平仓**（`horizon_expired`）——**优先于止损**。
4. **深超跌**（`dev20 < osc_stop_deep_dev20 = −7%`）且 `close < entry_price × (1−5%)` ⇒ 止损 `sl5_deep`。
5. **浅/中超跌即便跌破 −5% 也不止损**（`dev20 ≥ −7%`）——这是 owner 拍板的「SL5 只深」，
   **最容易被后人"顺手改成全止损"的一条**（组合层回撤会从 −26.3% 恶化到 −32.2%，见 §10.6）。

`days_held` 由 14:50 钩子**每天推进一次**（幂等：`last_check_date != today` 且非入场当日），
早盘卖钩子**不推进**（它只读 `days_held==0`）。

### 4.3 卖侧共用纪律

- 卖前先**账本 ↔ 账户对账**（`_reconcile_open`）：账户已无持仓（终端手工卖等）⇒ 移出账本；
  账户少于账本 ⇒ 减量。**防幽灵卖单**。
- 实际下单量 = `min(账本 qty, 账户 available)`；`available<=0`（T+1）⇒ 记 `t1_locked` 不卖。
- 卖出**不设归属锁**（各策略账本本就是卖侧真源）。
- 拒单/部分成交：账本只按 `filled_qty` 扣减（未成交部分留在账本，次日重评）。

## 7. 归属锁与框架接线（2026-10-12 新增）

- 下单走 `framework.GmGateway`（`gm_main._OscGmGateway` 绑 `STRATEGY_ID="osc"`）；
  `strategy_id` 同时是 **事件桥 `order_type` 标签 / 参数前缀 / 归属所有者名**，三者必须一致。
- **一票一策略硬锁**：买单发出前问 `framework.Ownership.can_open(code, "osc", held_qty)`。
  判据 = 各策略账本 × 账户实时持仓：
  - osc 账本持有 ⇒ 归 osc，可买；
  - 账户持有但无账本认领（旧镜像遗留 / 终端手工单）⇒ **LEGACY，对所有人锁** ⇒ 买不进；
  - 都无 ⇒ 可买。
- 被锁 ⇒ **不下单、不落 order 事件**，返回 `rejected` + `message="ownership_lock:..."`，
  并落 `risk: strategy_lock_conflict` + 审计事件。
- 人工豁免：`t_io/state/auto_ownership.json` 的 `{"overrides": {"600123": "osc"}}`
  （或 `"legacy"` 强制锁），**启动时重读** ⇒ 改文件+重启策略即生效。
- 详见 [策略框架·多策略封装设计](2026-10-12_策略框架_多策略封装设计.md) §2。

## 8. 失败语义（fail-closed 一览）

| 情形 | 现象 | 结果 |
|---|---|---|
| 预筛取不到日线 / 无热门板块 | `[OSC] 盘前超跌候选 0 只` + audit `osc_prepare` | 当日 `_osc_candidates={}` ⇒ **当日不下单** |
| 10:00 棒取数失败 | audit `osc_fetch_fail` | 当日不下单（`osc_skip:no_bars`） |
| 候选不足 `MIN_POOL` | picks 空 | 不下单，`note=no_picks` |
| 单票缺 prev_close/MA20/关键价 | 该票剔除 | 只影响该票 |
| 账户现金读不到 | 网关按 0 | 买单全部截断（`cash_insufficient`） |
| 无价（停牌） | `no_price` | 该票顺延，次日重评 |
| 当日已持且 available=0 | `t1_locked` | 不加仓 |
| 被别的策略/无人认领持仓锁定 | `ownership_lock:*` | 不下单 + 留痕 |
| 柜台拒单（同步 status∈4/5/6/8/12） | `rejected` + `message` | 不入账本 |
| 柜台拒单（异步） | `on_order_status` → `write_reject` + `risk:order_rejected` | 不入账本 |
| 归属表/override 文件损坏 | 打日志、按无 override 运行 | 锁仍生效 |
| 钩子内任何异常 | `[OSC] …失败（不阻断主循环）` + `risk:osc_*_error` | 主循环继续，当日该钩子跳过 |

**下单是幂等的吗？** 每日一次标记在下单前置位 ⇒ 同一时点不会重发。但**拒单后当日不重试**，
次日靠 picks 重评（执行器对账户状态无幂等要求）。

## 9. 运维手册

### 9.1 开关与急停

| 目的 | 动作 |
|---|---|
| 全部停手 | `osc_enabled=False` 重启策略（预筛+买+卖全停） |
| 只停买 | 建 `KILL_SWITCH` 文件（买侧拦、卖侧照跑） |
| 只停卖 | `osc_sell_enabled=False`（⚠️ 持仓失去退出路径，仅限事故） |
| 单只票豁免/认领 | 改 `t_io/state/auto_ownership.json` 后重启 |
| 回滚到"旧引擎" | **不可能**——旧引擎/S1/OGR 已整链删除，没有第二条线可退 |

### 9.2 每日核对（收盘后）

1. `[OSC] 盘前超跌候选 N 只`（09:31）——N=0 是否可解释（无热门板块/无超跌票）。
2. `[OSC] 10:00 早盘冲高卖执行` / `[OSC] 10:00 买侧执行` 两条摘要 JSON。
3. `fills_{date}.json` 的 `buys_placed` 与 `rejected_count` 是否对得上（被锁/被拒**不再**计入 placed）。
4. `sells_close_{date}.json`：`sl5_deep` / `horizon_expired` 计数，`open_after` 与账户持仓是否一致。
5. 账本 `positions.json` 与账户持仓对账（不一致 ⇒ 看 `_reconcile_open` 日志）。
6. `risk` 事件里的 `osc_*_error` / `strategy_lock_conflict` / `order_rejected`。

### 9.3 常见故障

| 症状 | 首查 |
|---|---|
| 当日完全没动 | `osc_enabled`？`_OSC_*_DONE_DATE` 是否已被当天更早的一次调用置位（进程重启会重置）？`KILL_SWITCH`？ |
| 买单全被拒 | 账户现金（`get_cash` 失败会按 0 截断）；`risk:strategy_lock_conflict`；拒单原因码 |
| 卖不出 | 账本 vs 账户对账（`t1_locked` / 账户无持仓）；`dev20` 是否为 None（缺 MA20 ⇒ 永不触发 SL5） |
| 手上有票但账本没有 | 那一定是"外部买入"（终端手工单）⇒ 不会被本策略卖；需人工处置 |
| 预筛常年 0 只 | ① 韭研分类文件 `stock_hunter/watchlist_jiuyan.json` 是否还在/格式变了；② **`core.market_data.facade` 是否可导入**（2026-10-12 真缺陷：GM 终端 sys.path 只有 `execution/auto`+`_gm/`，`import core` 失败 ⇒ 预筛天天 fail-closed、当日永不下单。宿主已改为把**仓根 append 到 sys.path 末尾**，且 `init` 会打印「数据源就绪」自检）；③ 启动日志若见 `daily_many … 无日线` ⇒ GM 不可达且 `daily_many` 无逐只兜底（已知问题，见 `文档 §11`） |

## 10. 研究证据（数字均可回溯到文件）

> 全部来自 `t_io/validation/weak_strong/results/exp*.json` 与
> [第一轮实验结论](../research/2026-10-10_弱转强第一轮实验结论.md)。**相对结论可信，绝对收益含幸存者偏差。**

### 10.1 为什么是"超跌 × 强开盘"

| 实验 | 结论 |
|---|---|
| exp1/2 | 盘中「先跌后翻红」（转强）**fade**：r_5d +0.50% 跑不赢全市场 +0.70%，2026 后半段 −0.18% |
| exp3 | 「一直强」（开盘就没破昨收）是唯一两段都正：r_5d +1.39%（h1 +1.63 / h2 +1.17） |
| exp4 | 等到 **10:00** 确认：r_5d **+1.62%**（h1=h2=+1.62%）；09:30 就买只剩 +0.13% |
| **exp5** | **强开盘 + 弱W1（昨收<MA20）：+2.11%（h1 +2.06 / h2 +2.15）**；非弱票只有 +1.14% ⇒ 「超跌」这层真加分 ≈1pp |
| exp6 | 收益分解（15055 笔）：日内 +0.08%；**隔夜 +0.48%（t=17.4）**；次日盘中 +0.06%；**第2~5天 +1.56%** |
| exp7 | 死拿 5 天（净扣 0.13%）**+2.05%，两段都第一**；死拿 3 天 +1.26%；止盈+10%/止损−5% 最差 +0.93% |

### 10.2 为什么是 top-4

| N | 净年化 | Sharpe | 最大回撤 | 日均持仓 |
|---|---|---|---|---|
| 全部 | +53.2% | 1.69 | −25.9% | 209 |
| 20 | +73.6% | 2.03 | −28.0% | 62 |
| 8 | +96.9% | 2.35 | −29.0% | 32 |
| **4** | **+113.6%** | **2.38（顶点）** | −30.5% | 17 |
| 2 | +122.6% | 2.30 | −33.6% | 9 |

（exp9，净扣双边 0.13%）**exp10 半窗**：h2 震荡市全持仓 Sharpe 0.52 → top-4 **1.52（近 3 倍）**，
年化 +17.3% → +77.7%；h1 牛市集中只抬绝对收益（+96.9%→+155.4%）、Sharpe 3.77→3.79 基本不动。
⇒ **集中不是牛市假象，恰在震荡市最值钱。**

### 10.3 板块过滤（exp12/13）

- exp12：基线单笔 +2.05% → **前一日涨停家数 top5 板块过滤 +2.72%**；组合年化 +113.6%→+135.5%、
  Sharpe 2.38→2.52、**回撤 −30.5%→−31.9%（略差）**。静态抱最大 5 板块反而变差（+1.71%）。
- exp13 半窗（**过滤只在震荡市值钱**）：

| 半窗 | 不过滤 | 涨停top5 |
|---|---|---|
| h1 2025 牛 | +155.4% / 3.79 | +104.6% / 2.79（**变差**） |
| h2 2026 震荡 | +77.7% / 1.52 | **+154.7% / 2.32（翻倍）** |

### 10.4 幸存者偏差的量化（exp15，全池 5034 只）

- gap 排序**全池稳健复现**：Q1 最弱 −0.67% → Q4 最强 **+3.68%（t=19）**。
- **全池 top-4 净年化 +36% / Sharpe 0.93 / 回撤 −22%**，只有 981 池（+113.6%/2.38）的**约 1/3**。
  ⇒ 这才是无幸存者偏差、纯 2026 震荡市的诚实基线。
- 板块维度在全池**测不了**（韭研分类仅覆盖 30%；替身被 `""` 伪板块污染）——所以生产里的
  板块过滤是**宇宙选择**，其增益只在精选池可测。

### 10.5 出场：组合层止损（exp19，**生产用 SL5 只深**）

| 配置 | 年化 | Sharpe | 回撤 | h2 Sharpe | h2 回撤 |
|---|---|---|---|---|---|
| HOLD 死拿 | +103.6% | 2.16 | −30.5% | 1.52 | −30.5% |
| **SL5 全** | **+111.6%** | 2.22 | −28.1% | **1.64** | −28.1% |
| **SL5 只深（dev20<−7%）** | +107.1% | **2.25** | **−26.3%（最优）** | **1.69** | **−26.3%** |
| SL5 浅中（dev20≥−7%） | +105.9% | 2.12 | **−32.2%（恶化）** | 1.44 | −32.2% |

⚠️ 单笔口径（exp18）与组合层（exp19）结论**相反**：单笔上深档止损贵（Δ−1.09pp），
但组合层回撤由深档聚集性下跌驱动 ⇒ **要砍回撤就止损深档，不是浅中档**。

### 10.6 为什么没上"绝对 gap 阈值"（exp21/22/23，**尚未接线**）

- exp22：`gap>8%` 单笔 **+5.83%/t12.3**、组合 +97%/1.70（保留约 14% 信号）；
  `gap>6%` 组合仅 +35%/0.79。生产原设计「**每日 rank top-4**」在候选少时会强选低 gap 票
  （exp21 精选池：top-4 **−3%**，反不如全持有 +3%）。
- exp23：**gap 阈值与板块过滤都是"震荡市武器"**——h1 牛市基线就 +98%/3.77/−6%（几乎不回撤），
  两者边际≈0（gap>8% 组合 Sharpe 3.77→3.89 不动、回撤反翻倍）；h2 震荡市 gap>8% 让
  Sharpe **0.59→1.35 翻倍**。
- **现状：生产仍用 rank top-4**（`osc_top_n=4`），未改成绝对阈值——这是**已知的待决策项**。

### 10.7 已验证「无增量 / 有害」的变体（别重做）

1. 盘中「先跌后翻红」（转强）——fade（exp1/2）。
2. 09:30 就买（未等 10:00 确认）——后半段只剩 +0.13%（exp4）。
3. 死拿 3 天 / 止损−5% / 移动止盈 5% / 止盈+10%+止损−5%——单笔口径全劣于死拿 5 天（exp6/7）。
4. 静态抱最大 5 板块——变差（exp12）。
5. 981 池上的「真实猎手排名」过滤——组合层塌成负 Sharpe（池错配+候选饿死，exp14）。
6. 浅/中档止损——两头不讨好，回撤反恶化（exp19）。
7. 高位跳空追涨（多头·强势）——左尾最宽（P5 −15.2%、跌 8% 达 22.8%）；**alpha 在超跌一侧**（exp16/17）。
8. **站上 5 日线硬约束**（两口径）——对弱转强同样有害（单笔 +2.17%→+1.75%、回撤恶化），
   被过滤的票反而更好（+2.36%/胜 61%）（exp20）。**与 S1 那次同构（年化 52.6%→19.4%）。**
9. **叠加做 T**——owner 2026-10-10 已拍板关闭；T 腿打在 S1 持仓上 −86bp/腿。

## 11. 已知局限与诚实披露

1. **真实买侧滑点未测**：10:00 收盘价下单，模拟盘撮合语义可能低估滑点；研究里按双边 0.13% 扣过成本，
   但真实开盘/盘中滑点没有实测（与 OGR 同一纪律：未达标不碰实盘）。
2. **幸存者偏差已量化**：981 池 top-4 ≈ 全池 top-4 的 **3 倍**（+113.6% vs +36%）⇒ **相对结论可信，绝对收益不可引用**。
3. **候选宇宙只覆盖 1551/5382 只**（有韭研分类的）；板块过滤那层的增益只在精选池可测。
4. **早盘冲高卖 +3% 是初始 knob**（exp11 说 1~10% 都可行）⇒ 待纸单数据校准。
5. **入场价差**：信号 10:00 才确认，真实成交在 10:00 之后一点；组合数字多为 120~187 天短窗年化，**噪声大**，
   单笔 t 值（9~26）才是稳健部分。
6. **exp19 止损口径**：按 close 触发（非盘中最低）；981 池排除退市股 ⇒ 深超跌左尾被低估，真实止损收益只会更大。
7. **GM 分钟权限只有 180 自然日**（2026-04-13 起）⇒ 全池面板只覆盖 2026 震荡市，无 h1 牛市。
8. **数据小出入（待核）**：exp23 池规模，脚本头写 993/970 只，
   文档 §8.6 与 memory 写 965 只——引用时以脚本为准并注明。

## 13. 与其它"决策/打分"系统的关系（**别混淆**）

自动盘里只有 §1~§4 那一条链会**下单**。其余带"得分/判定"字样的模块都是**展示或人工辅助**：
