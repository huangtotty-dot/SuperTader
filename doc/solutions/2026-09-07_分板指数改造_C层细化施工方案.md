## 〇、C 层目标与边界

**目标（D3 卖侧分板语义）**
1. **分板 uni_down 日**：该板持仓卖出端加急——SELL_HIGH/PANIC 阈值降档触发、尾盘归位提前、减仓确认升级；卖侧从"完全不消费指数"改为"响应个股所属板 regime"。
2. **分板 uni_up 日**：卖侧不改（只影响买入端拦截，A/B 已覆盖）。
3. **sysrisk 分板级**（本板指数跌≥阈值 → 本板持仓减仓确认）：B-1 已落"登记/标注"层（sentiment record `board_crash` + per-stock 减仓确认 note）；C 层把分板熔断接到 manual/auto **卖出决策上下文**（index_circuit_state / board regime）。
4. **不回滚 08-19 教训**：SELL_HIGH 不恢复"指数共振门控"（仍是 bypass），C 是**新增响应**而非旧门控复活。

**边界**：不动阈值校准（D 层挂起）；不改 D2 市场级保留——上证市场级"全市场断电"场景（sysrisk/z_S 清仓、market clear）仍在；C 只新增"该板级"响应。

## 二、核心设计（拍板项 + 建议）

### C0. manual 按板 regime 的数据源（前置，必须先拍）

**问题**：`index_circuit_state=clear`（禁买全卖）等语义与 uni_down 深度绑定；manual 侧没有"按板 uni_down"。两种取法：

- **方案 A（建议）：manual engine 支持 `index_code` 参数 + 每板独立 state**
  - `detect(.../detect_index_regime(..., index_code=None))`：缺省=市场上证（**行为不变**，零回归）。
  - 状态按板分文件：`state.json` → `state_{index_code}.json`（如 `state_sz399006.json`）；`_IR_MEM_CACHE` key 加 symbol 维 `f"{sym}:{mode}:{target}"`（与 A-7 的 _gm 副本同款改造）。
  - **市场级腿声明**：成交额腿 `index_symbol_sz`、e5 跌停潮、涨跌家数是**全市场**指标——分板 detect 时这些腿对板块无意义。建议：分板 detect **禁用/降级**这些腿（走既有 `degraded:["amount_sz"/"breadth"]` 机制），仅用该板块指数自身 K 线判 uni_up/uni_down/range。改引擎语义最小。
  - 成本：state 文件 +1/板；每交易日 detect 次数 ×(1+板数)。
  - 产出一石多鸟：喂 C-1 circuit、C-3 reason 板码、§5 日检对照、D 层未来校准。
- **方案 B：轻量 regime 代理**（close vs MA60 缓冲带 trend_up/dn/range，build_decision 同源）
  - 不动 uni 状态机；但 `index_uni_down_clearance`/`clear` 的"uni_down"词义被偷换成"trend_dn"，阈值/持续性语义全不同 → 电路误触发风险大。**不推荐**。

**C0b（2026-09-07 追加拍板项，未决）分板 detect 时环境分 E 的市场级腿如何处理**：
> `_detect_inner` 的 E 维度四项 breadth/NHNL/volume/QVIX + E5 涨跌停池（`:2382-2413`）均为**全市场**指标，与板块自身 K 线无关。
> - **(i) 保留市场 env 腿（代码改动小、风险低，建议起步）**：只换"趋势腿 df=该板指数 + state 按板分文件 + mem-cache 加 symbol"；分板 regime = 60% 该板趋势 + 40% 市场背景；E5/breadth 仍市场级，ctx 不标 degrade。默认路径（`index_code=None`）天然零回归。
> - **(ii) 分板时降级市场 env 腿（语义最纯但改动大）**：breadth/NHNL/QVIX/E5 对板块无意义，需给 `_ir_score_*` 增降级路径 + env 重加权 + ctx degraded 断言，回放验证成本高。
> - 建议 **(i)**：C 的目标是"该板 uni_down → 卖侧加急"，用"板趋势为主 + 市场背景"的 uni 判定足够；周六对照若显 (i) 口径误判再升级 (ii)。

### C-1. manual 仓控按板（数据层改，决策层零改）

- `_attach_index_regime_context(ctx, code)` 内按 `resolve_index(code)` 取板，`detect_index_regime(..., index_code=board)` 写 ctx。
- ctx **旧键全部保留**（`index_regime/index_score/index_circuit_state/...` 语义 = 该板），**新增** `index_index_code/index_index_name`（加键不改结构，trace/GUI 兼容）。
- **性能**：24 票每票一次 detect 太贵 → 按板做 mem cache（`{board: (ts, ctx部分)}`，TTL 对齐现有 `daily_cache_ttl`），同板共享。
- 市场级并存：`index_circuit_state` 出现 `clear`（市场全清仓）的**场景语义保留**——当且仅当该股所属板 `clear` 或市场级 `clear` 才触发 `net_qty` 全卖（D2：市场级不断电）。

### C-2. auto 卖通道注入板 regime（新机制，周六对照）

- `context.board_regime`（A-7）注入 `sell_channels`：卖出仲裁时取该股所属板 regime。
- **加急口径（需拍具体数值）**：board uni_down 时
  - PANIC 深亏触发回撤阈值下调（如 -8%→-6%？）与 HARD_STOP 关系需先核（`HARD_STOP_EXIT` 是硬规则，**不动**；只动软性 PANIC 深亏/SELL_HIGH 降档）；
  - SELL_HIGH/尾盘归位"提前"——提前到哪个 slot（现尾盘 slot 定义在哪）需施工时读 gm_main/sell 仲裁确认。
- board uni_up/range：卖侧不动（对照组）。
- **验证前置**：harness_backtest 需有"分板 uni_down 日 × 该板持仓减仓"的历史样本窗口，先跑现状基线再跑 C-2，指标：卖出后 5 日胜率、回撤保护不恶化、地板穿透=0、绞肉机=0。

### C-3. reason 带板码（小改，可归因）

- 格式建议：`HOLD_BUY_BLOCKED:index_uni_down_clearance:{index_code}`（例 `…:sz399006`）；auto `buy_block` token 后挂板码或 reason 尾部追加。
- **兼容**：解码端 `main.py:2195` 用 `startswith("HOLD_BUY_BLOCKED:index_uni_down_clearance")`——旧格式（无板码）仍命中，**不破旧回测脚本**（w32 等按前缀/精确 token 分类处需核对；仅改生成端新格式 + 解码端容忍后缀）。
- superTrader 内先落地：auto 生成端（`t_engine_auto` buy_block 组装）+ manual 解码端透出；manual 生成端在外部决策引擎，需同步口径（见 §四风险4）。

## 四、风险与影响面

1. **manual engine 改造面**：state 按板分文件（`state_sz399006.json` 等）；现有 `IR_STATE_DIR` 兼容（目录不变、文件名按板后缀）；`state.json`（上证）路径语义不变。
2. **市场级腿降级**：分板 detect 若忘了降级成交额腿/跌停潮，会把全市场指标错当板块信号 → C-0 验收必须有"分板 ctx degraded 标注 amount_sz/breadth"断言。
3. **C-2 行为改动**：卖出加急会改变真实卖出行为，**未过对照决赛不得接线**（预注册闸门）。HARD_STOP_EXIT 硬规则优先级最高，加急不得穿透。
4. **reason 生成端分散**：manual `HOLD_BUY_BLOCKED:index_uni_down_clearance` 生成点不在 superTrader 仓库（外部手动决策引擎），板码只能两侧同步落地；先保证 superTrader 侧解码 + 新格式向前兼容，外部侧排期。
5. **trace/GUI 兼容**：ctx 增 `index_index_code/index_name`、board_regime 已在 A-7 落地；heartbeat/复盘读旧键不破。
6. **周六对照窗口**：C-2 需要"分板 uni_down 日 × 该板持仓减仓"的样本；样本不足时 C-2 缓接线、C-1/C-3 先走 trace 归因观察。
