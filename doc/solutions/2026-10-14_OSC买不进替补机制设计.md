## 1. 事故还原（根因）

### 1.1 三笔单的下单逻辑（代码事实）

- **参考价**：`executor.run_buy_exec` 把 `p["price"]` 设为 **10:00 棒收盘价**（信号入场价口径），`build_buy_plan` 按它折算股数；该 price 传给 gateway **仅作留痕**（executor.py docstring 明写 "price 仅留痕参考"）。
- **实际单型**：`framework/gateway.py:171-177` —— 参数 `osc_limit_slippage_bp=0`（`_gm/config/params.py:212`）⇒ 走 `OrderType_Market` **市价单**。所以今天三笔都是市价单，「挂 10.20 / 挂 24.55」只是留痕参考价，并非限价单。
- **301373 为什么成交价高于挂单价**：参考价 108.81 = 10:00 棒收盘（≈09:59 最后一笔，腾讯分钟线 09:59=108.81）；市价单 10:00:01 进场，10:00:02 以 109.6967 成交（分钟线 10:00 那一分钟已到 109.70）。+0.81% 是「参考价时点 vs 市价成交时点」之间的动量滑点，不是限价被击穿。
- **GM 模拟盘撮合**：市价买单在标的**封死涨停**时进入涨停价位买方队列，仿真柜台排队不成交（实盘中同样排在巨量封单之后）；挂到 15:00 以 `status=12`（过期）拒单释放资金（bridge events 实证：两票均 15:00:00 status=12）。

### 1.3 结构性根因

OSC 信号按 **gap 降序取 top-N**，gap 最大 = 跳得最高 = 最接近/已经封涨停。10cm 主板票 gap≥9.9% 必然已在涨停价上（600097 gap 10.03%、000823 gap 9.99%）。**策略选股偏好与成交概率天然负相关：排名越靠前的候选越买不进。** 这不是执行 bug，是信号定义的市场后果。

## 2. 四个方案对比

### (A) 限时未成交改追价/市价

- **描述**：下单 N 分钟未成交 ⇒ 撤单 ⇒ 改市价（或涨停价）追。
- **优点**：实现小（gateway 已有市价路径，补 cancel 即可）；对「未封板但流动性薄」的票能提高成交率。
- **缺点**：**对今天的失败案例完全无效**——买不进的原因就是封死涨停，追价改市价仍排在同一队列；对「开板回落」的票会在情绪尖上成交，恶化入场价分布；与回测口径（10:00 收盘价入场）偏离更大。
- **统计性质影响**：入场价从「10:00 收盘」漂移到「追价时刻价」，exp 回测假设被稀释，Sharpe 不可比。
- **实现复杂度**：低-中（撤单 + 重报 + 状态机）。
- **结论**：单独上不推荐。

### (B) 未成交顺移下一名候选（owner 提议方向）

- **描述**：top-N 内某票 X 分钟未成交 ⇒ 撤单 ⇒ 额度顺移给第 N+1、N+2… 名确认候选，直到额度用完或候选耗尽。
- **优点**：不追单票的价，每只仍按信号价附近成交；候选池利用率提高；与 owner 直觉一致。
- **缺点与约束**：
  1. **候选耗尽**：`decision.evaluate` 只返回 top_n=4（decision.py:128），顺移需要决策核暴露**完整排序候选**（小改，但动决策核要单测钉住）；pool 本身就不深的日子（min_pool fail-closed 边缘）顺移无米下锅。
  2. **确认条件时效**：「10:00 跳空守住」只在 10:00 棒判定；10:10/10:20 顺移时第 5 名的确认已过时 ⇒ 需要时效复检（如：顺移时现价仍 ≥昨收 且 ≥VWAP，且未涨停封死）。
  3. **隐性追价**：第 5 名 10:15 时可能也涨上去了，市价顺移 ≈ 温和版追价，滑点期望高于 10:00 首单。
  4. **状态机复杂度**：撤单→确认撤成→复检→重报→再限时，每轮有部分成交/撤单失败边角；撤单后现金释放时延要对账。
- **统计性质影响**：组合从「gap top-4」变成「top-4 中能成交的 + 候补」，入场时点从 10:00 单点变成 10:00~10:20 分布；回测需补「可成交性」假设才能对齐，方向上是让实盘更接近信号池全覆盖，偏差可控。
- **实现复杂度**：中-高（决策核返回全排序 + hooks 定时撤单/复检 + executor 补单轮次 + 单测）。
- **结论**：**推荐主方案**，但要做成「带时效复检和涨停封死跳过」的受限顺移，不是无脑顺移。

### (C) 限价上浮一档容忍度（`osc_limit_slippage_bp>0`，如 +50bp）

- **描述**：市价单改限价 = 参考价×(1+bp)（更精细可 cap 到涨停价）。
- **优点**：只改 params.py 一行（网关已有该路径，gateway.py:171-175）；成本上界明确。
- **缺点**：**对已封死涨停完全无效**（限价再高不过涨停价，排队位置不变）；对非涨停票反而比市价成交慢甚至不成交（挂限价排队 vs 市价秒成），**引入「限价未成交」新失败模式，成交率可能不升反降**。
- **统计性质影响**：入场价分布右移 ≤bp；成交率变化方向不确定。
- **实现复杂度**：极低。
- **结论**：对本案无效，单独上不推荐；其「价格容忍度上界」思想可吸收进 B 的复检条件。

### (D) 维持现状 + 只补统计

- **描述**：不改执行行为；把成交率/滑点/冻结资金做成每日统计。
- **优点**：零风险；先积累「gap → 成交率」曲线，给 B 的阈值（限时几分钟、复检条件）提供数据。
- **缺点**：买不进的日子资金继续闲置到 15:00（但口径已不虚亏）。
- **实现复杂度**：极低（**本方案已附带落地**，见 §4）。
- **结论**：立即执行，作为 B 的数据前置。
