## 审核原则

1. **设计文档是唯一基准**：实施偏离方案 §5/§6 契约的，要么改实施、要么回改文档（需用户确认），不允许静默漂移。
2. **每阶段有验收闸**：证据驱动（测试输出/对照数据/日志），不接受"应该没问题"。
3. **不破生产**：合并期间 superTrader 人工链路（做T推送/建仓扫描/复盘）任何回归都视为破闸。
4. **代码级红线**（任一触碰即打回）：
   - 掘金 token 或飞书 webhook 明文进入版本库；
   - bridge jsonl 出现双写者（单文件单写者纪律）；
   - 修改 goldminer 现有事件 schema 字段（只允许扩展命名空间）；
   - 破坏 `t_qty 只减不增` 不变量（src/holdings_sync.py）；
   - 引擎 API 退化为隐式读取系统时钟（必须保持时间注入，保回测可重现）。

### P1 重审新发现（阻断 #7，2026-08-28）

**EOD 时段当日日线缺失**：实测 gm `history_n` 日线在 14:11 以 `end_time='2026-08-28 23:59:59'` 查询仍只返回到昨日——gm 盘中/盘后初段**不含当日 daily bar**；而 `facade._maybe_append_forming` 的补 bar 窗口止于 15:05（`"09:15"<=t<="15:05"`）。后果：15:05 后的盘后建仓扫描/复盘会丢掉当日整天数据（旧腾讯路径收盘后立即含当日 bar，属回归）。

**修法（二选一或组合）**：① forming bar 窗口延长至收盘后（如 ≤16:00），ts_date 新鲜度闸保证安全（盘后快照=当日收盘，补入即为完整当日 bar）；② 实测 gm 结算后（~15:35）是否含当日 bar，若含则 15:35 后清缓存重拉。建议 ① 立刻可做，② 今天 15:35 后实测确认并在代码注释记录结论。

**残留建议（不阻断）**：facade gm 路径无 cache-first 快路径（每次都实拉，实测 ~0.4s/只可接受，但建议加 15 分钟新鲜度快读以削减 10× 负载）；`core/market_data/gm_token.py` 与 goldminer `utils/gm_token.py` 是两份拷贝，P2 合并时收敛为一份。

### P1 打回记录（2026-08-28）

**通过的部分**：codec 四函数与契约单测 12/12 通过；gm 侧单位换算（股→手 ÷100）与前复权（ADJUST_PREV）正确；腾讯侧 WAF 双主机兜底/竞价快照字段口径保留；facade 降级与 attrs["source"] 标记机制符合方案；报告/注释诚实（裸 subscribe 局限有如实标注）。

**阻断项（审核方逐一复现确认，全修才可重审）**：

1. **index_regime 主路径必崩**：provider `index_daily` 丢失 `amount` 列 → `_two_market_amount`（analysis/index_regime.py:2623）KeyError → detect 兜底后 regime 恒 RANGE。审核方直接执行复现。修法：provider 指数日线补 amount（腾讯 fqkline 行内第 7 列；gm 用 amount 字段），或 _two_market_amount 对缺列退化 volume（akshare 备源同款退化）。
2. **market_review 周/月线坍缩**：`_tx_kline` 把 count 当日线根数再重采样（fetch_index_weekly(52) 只剩 ~10 周线）。修法：按周期换算拉取量（week: count×7 天级别）或恢复腾讯周期 URL。
3. **P2-4 日期校验契约被架空**：TencentProvider.minute 用入参 date 给 bar 打戳、不校验响应实际日期（tencent_provider.py:273），周末/节假日会把上一交易日伪造成当日分钟线；position_builder 在线路径恒返回 target 使调用方陈旧检查永不触发。修法：恢复响应 date 校验（旧代码 raw_date 逻辑），不符即空。
4. **stock_hunter「涨停」列语义变更**：0/1 布尔旗标变成涨停价（price），heat_tracker/data_loader 按 0/1 计数 → 涨停密度分失真。修法：恢复布尔旗标（含 ST/30/68 分档阈值）。
5. **gm 日线不含当日 forming bar**：`GmProvider.daily` end_time=当日 00:00 只返回到昨日 → "盘中最后一行=当日 forming bar"契约系统性失效（timing_gate/MA 闸/建仓条件盘中口径全部滞后一天）。修法：facade 层盘中对 gm 结果用 snapshot 补 forming bar（必须带 ts_date 新鲜度闸，08-28 事故教训）。
6. **gm 路径缓存层丢失（审核方补充发现）**：facade.daily/index_daily 的 gm 分支无缓存直拉（每次 ~2s/只），`fetch_daily_kline`/`_fetch_index_daily` 收敛后缓存与 B-1 陈旧校验全没了——41 只 × 每 5 分钟扫描会打爆配额且拖垮节奏。修法：provider 层恢复日线缓存读写（含盘中 15 分钟新鲜度规则与 B-1 校验），gm 结果写缓存。

**必须同步修复的建议级**：#6 指数分时腾讯通道 volume 单位回退为手 → vwap ×100（index_regime_intraday）；#7 代理清除在 daily/index_daily/minute 路径丢失；#8 TencentProvider.index_daily 忽略 end_date 抓取（历史查询静默退化）；#9 market_review 缓存污染（含未来数据写入按 end 键的缓存）；#10 load_snapshot_df 在线路径吃到无 TTL 缓存；#13 timing_gate stale 语义盘前误标 + 无缓存失败从抛错变静默。

**测试质量意见**：契约单测只测形状不测语义（12/12 通过但上述阻断全漏），要求为阻断 1/2/3/4/5 各补一个行为级测试（含周末/节假日分钟线伪造日期用例）。

### P0 打回记录（2026-08-28）

**通过的部分**：token 已移出两仓库 git（goldminer 2c217a0 + superTrader 016c26b6）；.gitignore 覆盖正确；`utils/gm_token.py` 读取顺序合理；probe 脚本结构与报告格式规范。

**致命问题（打回原因）：实测报告当前不可复现——`t_io/state/gm_config.json` 中的 token 无效。**

审核方实测证据链：
1. 用 gm_config.json 当前 token 调 `history_n` → gm 服务器返回 `{"status":1000,"message":"错误或无效的token"}`（重试含 strip 均失败）；
2. 该 token（36 字符）与 goldminer git 历史中的旧 token（40 字符）不同——旧 token 同样已失效；
3. **根因**：国盛定制版 gm SDK 的数据接口认证的是**掘金终端会话 token**（`gmterm-serv.exe` 启动参数 `--token=`，随终端重启轮换）。审核方用当前运行中终端的会话 token 实测 `history_n` **成功**（600481 日线返回正常）；
4. 时间线推测：10:19 的 probe 报告可能用的是当时有效的终端会话 token，10:25 写入 gm_config.json 的静态 token 本身就不是有效凭证。

**打回项（实施方修复要求）**：
1. **token 机制重做**：静态 gm_config.json 不成立。改动态发现——WMI/`psutil` 查 `gmterm-serv.exe` 进程命令行解析 `--token`（审核方已验证可行）；终端未运行 → 返回 None → facade 降级腾讯并 log 告警。gm_config.json 保留为兜底/覆盖。实施方案 P0-2 已同步修正；
2. 修复后用有效 token **重跑全量 probe**，报告须加**每只标的行数校验**（现仅 first_rows 验证首只），daily 要求 min(rows)==800、minute min(rows)==240；
3. **subscribe 证据补强**：裸 `subscribe()` 无 run() 上下文不能证明能收到 bar——改为在终端策略上下文或 run() 回调内验证 41 只实际收到 60s bar（goldminer 生产仅覆盖 17 只，41 只是新证据域）。

**给用户的提示**：掘金终端必须保持运行且登录，gm 数据链路才可用——这是合并后系统的运行时依赖，请知悉。
