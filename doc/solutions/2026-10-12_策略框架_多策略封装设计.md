### 2.2 一票一策略硬锁（owner 拍板）

**判据是算出来的，不是维护出来的**（少一份状态就少一处漂移）：

| 情形 | 判定 | 结果 |
|---|---|---|
| 某策略账本（`positions.json` 的 open）持有 | owner = 该策略 | 只有它自己能买 |
| 账户持有、无任何策略账本认领（旧镜像遗留 / 终端手工单） | `LEGACY` | **对所有策略锁** |
| 账户无持仓、账本也无 | 无主 | 可买 |
| `t_io/state/auto_ownership.json` 有 override | 以它为准 | 人工豁免通道 |

- 被锁 ⇒ 网关**不下单、不落 order 事件**，返回 `status="rejected"` +
  `message="ownership_lock:..."`（`rejected` 是执行器既有终态语义：不入账本、计入 rejected_count），
  并落 `risk: strategy_lock_conflict` + 审计事件。
- **被锁单刻意不写 `write_order`**：写了孤儿闸会误以为「本策略今天对这只票下过单」。
- 卖侧不设锁（各策略账本本就是卖侧真源）。
- ⚠️ **上线首日的已知后果**：账户里的历史持仓无人认领 ⇒ 判 LEGACY ⇒ **那些 code 当天买不进**
  （避免把新旧仓位混成一笔）。三条出路：① 接受（卖掉后自动解锁）；② override 成 `osc`；③ 先清仓。
  每次拒绝都有留痕，不会静默。

### 2.3 孤儿闸的判据**刻意没改**（原计划改 `(code, order_type)`，推导后否决）

孤儿闸 `_strategy_ordered_today` 的谓词是「**我方任一策略**今天是否对该 code 下过单吗」——
事件桥里本来就只有我方事件，所以「按 code 匹配」已经是对的；改成按 `order_type` 精确匹配会
把「本策略 id 对不上但有 order 事件」的成交误判成孤儿，**静默丢自己的成交**（6a96829c 那类事故）。
多策略争同一票已由硬锁排除 ⇒ 无需为此改谓词。`order_type` 已按策略 id 落盘，将来真需要时可用。

### 2.4 顺手修的一个真缺陷

`oversold_gap_executor._write_fills` 的 `buys_placed` 原先只数 `qty_placed>0`，把**被拒/被锁**
的单也算成"已下单"（与 S1 复盘里 `buys_placed=4/rejected=0` 的虚报同源）。已改为只数未被终态否决的。

### 2.5 踩到的坑（值得记住）

`oversold_gap_executor` **在导入时**执行 `sys.path.insert(0, ROOT)`，会把 superTrader 根插到
`_gm/` 之前 ⇒ 若这次导入发生在 `init` 的 `analysis.index_regime` 预取**之前**（本次新加的归属
快照就会），gm_main 自带的 fail-loud 守卫会解析到仓根副本并 `raise`，**策略起不来**。
解法：`_OscBookOwner._open()` 导入前后保存/还原 `sys.path`（适配器对宿主零副作用）；
并在行为测试里加了断言 `index_regime_from_gm`（且**不设 PYTHONPATH**，否则该断言会被掩盖）。

## 3. 目标契约（P2 落地时按此写）

```python
class Strategy(ABC):
    id: str                       # 账本键 = order_type 标签 = 参数前缀，三者必须一致
    hooks: list[Hook]             # Hook(when=dtime, phase="prepare|buy|sell|eod", once_per_day=True)
    def universe(self) -> list[str]: ...        # 需要的 subscribe 池（宿主做并集）
    def params_schema(self) -> dict: ...        # 声明的参数与默认值（宿主校验/命名空间化）
    def owns(self, code) -> bool: ...           # 归属证据（账本）
    def owned_codes(self) -> list[str]: ...
    def run(self, hook, ctx) -> None: ...       # ctx: StrategyContext(gateway/params/book/budget/data)
```

宿主 (`gm_main`) 只做三件事：**按 hook 时间窗分发** → **每策略每日一次的状态闸** →
**异常隔离 + 按策略留痕**（一条策略炸不影响别的）。

## 4. 加一条新策略的 checklist

1. 决策核放 `core/<name>.py`（**纯函数、零 IO**，可离线单测）。
2. 执行器放 `execution/auto/<name>/executor.py`（**不 import gm.api**，吃注入的 gateway 鸭子类型 ⇒ 可干跑）。
   —— 照 `oversold_gap_confirm/` 的包结构抄：`decision/prescreen/executor/hooks/gateway/runtime`。
3. 账本目录 `t_io/state/<name>_book/`（`positions.json` 为卖侧真源）。
4. 参数用 `<name>_*` 前缀落 `PARAMS`（P2 后改为 `PARAMS["strategies"][<name>]`）。
5. 在 `gm_main` 注册：`SERVICES` 里挂 `_XxxBookOwner`（`id/owns/owned_codes`）+ 建 `<name>.Runtime`
   + `on_bar` 里一行 `<name>.on_bar(RT, context, now, today, t)`（**宿主不持有策略状态**）。
6. 补两件测试：决策核单测 + 行为级钩子/网关测试（照 `tests/phase3/test_gm_main_osc_hooks.py` 抄）。
