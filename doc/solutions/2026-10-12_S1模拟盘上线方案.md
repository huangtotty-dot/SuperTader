## 一、策略规则（大白话版）

### 1.1 它在买什么

S1 是一只**量化选股轮动策略**。它每天收盘后给全市场 5,000 多只股票打分，挑出得分最高的 4 只，第二天开盘买入持有。分数由 4 个因子等权合成（都来自截至前一收盘的公开行情，无未来函数）：

| 因子 | 大白话含义 | 方向 |
|---|---|---|
| 10 日反转（REV10） | 最近 10 天跌得多的票，短期倾向反弹 | 跌得多加分 |
| 隔夜跳空（GAP） | 今开相对昨收的跳空幅度 | 低开加分 |
| 成交额突变（取反） | 成交额相对过去 20 日均值突然放大 | 放量**减**分（避拥挤） |
| 60 日通道位置（取反） | 当前价在最近 60 天价格区间的位置 | 处低位加分 |

整体风格一句话：**在超跌低位票里等反弹，躲开放天量的拥挤票**——这是一个"日级反转"策略。

### 1.2 它怎么轮仓（调仓纪律）

| 规则 | 值 | 含义 |
|---|---|---|
| 槽位数 N | **4** | 最多同时持 4 只，各约 25% |
| 调入线 | 排名 ≤ 4 | 综合分排进前 4 才买 |
| 调出线 M | **8** | 手中票排名跌出**前 8** 才卖——留了缓冲带，避免排名 4、5 名之间来回刷单 |
| 最短持有 | **1 个交易日** | 今天买的明天才能卖（A 股 T+1 本就如此，规则对齐） |
| 止盈臂 A | 启用 | 研究期验证过的止盈/兜底止损规则组（含 SL12 兜底止损），按回测同一套逻辑执行 |
| 成交方式 | 开盘价成交 | 每天 09:31 左右以市价单执行，先卖后买；卖出回款当日即可用于买入 |

### 1.3 什么样的票永远进不了名单（卫生宇宙）

打分前先过一道"体检"，不及格的票直接除名：

- 股价 ≥ 2 元（剔仙股）
- 上市满 120 个交易日（剔次新）
- 20 日日均成交额 ≥ 5,000 万（剔流动性差的）
- 近 60 日最大回撤 ≤ 60%（剔崩过的）
- 非 ST、非停牌

### 1.4 它的历史成绩（回测，2024-03 ~ 2026-09）

| 指标 | 数值 | 备注 |
|---|---|---|
| 年化收益 | **+53.6%** | 已扣双边费用、剔除暖机段 |
| 夏普比率 | 1.05 | 前/后半段分别为 1.19 / 0.80，没有"前半段撑门面" |
| 最大回撤 | **−45.5%** | ⚠️ 4 只集中持仓，波动非常大，腰斩级回撤历史上发生过 |
| 参数稳健性 | 12 组邻近参数全盈利、零孤峰 | 不是碰运气调出来的"独苗"参数 |

> ⚠️ **必须有的心理预期**：回测 ≠ 未来。这套策略此前**零仿真、零实盘记录**，周一是它第一次接触真实撮合。且因子监控显示 2026 年 2~7 月同类因子经历过结构性衰减（8 月起已修复回正），我们上了每日监控线盯这件事（见 §七）。

## 三、系统组成（三个新部件 + 一本账）

| 小名 | 真身（文件） | 职责 |
|---|---|---|
| **数据管家** | `scripts/s1_data_update.py` | 每天从掘金终端增量更新全市场日线数据（已更新到 10-09） |
| **选股官** | `t_io/validation/factor_mining/s0_account/s1_daily.py` | 每晚算出次日的买/卖/持有名单（picks 文件） |
| **执行官** | `execution/auto/s1_executor.py`（挂在 gm_main 内） | 每天 09:31 读名单自动下单：先卖后买、算股数、处理拒单/停牌/T+1 |
| **S1 账本** | `t_io/state/s1_book/` 目录 | 名单、成交留痕、每日净值全部在这里，和你的手动账户完全分开 |

数据流：`掘金行情 → 数据管家 → 选股官（出名单）→ 执行官（下单）→ S1 账本（记账）`

## 四、周一时间线（照着做）

### 盘前（08:30 – 09:25，和平时一样）

1. 启动**国盛掘金终端**，登录。
2. 启动 gm_main 策略（watcher 会自动拉起，与往日相同）。
3. （可选，1 分钟）人工预演：`python scripts/s1_executor_dryrun.py` —— 5 个场景应全绿。
4. （可选）确认开关：`execution/auto/_gm/config/params.py` 里 `s1_mode_enabled: True`。

### 盘中（09:31 起，关键 5 分钟）

控制台日志应依次出现（都有 `[S1]` 前缀）：

```
[S1] picks 已载入（2026-10-12，卖 0 / 买 4）
[S1] 账户快照：现金 … 持仓 N 只
[S1] ⚠️ 清仓计划: 旧持仓 N 只全部卖出（bootstrap_liquidation）
[S1] SELL …（逐票）
[S1] 买侧预算 …
[S1] BUY 605198 / 688003 / 301160 / 603950（逐票）
[S1] 留痕完成
```

**你要核对的只有一件事**：打开 `t_io/state/s1_book/fills_2026-10-12.json`，确认
① `bootstrap_liquidation=true`；② 旧持仓卖单全部成交；③ 新买 4 票的股数合理。

09:35 之后 S1 当天就没有动作了（它是日频策略，一天只动一次）。盘中其余时间 OGR 影子记录、滑点观测照常运行，互不干扰。

### 收盘后

1. 看 `t_io/metrics/equity_s1_daily_2026-10-12.json`（S1 专属净值记录，首日 `account_ret=null` 是预期行为）。
2. 晚上跑**数据管家 + 选股官**生成周二名单（见 §六）。
3. 按复盘清单做日复盘（A-5/A-6 照常）。

## 五、账本切换：旧镜像持仓的处理（重要）

- 此前模拟盘的任务是**镜像你的 A/B 实盘持仓**。周一 09:31，执行官会把模拟盘里**所有不在新名单内的旧持仓一次性卖出**（市价单），这是你我拍板的账本切换，**只发生这一次**。
- 卖出回款当日可用，紧接着买入 4 只新票。
- 切换后，模拟盘持仓**只反映 S1 策略的选择**，不再镜像实盘。你的 A/B 实盘账户从头到尾不受影响。

## 八、应急手册

| 情形 | 你会看到 | 怎么办 |
|---|---|---|
| 名单缺失或日期不对 | `[S1] ⛔ picks 不可用` | 当天 S1 不下单（旧系统也不会自动抢跑）。补跑 §六两条命令，次日自愈；紧急可手工在终端按名单下单 |
| 终端掉线/会话失效 | 现金读取为 0 的告警 | 重启终端重新登录；被拒的单次日自动重评，**不要手工补单**（防双买） |
| 大面积拒单 | fills 里 `rejected_count` 很高 | 把 fills 文件发我分析；现金类问题次日自愈 |
| 执行官报错崩溃 | `[S1] 开盘执行失败` | 主程序不会挂（只影响 S1 当天执行）；把日志发我，当日剩余单可手工处置 |
| 今天就是不想让 S1 动 | — | 删掉/移走当天的 picks 文件即可（它没名单就不下单） |
| **整体回退旧系统** | — | `params.py` 改 `s1_mode_enabled: False`，重启策略——镜像对齐、TAIL、旧引擎全部恢复，S1 自动失效 |

## 十、诚实披露（读一遍再开盘）

1. **零仿真记录**：S1 周一第一次接触真实撮合。回测里的"开盘价成交"是理想假设，真实市价单会有滑点，仓位权重会有小偏差。
2. **最大回撤 −45.5% 是真实发生过的回测值**：4 只集中持仓 + 日频轮动，净值剧烈波动是常态，不是系统坏了。
3. **因子衰减有前科**：2026-02~07 同类因子结构性失效过（8 月已修复）。监控线会盯，但监控是"事后 6 天"的滞后指标，不能当保险。
4. **首日净值是费前估计**：精确的费用/基准核算在当日收盘后重估（该小工具列为待办 U2，不影响交易本身）。
5. **数据口径修正已归档**：本次数据更新修正了 241 只除权股的历史前复权锚点（这是把旧错误价格改正确，不是数据错误）。
6. 止损三票（588170/000988/688008）base 已清零，周一清仓计划**不会**误碰你的实盘相关台账。
