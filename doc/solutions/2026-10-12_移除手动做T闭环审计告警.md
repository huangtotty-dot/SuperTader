# 做T口径整链退场：闭环审计告警 → 连亏熔断 → 审计与费率工具（2026-10-12）

- owner 原话：贴来一张「🚨 闭环审计异常」飞书卡（「江西铜业 qty=500 与 base=0 不一致」
  「【模拟盘 auto】卖出 X / 未接回 X → 模拟盘缺口」「请尾盘手动处理，确保卖出=接回、qty=base 闭环」）
  后说：「**因为已经没有手动做T了 因此这些提示以及相关的代码可以删除了**」；随后「继续」。

## 为什么这些提示是噪音

`qty=base`（底仓闭环）与「卖出=接回」是**手动做T时代**的判据（manual 做T 已于 2026-09-14 下线）。
做T退场后 `base` 不再被维护 ⇒ 每一只都会被报「qty 与 base 不一致」，纯噪音。

## 两轮删除，中间差在"还有谁在读它"

### 第一轮：只删提示（保留数据写入）

动手前查到 **`t_io/logs/closure_audit.jsonl` 是活依赖**：
`execution/daily_sentiment.load_loss_streaks`（**V2c 连亏熔断**：同一标的连续 N 日做T亏损 → 次日 hold，
调用点 `daily_sentiment.py:612-614`）读它的 `details[].est_pnl`。
⇒ 整段删掉会让那条闸**静默退化为"永无数据"**。故第一轮只删告警、保留落盘。

### 第二轮（owner「继续」）：整链退场 —— 但先验证了三件事

**① 连亏熔断不是死码。** 从真实数据推计数：

```
{'600481': 1, '000988_B': 3, '300153': 2, '300364': 1, '002639': 1}
```

`000988_B` 连亏 **3**、`300153` 连亏 **2** ⇒ ≥ 阈值 2，**只要 `rank > 6` 就真的会触发**
⇒ 不能当"没在跑"直接删（本仓两种前科都发生过：以为没生效其实在跑 / 以为在跑其实从未运行）。

**② 它的「清仓门控」从未门控过任何东西。** 全仓 `trade_gate` 共 7 处引用，
唯一非 `daily_sentiment` 的一处是 `main.py` **写死 `"normal"`** ⇒ 没有下游读它，
实际效果只是往复盘文本里塞一句"连亏熔断(N日做T亏损)→今日清仓门控"。

**③ 删除不影响任何下单路径。** 自动侧 `t_engine_auto.py` / `gm_main.py`
**完全不读** `trade_gate` / `pos_factor` / sentiment ⇒ 只影响**复盘文本**。

⇒ 整链可删，且删除**有依据**，不是靠"看起来没在用"。

> **可迁移的教训**：删代码前先跑一遍「**还有谁在读它的产物**」——
> 本次靠这一步发现了 `daily_sentiment`（活闸）与 `equity_daily`（脚本）两个读者；

> 两个方向都不能靠印象。
