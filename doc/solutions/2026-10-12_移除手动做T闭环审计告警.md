# 移除手动做T时代的「闭环审计」告警（2026-10-12）

- owner 原话：贴来一张「🚨 闭环审计异常」飞书卡（内容是
  「江西铜业 qty=500 与 base=0 不一致」「【模拟盘 auto】卖出 X / 未接回 X → 模拟盘缺口」
  「请尾盘手动处理，确保卖出=接回、qty=base 闭环」）后说：
  「**因为已经没有手动做T了 因此这些提示以及相关的代码可以删除了**」

## 为什么这些提示是噪音

`qty=base`（底仓闭环）与「卖出=接回」这套口径是**手动做T时代**的判据
（manual 做T 已于 2026-09-14 下线，见 memory）。做T退场后它们只会产生假警报：
`base` 不再由做T维护，于是每一只都会被报「qty 与 base 不一致」。

## ⚠️ 关键：整段**不能**删 —— 有一条活依赖

动手前查到：`t_io/logs/closure_audit.jsonl` 是
`execution/daily_sentiment.load_loss_streaks`（**V2c 连亏熔断**：同一标的连续 N 日做T亏损
→ 次日 hold；调用点 `daily_sentiment.py:612-614`）的**唯一数据源**——
它读 `rec["details"][].est_pnl`。

⇒ 若把 `_maybe_audit_closure` 整个删掉，文件不再增长，**连亏熔断会静默退化为"永无数据"**。
所以本次**只删提示，保留数据写入**。这与本仓那条老教训同源：
**判断"某段代码没用了"很容易，删之前先确认还有谁在读它的产物。**
