## 1. 通道命名与仲裁优先级

### 1.1 命名

- 卖出通道：**`OVERNIGHT_REVERSE_T`**（信号 `sig.action`），次日接回通道：**`B7_BUYBACK`**。
- 不复用 `SELL_HIGH`/`TAIL`/`TARGET_SELL` 任一现有 action——避免 A-1 盈亏归因混栏（见 §6）。

### 1.2 优先级（14:55 尾盘段的门链顺序）

现有门链（`_sell_channel_gate`）从高到低：`HARD_STOP_EXIT`(P0) → `TRAIL_SELL`(P2) → `TREND_EXIT`(P3) →
`TARGET_SELL`(P4) → `PANIC_SELL` → `TAIL 归位`。B7 设计为**全场最低优先级、仅在 14:55 bar 评估的独立段**：

| 序 | 机制 | 与 B7 的关系 |
|---|---|---|
| 1 | 保护类卖出（HARD_STOP/PANIC/TRAIL/TREND_EXIT/TARGET） | 任一存在当日已执行的卖出义务 → B7 不触发（见 §4 互斥） |
| 2 | `_force_tail_buyback`（14:50 起，数量不变硬约束） | **先于 B7**：若本 bar 强制回补已下单 → `continue`，B7 本 bar 跳过 |
| 3 | `TAIL 归位`（14:50 起，超底仓部分归位卖出） | **先于 B7 且同 bar 互斥**：`tail_done=True` → B7 本 bar 跳过 |
| 4 | **B7 信号评估（仅 now == 14:55 的 bar）** | 归位已把持仓压回 base_ref 后才轮到 B7 |

### 1.3 与 14:50 归位机制的时序协调（关键冲突点与解法）

**冲突表象**：归位 14:50 起把持仓压回 base_ref，B7 14:55 又从 base_ref 里卖出——看起来「刚归位又破坏归位」。

**解法（语义切割，不是时序切割）**：

1. **归位管「超仓」，B7 管「隔夜敞口置换」**。TAIL 归位的语义是「持仓 ≤ base_ref」；B7 的语义是
   「今日收盘有意让持仓 < base_ref，缺口由明早开盘接回补齐」。两者不矛盾：归位在 14:50~14:55 完成
   「平掉日内超仓」，B7 在 14:55 做「主动隔夜空仓腿」。B-1 复盘项「尾盘归位」的检查口径需修订为
   「14:55 前持仓回到 base_ref；此后至收盘的缺口仅允许来自 B7 通道」（见 §6 挂钩点）。
2. **B7 与 awaiting_buyback 互斥**：该票有未平的日内反T回补义务时 B7 不触发——否则 14:50 强制回补
   刚买回、14:55 B7 又卖出，同一 bar 窗口内来回打脸，台账也无法归因。草案 `detect_signal` 已内置
   `has_awaiting_buyback` 守卫。
3. **B7 卖出不进 `awaiting_buyback` 既有字典**。`awaiting_buyback` 的消费方是「价格回到卖出价下方
   +Renko 向下砖」的日内回补逻辑与 14:50 强制回补——B7 的接回是**次日开盘**，语义完全不同。
   设计为独立链 `b7_overnight_chain`，与 awaiting_buyback 一并持久化到 `buyback_chains.json`
   （同文件、不同 key 前缀），今日（09-15）已落地的 buyback_chains.json 持久化机制**结构不变、只增键**。

## 3. 影子模式设计（唯一建议的上线路径）

### 3.1 影子行为定义

- 信号照常检测，**绝不下单、绝不写 bridge/orders**。
- 每次触发追加写 `t_io/logs/b7_shadow_{date}.jsonl`（草案 `B7ShadowLedger`，log_dir 可注入）：
  - `b7_signal`：信号全量 + 当时持仓 + 虚拟卖出量；
  - `b7_virtual_sell`：以 c14:55 为虚拟成交价；
  - `b7_virtual_buyback`：次日开盘价虚拟接回，结算 `net_pct`（实验费用口径）与 `overnight_gap_pct`；
  - `b7_skip`：触发但被守卫拦截（熔断/互斥）留痕——拦截与触发同样重要。
- 每日复盘：影子虚拟成交 vs 实盘走势对照（接在 A-2 C5-1 机制上，见 §6）。

### 3.2 影子期 = 2 周（≥10 个交易日）验收口径

草案 `shadow_acceptance_check(events, pool_size, trading_days)` 已实现以下口径：

| 验收项 | 锚点（E1 离线） | 通过标准 | 备注 |
|---|---|---|---|
| 信号数 | 0.99 次/票/月 × 39 票 ≈ 19 笔/2周 | 在预期 0.4×~2.5× 区间（≈8~48 笔） | 超区间需归因（行情结构变化/数据缺bar） |
| 次日低开率（≈胜率） | 64.1% | 相对漂移 ≤ 20%（≥51.3%） | 2 周 n≈19，以分布对照为主 |
| 卖飞率 | 36% | 相对漂移 ≤ 20%（≤43.2%） | 同上 |
| 信号频率 | 0.99 次/票/月 | 相对漂移 ≤ 20% | 同上 |
| 虚拟净收益 | +0.638%/笔 | **不得转负**；转负即告警 | 小样本不做均值显著性检验（诚实声明：2 周不足以检验均值） |
| **漂移告警** | — | 任一指标相对漂移 **>20%** → 告警 + 周六议题 | 与 A-2 C5-1「漂移>20%标注」同闸 |

**出口判定**：2 周全部无告警 → 周六评审决定是否进入「小仓实单」议题；任一告警 → 归因后顺延或终止。
**影子期绝不自动转实单**——转实单属 L3 级决策（见 §5）。

## 4. 风控规则

### 4.1 单次卖出量上限（活动仓额度内）

- B7 卖出量 ≤ **活动仓额度**（= 目标底仓 base_ref 中非 intact 底仓、可用于日内周转的部分），
  且 ≤ min(实际持仓, T+1 可用量) − 在途，向下整百。
- E1 的 +0.638% 是「底仓全卖全接」口径；只对活动仓执行时，对账户的贡献按活动仓占比折算
  （E1 §7.2 已声明）。**活动仓额度的具体比例是 📝 owner 拍板项**（建议上限：单票活动仓，且单票
  单次 ≤ base_ref 的 50%——给「归位语义 + 底仓 intact 框架」留双保险）。
- B7 卖出走 TAIL 同款**直下市价单**模式（不走 `_sell_arbiter` 的地板/sizer）——因为 B7 就是有意
  打穿地板换隔夜敞口；但必须单独记 `daily_sell_count` 并受拒单退避（`_protect_sell_reject_until`）约束。

### 4.2 连亏熔断（N=4，📝 owner 拍板项）

- 全池口径：连续 4 笔费后为负 → B7 通道暂停（`B7CircuitBreaker`，草案已实现）。
- 依据：E1 最长连亏 11 笔是 10.9 个月 421 笔的极值（非典型段）；胜率 64.1% 下连亏 4 笔概率
  ≈ 0.359⁴ ≈ **1.7%/段**，是「效应可能漂移」的低成本告警。N=3 太敏感（4.6%/段），N=5 反应过慢
  （0.60%/段但多扛一笔左尾）。**建议 N=4**，周六拍板。
- 熔断后恢复条件：人工复盘确认漂移原因（对照影子/实盘 gap 分布），owner 手动 reset——不自动复活。

### 4.3 高开≥1% 日的接回纪律

- **次日开盘即接，不犹豫、不观望、不摊低成本**。实验数字：接回越等越贵（open +0.638 →
  vwap30 +0.323 → close +0.165），「等回落再接」在 S1 口径下是明确的负优化。
- 高开≥1% 日平均 −2.94%（72/421）是本策略的**入场费**，不是异常；因单笔亏损而破坏接回纪律，
  等于只付学费不收收益（E1 §6.1：策略全部收益来自 64.1% 的低开日）。
- 接回单设计：`B7_BUYBACK` 走「做T回补」同款豁免——不弹人工确认闸、豁免 09:35 开盘缓冲
  （gm_main 的 morning 缓冲只拦 SELL_HIGH/TARGET_SELL，买入侧豁免需在接入时显式声明）。

### 4.4 与既有风控的兼容

| 既有机制 | 兼容设计 |
|---|---|
| **HARD_STOP_EXIT（-8% 硬止损）** | 硬止损触发 → 该票 pending 的 b7_overnight_chain 立即作废（与 gm_main `clear_awaiting_buyback(reason="hard_stop_exit")` 同款处置），**次日不接回**——破位票不得因纪律单重新进场 |
| **绞肉机监测**（同票连续≥3日分批割肉，红色判定） | B7 卖飞日的接回是实现亏损，形态上会被绞肉机误报 → 绞肉机口径**排除** `OVERNIGHT_REVERSE_T`/`B7_BUYBACK` 通道成交（见 §6 挂钩点）；B7 自身的连亏由 §4.2 熔断专管 |
| **地板保护** | B7 有意打穿地板（隔夜敞口置换），不参与 `_sell_arbiter` 地板检查；但卖出量封顶在活动仓额度内（§4.1），intact 底仓本体不动 |
| **拒单退避 / 在途守卫 / 心跳 / KILL_SWITCH** | 全部沿用，无豁免 |

## 5. 与 L0~L4 阶段口径的映射

B7 不另起阶段，**挂在既有路线图的影子层**：

- **当前（L0✅ / L1 待启动）**：B7 影子模式可与 L1 并行——影子只读分钟 bar + 写 logs，不改执行链路，
  不污染 L1 的 merge_parity 对账（B7 影子事件在独立 jsonl，不进事件桥）。
- **影子 2 周验收通过 ≠ 可实单**。实单属 L3 级：需 L3 硬条件（接口报备/止损链路实测/费用校准等）
  全部打勾后，B7 作为 L3 试点的**增量通道**以最小活动仓额度上线，并按 L3 试点标准重新观察 10 个交易日。
- **每日 A-4 标注**：影子期在 A-4 结论行追加「B7 影子第 N 日」，漂移告警视同阻塞项（连续 3 日无归因
  → 黄起评 + 周六议题，沿用既有节奏）。
