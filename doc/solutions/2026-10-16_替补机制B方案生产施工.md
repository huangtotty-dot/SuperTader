- 决策核暴露全排序候选（`decision.evaluate` 返回 `signals`，`executor.evaluate_full` 保留）；
  `build_spares` 取 top-N 之外的 TRADE 候选为顺移候补（gap 降序）。
- `hooks` 新时点钩子：10:08 / 10:14 两轮（`osc_backfill_rounds=2` /
  `first_hhmm=1008` / `interval_min=6`），**10:20 硬闸后不再开新仓**；
  每轮「未成交 ⇒ 撤单 ⇒ 时效复检（现价≥昨收 且 ≥当日累计VWAP 且非涨停封死）⇒ 顺移」。
- 状态落盘 `day_state_{date}.json`（防进程重启后挂单冻结到 15:00 / 重复首轮）。

## 2. 本次生产施工改动点（过闸后最小落地清单 + 生产加固）

### 2.1 翻闸（params.py）

- `osc_backfill_enabled`：**False → True**（owner 2026-10-16 拍板）。
  开关保留：翻 False 即回「不撤不补」现状（`test_osc_backfill_shift` 闸⑥钉住逐位一致）。
- ⚠️ 该表由 `.gszq` 壳一次性加载 ⇒ **需重启策略进程生效**（周一开盘前重启）。

### 2.2 安全闸：撤单失败 ⇒ 本轮不补单（backfill.py）

- `run_backfill_exec` 新增中止闸：`cancel.failed` 非空 ⇒ `note=cancel_failed_abort`，
  本轮一个候补单都不下（账户委托状态不可知时绝不加仓），挂单保持到下一轮/15:00 拒单。
- 只闸 `failed`：`unconfirmed`（status=6 钱未解冻、或无在途单）**不中止**——
  那笔额度不释放，剩余额度内补单仍允许（既有测试口径不变）。

### 2.3 生产加固 A：order_id 缺失的撤单解析（gateway.py + backfill.py）

**根因**：GM 仿真终端**同步下单回报里 order_id 恒为空**（10-14/10-16 两天 bridge
events 里 `"order_id"` 无一非空；与 10-16 卖侧迟确认修复同源）。fills 账本只有空 id
⇒ 原 `pending_from_fills` 直接丢弃无 id 买单 ⇒ 整个替补机制在生产上**静默失效**。

处置（防御式降级，与 `cancel_order` 既有口径一致）：

- `pending_from_fills`：无 order_id 的未成交买单**保留**进待补单；
- `GmGateway._resolve_open_buy_order_id`：order_id 缺失时按 symbol 经
  `get_orders`（`_poll_pending_recon` 同款已验证渠道）找「在途且方向=买」的唯一委托取 id；
  - `no_open_order`（已成交/已终态）⇒ 归 **unconfirmed**（不释放、**不中止**本轮）；
  - 找到但无 id / 多候选 / 查询异常 ⇒ 归 **failed** ⇒ 触发 2.2 中止闸；
- `cancel_and_confirm`：撤单下发后用**解析出的** id 轮询确认。

### 2.4 生产加固 B：候补按 done_codes 剪枝（hooks.py）

每轮开头把「今日已碰过的票」从 spares 剪掉：第 2 轮不得**原票追回**第 1 轮
刚顺移买过的候补（那是方案 A 的追价，owner 已否决）；「顺移下一名」语义 = 只往
候补列表下游走，**候补池耗尽即停**（只撤不买）。

### 2.5 留痕与入账（executor.py + hooks.py）

- `executor.merge_backfill_fills`：每轮结果并入 `fills_{date}.json`——
  顺移单进 `buys` 且带 **`round`（1 起）/`shift_from`（本轮撤单释放的 code）** 两键
  （首轮记录无此两键，以此区分首单/补单）；撤单/额度/跳过明细进 `backfill_rounds`；
  summary 按合并后 buys 全量重算（与首轮同一 `_buys_summary` 口径）；按 round 幂等。
- 顺移买入**并入持仓账本**（`register_buys_to_book`，与首轮「挂单即入账 + 卖前对账
  夹紧」同一纪律）——不并的话 14:50 止损/次日早盘冲高卖看不见 ⇒ 孤儿持仓。
- 顺带修一处潜伏缺陷：`load_day_state` 轮次标记**合并而非覆盖**（原实现会把 on_bar
  刚打的本轮标记冲掉 ⇒ 同一轮可能重复触发；生产上 buy_done=True 恰好挡住，单测复现后修复）。

### 2.6 未动的部分
