## 一、问题定义：不只是"贴图麻烦"

表面痛点是每天截图 → 发我 → 我读图 → 手改台账。拆开看实际是四个问题：

| # | 痛点 | 后果 | 现状证据 |
|---|------|------|----------|
| P1 | **持仓快照靠 OCR 人肉录入** | 每天一次会话往返，读错/漏读风险常在 | 每日 08:50 前后 2~3 张截图 |
| P2 | **成本价大量"暂记"失真** | 台账成本 ≠ 真实成本，盈亏分析失真 | `holdings_manual.json` 里 588170「成本暂按收盘 0.714 统一重置，待交割单核对」、601872「成本按当日收盘暂记」 |
| P3 | **手动成交靠"复盘问答"发现** | 盘中买卖我不知道，台账当天就漂 | 每日复盘固定一问："今天手动盘有动作吗？" |
| P4 | **对账债越欠越多** | 漂移累积到要靠专门 reconcile 脚本救火 | `tmp/_reconcile_holdings_20261110.py`、`20261111.py`；588170 成本「陈年老值失真」事故 |

**范围界定**：痛的只有**账户B（东方证券，实盘，手动交易）**。账户C（国盛/掘金仿真）全程程序化（GM SDK 直查），无病。

## 三、候选方案调研（2026-11 现状核实）

### 方案 A：券商导出 + 解析管线（半自动）

**做法**：在东方证券 PC 客户端导出两张表，扔进 `E:\superTrader\inbox\broker\`：
1. 「当日成交/历史成交」（查询 → 交割单/历史成交 → 导出 Excel）
2. 「资金股份/持仓」（查询 → 资金股份 → 右键导出）

我写 `scripts/import_broker_snapshot.py`：解析 → 精确更新成本/数量/总资产/可用 → 跑一致性守卫 → 出 diff 报告。
**用户每天动作：收盘后点两下导出（约 30 秒），说一句"导入"。**

| 维度 | 评价 |
|---|---|
| 数据质量 | ★★★★★ 券商原始数据，成本/费用精确到分，P2/P3/P4 全灭 |
| 自动化程度 | ★★★☆☆ 仍需手动导出，但告别截图与会话往返 |
| 可靠性 | ★★★★★ 无 UI 自动化、无第三方依赖 |
| 成本 | 零 |
| 风险 | 零（只读文件） |

### 方案 B：easytrader 客户端自动化（近全自动）

**做法**：早盘前/收盘后你手动登录同花顺客户端（东方证券账户可走同花顺委托），脚本通过 easytrader 连接已登录窗口，调 `user.position` / `user.balance` / `user.today_trades` 直接读出持仓/资金/当日成交，落台账。

调研事实：
- 仓库 shidenggui/easytrader（9.2k star）**仍在维护**，2026-02 还有提交，且已内置 miniqmt 后端；
- 支持"先手动登录、再连接"模式，**不需要把交易密码交给脚本**；
- 原理是 pywinauto 界面自动化——**客户端升级/弹窗可能弄断它**，社区共识是"能用但脆"。

| 维度 | 评价 |
|---|---|
| 数据质量 | ★★★★★ 实时、精确 |
| 自动化程度 | ★★★★☆ 登录一次后可定时自动读 |
| 可靠性 | ★★★☆☆ UI 自动化天然脆，需客户端常驻登录 |
| 成本 | 零 |
| 风险 | 只读用法风险低；**绝不开下单权限、不落密码** |

### 方案 C：miniQMT / xtquant（券商官方 API，终局方案）

**做法**：向东方证券申请 QMT（迅投量化终端）权限，用其官方 Python 库 xtquant 直连柜台：实时持仓/资金/委托/成交，事件回调，**还能下单**。

调研事实：
- 东方证券在迅投 QMT 支持名单内（雪球 2024-08 整理的 76 家券商名单将其列为**中门槛 30~50 万**档）；
- 2026 年行业门槛普降：国金/中金财富/华西/银河等**10 万日均资产**即可开通 miniQMT；同一券商不同渠道（自助开户 vs 客户经理渠道）标准不同，**可谈**；
- 账户B 当前总资产约 28.5 万，正好卡在中门槛边缘——**值得给客户经理打一个电话**；
- 战略意义：OSC 自动盘将来上实盘的执行通道，大概率就是 QMT——持仓查询只是它的赠品。

| 维度 | 评价 |
|---|---|
| 数据质量 | ★★★★★ 柜台级实时 |
| 自动化程度 | ★★★★★ 全自动、事件驱动 |
| 可靠性 | ★★★★★ 券商官方接口 |
| 成本 | 资金门槛（28.5 万可能够也可能差一口气） |
| 风险 | 只读查询无风险；**开通审批需要 owner 亲自办** |

### 方案 D：贴图流规范化（兜底保留）

现有流程不废除，只规范化：截图扔进固定文件夹、固定命名，我定时读取解析。作为 A/B/C 全部失效时的兜底，以及导出文件与截图交叉验证的手段。OCR 自动化引擎不另搞——我的视觉识别准确率高于通用 OCR，重复建设无意义。

阶段三（战略，一个电话） 方案 C 探路
   ├─ owner：问东方证券客户经理——QMT 开得了吗？门槛多少？
