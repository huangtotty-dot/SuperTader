# 选股猎手 30 分钟轮询 + 异常飞书告警

- 日期：2026-10-11 ｜ 执行：Claude ｜ 状态：**已接线**（main.py 无头驱动）
- owner 原话：「在实盘过程中，选股猎手应该每隔 30 分钟做轮询，**重点中的重点：异常信息一定要通过飞书发出来**」

## §1 与旧决定的关系（重要）

2026-10-10 owner 曾要求「任何扫描禁止自动跑，唯一入口是按钮」，当时**删掉了**
`t_gui.start_hunter_autoscheduler` 与 `HUNTER_AUTORUN_SLOTS`。本次是**在该约束下**重新引入轮询：

- **GUI 行为不变**：打开页/切页/改日期**仍然不会**自动扫描，按钮仍是唯一的手动入口。
- 轮询放在 **main.py 主循环**（无头、常驻、不依赖 GUI 是否打开）⇒ 异常告警在没人看盘时也能发出。

## §2 设计

| 项 | 取值 |
|---|---|
| 触发者 | `main._maybe_run_hunter_poll(now)`，挂在主循环盘中段（与其它 `_maybe_*` 同级） |
| 时段 | 工作日 09:30-11:30 / 13:00-15:00（`core.hunter_poll.in_trading_hours`） |
| 频率 | **每 30 分钟**（`should_poll`：距上轮 ≥1800s）；单飞——上一轮没跑完不开新轮 |
| 每轮做什么 | 重跑猎手**取数 + 打分**（`prepare_data`→`score_stocks`→loader 补 summary/detail/sectors），随后**校验** |
| 告警 | **只发异常**（不发常规报告）；**按状态变化去重**（见 §5）；推送失败**不写状态**⇒下轮重试 |
| 消息 | **精简到 ≤5 行 / ≤260 字**（见 §5）；traceback 与管线输出**不进卡片**，留在日志 |
| 开关 | `config.json` → `feishu.enabled` + `feishu.notify_on_hunter_poll`（默认开） |

**异常类型**（`_KIND_LABEL`）：`run_exception`（含 traceback 尾巴）/ `empty_watchlist` /
`empty_pool` / `empty_summary` / `low_coverage`（行情覆盖率 <50%）/ `stale_date`（盘中但数据日期不是今天）。

**推送契约**：走 `config.send_feishu_payload(payload, success_log, error_prefix)`——
本仓有过血案：`core/hunter_ma5_alert.py` 注释记着「2026-10-10 前只传了 card，每次都抛 TypeError，
又被裸 except 吞掉 ⇒ **该告警自上线起从未推送成功过一次**」。故本模块**不写裸 except**、
**必传三参**、**检查返回值**，失败时打日志并**不写去重**。

## §5 owner 二次反馈后的两处调整（2026-10-11）

owner：「**实时性很重要，因为影响买点**；唯一可以优化的是**对于异常信息精简消息**。」
⇒ 频率/触发**不动**，改两处：

**(1) 消息精简**：`format_anomaly_card` 重写。**16 行 / 531 字 → 4 行 / 141 字**。

```
⚠️ 猎手轮询异常 · 10-11 10:30
① 行情覆盖低：行情覆盖率仅 43%（阈值 50%）⇒ 行情源可能不可用
② 跑挂了：AttributeError: 'tuple' object has no attribute 'get'
· 池5658 打分1753 覆盖43%
```

规则：只留**什么时候 / 哪里坏了 / 一行关键数字**；每条异常**只取首行**、压掉换行与
`Traceback`、单条 ≤70 字；`_KIND_SHORT` 短标签（跑挂了/池未加载/打分结果空/板块排名空/
行情覆盖低/数据非当日）。**完整 traceback 与管线输出留在日志**，不进卡片。

**(2) 去重语义改为"按状态变化"**（原为"同类一天只推一次"）——那等于 **10:00 坏了、14:00 又坏却不报**，
恰恰压掉实时性。现规则：

| 情形 | 行为 |
|---|---|
| 异常**出现**（上轮没有） | **报** |
| 异常**持续存在** | 不重复报（30 分钟一轮不刷屏） |
| **恢复后再次出现** | **再报**（实时） |
| 同类当日次数 ≥ `_MAX_PER_KIND_PER_DAY`(5) | 封顶（防抖动） |
| 推送**失败** | 不写状态 ⇒ 下轮重试 |

实现：状态文件由 `{date: [kinds]}` 升级为 `{date: {"last": [...], "counts": {...}}}`（读时兼容旧格式）；
**健康轮询会清 `last`**（保留 counts），这正是"再次出现能再报"的关键。

## §6 每轮心跳（owner 2026-10-12：「基本上没有收到选股猎手的相关信息」）

**问题**：原设计**只发异常** ⇒ 健康轮完全静默。结果 owner **无法区分「一切正常」和「根本没在跑」**
（首日实测：09:32 判正常、当天 0 条推送，只有日志里那一行）。

**owner 定**：**异常 + 每轮精简摘要**，且**只发「做T猎手预警」群**（根 webhook，与其它告警同群）。

**改成「每轮恰好一条」**：

| 本轮情况 | 发什么 |
|---|---|
| 出现**新异常** | 异常卡（精简、可执行；去重语义不变） |
| 一切正常 / 异常**持续中** | **心跳摘要卡**；异常持续时标题转 ⚠️ 并**把异常一行置顶**（心跳不掩盖故障） |

心跳卡样例（**4 行 / 98 字**）：

```
📊 猎手轮询 · 10-12 10:00
涨停前三：大农业 5 / 有机硅 3 / 电力 2
榜首三强（大农业）：万向德农 金健米业 海南橡胶
· 板块23 涨停13家 打分1753 覆盖100%
```

- 排行用**涨停数**（不是平均分）：本仓实测「涨停率」是唯一在两种成分口径、两个持有期都稳的
  板块强弱度量（`doc/research/2026-10-10_板块强弱度_成分股数量差异实验.md`）。
- 心跳**不去重**（就是要每轮都看到）；推送契约与异常卡相同（三参必传 + 检查返回值）。

### ⚠️ 顺带查清：为什么"平时收不到猎手信息"

**本仓有两个不同的飞书机器人/群**：

| 通道 | 目标 | 收什么 |
|---|---|---|
| 根 `config.FEISHU_WEBHOOK`（`…e80…`，关键词"做T猎手预警"） | 群A | **全部告警**（破线/站上/背离/指数/轮询心跳与异常） |
| 猎手 `stock_hunter/config.json` 的 `webhook_url`（`…ac3…` + chat `oc_b835…`） | 群B | **韭研报告 + Excel**（`send_report_summary`） |

而 **`send_report_summary` 全仓只在 `stock_hunter/main.py` 里被调用一次**（手动跑才推）
——**没有任何定时器自动跑它**。所以"平时自动来的猎手信息"从来就不存在：要么手动跑报告，
要么靠本模块的 30 分钟心跳。owner 已选**只发群A**，故心跳/异常都投根 webhook。

## §7 深度排查：为什么"报异常"几乎不响（owner 2026-10-12：「效果不是很好」）

**结论**：上线至今 **0 次告警** —— `t_io/state/hunter_poll_alerts.json` **从未生成**，
全部历史日志里**一条异常行都没有**（`grep 猎手轮询异常` 空）。不是推送坏了，是**判据够不着**。

| # | 证据 | 处置 |
|---|---|---|
| 1 | **唯一量化判据是结构性死的**：`low_coverage` 阈值 `0.5`。用 32 个已存档交易日（`stock_hunter/data/market_*.csv` × 韭研池）复算轮询自己的 `_coverage` ⇒ **min = 中位 = max = 1.0000**，生产见过的最低 0.996。阈值与实测差 **50 个百分点** | **已收紧到 0.95**（留 5pp 余量） |
| 2 | 其余 5 条里 **4 条是"整体为空"型**（watchlist / 打分池 / 板块排名 全空 + 跑挂）—— 只有"猎手彻底挂掉"才触发，而那种状态看 GUI 就知道，**告警没有增量** | 保留（是必要的兜底，但不是"监控"） |
| 3 | **真实退化信号就在手边却被丢掉**：管线遇取数失败**不抛异常**，只 `print("[WARN] N 只获取失败（已跳过）…")` 继续。轮询把 `pipeline_tail` 存进 stats 却**从不解析**，`data["failed_codes"]` 也从不读 | **已加 `data_warn` 判据**：全量扫 stdout 的 `[WARN]/[ERR]`（不只尾巴 8 行），剔除**已知常驻**的北交所 |
| 4 | **有一类失败连捕获都进不去**：`core/market_data/bj_daily.py:100`「北交所日线不可得(920126)…」与 `facade.py:256`「daily_many: 北交所首次取数失败…」都是 **`log.warning`**，而轮询用 `redirect_stdout` 只换 `sys.stdout` ⇒ logging 输出**看不到**（记录的 `pipeline_tail` 里确实没有这两条），今日主日志里也是 **0 条** | **已修**：新增 `_ThreadWarnCapture` —— 跑管线期间给 root 挂一个**只收本线程**的 WARNING+ handler，并临时把 root 级别放到 WARNING（否则 `log.warning` 在 logger 级就被丢掉，这正是今日主日志 0 条的原因）。⚠️ 踩坑：logging 的 `getMessage()` **不带 `[WARN]` 前缀** ⇒ 不能复用 stdout 的"必须含 `[WARN]`"判据（否则全部被滤掉、看似接线实则永不触发），故单列 `_log_warnings`，并有回归测试 `test_09` |
| 5 | **`stale_date` 会在周内节假日假报**：`in_trading_hours` 与调用方闸（main.py 主循环）都只判 `weekday()`，**全仓无交易日历**（`core/chart_cache.py` 明写"无全局交易日历"） | **未改**：需日历或"指数今日有无 bar"探针，属 owner 决策 |
| 6 | **输出塌缩不能当判据（先验证后否证）**：直觉方案"板块数/涨停家数骤降就报警"，用 `stock_hunter/history/daily_summary.json` 73 天复算 ⇒ 板块数 **2~23**、涨停合计 **1~109**，市场自发波动就覆盖了"塌缩"区间 | **明确不做**（朴素塌缩报警必然噪声） |

**新判据的真数据回归**（防"加了报警反而变吵"）：
- 健康轮实跑 `poll_once('2026-10-12')` ⇒ `ok=True`、覆盖率 1.0、`pipeline_warns=[]` ⇒ **不误报** ✓
