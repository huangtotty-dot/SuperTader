# 选股猎手 30 分钟轮询 + 异常飞书告警

- 日期：2026-10-11 ｜ 执行：Claude ｜ 状态：**已接线**（main.py 无头驱动）
- owner 原话：「在实盘过程中，选股猎手应该每隔 30 分钟做轮询，**重点中的重点：异常信息一定要通过飞书发出来**」

## §1 与旧决定的关系（重要）

2026-10-10 owner 曾要求「任何扫描禁止自动跑，唯一入口是按钮」，当时**删掉了**
`t_gui.start_hunter_autoscheduler` 与 `HUNTER_AUTORUN_SLOTS`。本次是**在该约束下**重新引入轮询：

- **GUI 行为不变**：打开页/切页/改日期**仍然不会**自动扫描，按钮仍是唯一的手动入口。
- 轮询放在 **main.py 主循环**（无头、常驻、不依赖 GUI 是否打开）⇒ 异常告警在没人看盘时也能发出。

## §2 设计

| 项 | 取值 |
|---|---|
| 触发者 | `main._maybe_run_hunter_poll(now)`，挂在主循环盘中段（与其它 `_maybe_*` 同级） |
| 时段 | 工作日 09:30-11:30 / 13:00-15:00（`core.hunter_poll.in_trading_hours`） |
| 频率 | **每 30 分钟**（`should_poll`：距上轮 ≥1800s）；单飞——上一轮没跑完不开新轮 |
| 每轮做什么 | 重跑猎手**取数 + 打分**（`prepare_data`→`score_stocks`→loader 补 summary/detail/sectors），随后**校验** |
| 告警 | **只发异常**（不发常规报告）；**按状态变化去重**（见 §5）；推送失败**不写状态**⇒下轮重试 |
| 消息 | **精简到 ≤5 行 / ≤260 字**（见 §5）；traceback 与管线输出**不进卡片**，留在日志 |
| 开关 | `config.json` → `feishu.enabled` + `feishu.notify_on_hunter_poll`（默认开） |

**异常类型**（`_KIND_LABEL`）：`run_exception`（含 traceback 尾巴）/ `empty_watchlist` /
`empty_pool` / `empty_summary` / `low_coverage`（行情覆盖率 <50%）/ `stale_date`（盘中但数据日期不是今天）。

**推送契约**：走 `config.send_feishu_payload(payload, success_log, error_prefix)`——
本仓有过血案：`core/hunter_ma5_alert.py` 注释记着「2026-10-10 前只传了 card，每次都抛 TypeError，
又被裸 except 吞掉 ⇒ **该告警自上线起从未推送成功过一次**」。故本模块**不写裸 except**、
**必传三参**、**检查返回值**，失败时打日志并**不写去重**。

## §5 owner 二次反馈后的两处调整（2026-10-11）

owner：「**实时性很重要，因为影响买点**；唯一可以优化的是**对于异常信息精简消息**。」
⇒ 频率/触发**不动**，改两处：

**(1) 消息精简**：`format_anomaly_card` 重写。**16 行 / 531 字 → 4 行 / 141 字**。

```
⚠️ 猎手轮询异常 · 10-11 10:30
① 行情覆盖低：行情覆盖率仅 43%（阈值 50%）⇒ 行情源可能不可用
② 跑挂了：AttributeError: 'tuple' object has no attribute 'get'
· 池5658 打分1753 覆盖43%
```

规则：只留**什么时候 / 哪里坏了 / 一行关键数字**；每条异常**只取首行**、压掉换行与
`Traceback`、单条 ≤70 字；`_KIND_SHORT` 短标签（跑挂了/池未加载/打分结果空/板块排名空/
行情覆盖低/数据非当日）。**完整 traceback 与管线输出留在日志**，不进卡片。

**(2) 去重语义改为"按状态变化"**（原为"同类一天只推一次"）——那等于 **10:00 坏了、14:00 又坏却不报**，
恰恰压掉实时性。现规则：

| 情形 | 行为 |
|---|---|
| 异常**出现**（上轮没有） | **报** |
| 异常**持续存在** | 不重复报（30 分钟一轮不刷屏） |
| **恢复后再次出现** | **再报**（实时） |
| 同类当日次数 ≥ `_MAX_PER_KIND_PER_DAY`(5) | 封顶（防抖动） |
| 推送**失败** | 不写状态 ⇒ 下轮重试 |

实现：状态文件由 `{date: [kinds]}` 升级为 `{date: {"last": [...], "counts": {...}}}`（读时兼容旧格式）；
**健康轮询会清 `last`**（保留 counts），这正是"再次出现能再报"的关键。
