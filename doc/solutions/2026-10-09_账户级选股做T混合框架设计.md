# 账户级「选股因子驱动 + 机会型做T增强」混合框架设计（2026-10-09）

> 任务 F4（只读设计，不动代码）。
> 战略背景：v1~v5 日内做T实验（1min MACD 背离路线 39 票 229 日 16861 信号全负期望）与 −8% 硬止损反省（见《2026-10-09_止损机制深刻反省与重构方案》）之后，owner 裁决战略转向——**从「持股做T」转向「选股因子驱动」**：用因子选标的 → 建底仓 → 盘中有条件就做日内T增强、没条件就在合适盈利空间卖出 → 换股，以**整体账户盈利最大化**为目标。做T收益必须**单独核算**，不允许被选股 alpha 掩盖或反向掩盖。
> 本文档给出账户级仿真框架的模块划分、数据流、状态机、接口签名与分阶段路线。

## 二、总体架构：四层 + 一本账

```
┌──────────────────────────────────────────────────────────────┐
│ L0 数据层  截面面板(PIT 5674只 prevadj) + 1min/30min 分钟线    │
├──────────────────────────────────────────────────────────────┤
│ L1 决策层（盘前/收盘后，日频）                                  │
│   ① 因子排名器 FactorRanker   ② 换股调度器 RotationScheduler   │
│   ③ 槽位分配器 SlotAllocator（目标底仓、T+1 兼容）              │
├──────────────────────────────────────────────────────────────┤
│ L2 盘中层（分钟频，复用 gm_main/sell_channels 既有链）          │
│   ④ 做T机会门 TOpportunityGate（OGR / trend30 / 30min背离）    │
│   ⑤ 做T执行臂 TLegExecutor（正T/反T，腿台账，当日闭合）         │
│   ⑥ 退出链 ExitChain（三区间分层止损 + 止盈档位 + TRAIL + 破位）│
├──────────────────────────────────────────────────────────────┤
│ L3 账户层  AccountLedger（净值/归因/做T单独核算/风险）         │
└──────────────────────────────────────────────────────────────┘
```

关键分工：**选股是主引擎，做T是寄生在持仓上的增强层**。做T层只产生「当日闭合腿」，永远不改变隔夜持仓语义（T+1 下腿腿独立记账）；退出链对「底仓」负责，做T腿对「当日」负责，两本账。

## 三、账户状态机：N 槽并行 + 每槽生命周期

### 3.1 槽位（Slot）建议：3~5 槽

- owner 单笔 ≥10 万口径下，账户资金按 100% 满仓目标：槽位数 N = 总资金 / 单槽目标底仓。
- **建议 N=4**（例如 60 万账户 → 每槽 15 万目标底仓）：3 槽集中度过高（单票风险 33%），5 槽摊薄单槽做T腿的相对收益且换股摩擦上升（每换一次 = 一个完整往返 0.069%）。
- 现金缓冲：总资金的 0~10% 留在槽外（owner 现行框架为 20%，参数化 `cash_buffer_ratio`），用于正T买腿的日内流动性——**注意**：正T买腿占用现金，若现金缓冲为 0 则只能做反T。

### 3.2 单槽生命周期（文字版状态机）

```
                 因子排名(每日收盘后)
                        │
                        ▼
   ┌─────────┐   排名入Top-N且无持仓     ┌──────────┐
   │ CANDIDATE│ ───────────────────────▶ │ PENDING_BUY│ (T日收盘后挂单计划，
   └─────────┘                            └────┬─────┘  T+1日开盘建仓)
        ▲                                       │ 成交回报确认
        │                                       ▼
        │ 清仓确认(T日)                    ┌──────────┐
        │                                  │ HOLDING   │◀───────┐
        │                                  └────┬─────┘        │
        │                                       │              │ 做T腿当日闭合
        │              ┌────────────────────────┤              │ (qty回到base)
        │              │                        │              │
        │              ▼                        ▼              │
        │      ┌──────────────┐        ┌──────────────┐        │
        │      │ T_ENHANCING   │ 腿闭合  │ EXIT_PENDING │        │
        │      │ (做T腿在途)   │────────▶│ (止盈/止损    │────────┘
        │      └──────────────┘        │  信号待执行)   │
        │                              └──────┬───────┘
        │                                     │ 全清确认
        │                              ┌──────▼───────┐
        │                              │ COOLDOWN     │ (换股冷却，默认1日，
        │                              │ (禁当日重买)  │  防同票日内反复)
        │                              └──────┬───────┘
        └─────────────────────────────────────┘ 次日重入排名池
```

**状态-动作矩阵**（每槽每 bar / 每日只允许的动作）：

| 状态 | 买底仓 | 做T腿 | 保护性卖出 | 止盈卖出 | 调出(换股) |
|---|---|---|---|---|---|
| CANDIDATE | 否 | 否 | — | — | — |
| PENDING_BUY | 是(开盘) | 否 | — | — | — |
| HOLDING | 否 | 是(需门通过) | 是 | 是 | 是 |
| T_ENHANCING | 否 | 腿未闭合前禁新腿 | 是(优先平仓腿) | 是 | 否(先闭腿) |
| EXIT_PENDING | 否 | 否(禁新腿) | 是 | 是 | 是 |
| COOLDOWN | 否 | 否 | — | — | — |

### 3.3 与 T+1 的兼容性（硬性）

1. **建仓日不做T**：PENDING_BUY 当日成交的底仓当日 available=0，槽内首根可卖 bar 为 T+2（与 backtest_holdings `_bt_first_day` 整日跳过 OGR 的实证一致）。
2. **换股卖出与买入解耦**：调出票 T 日收盘后定计划、T+1 日卖出回款；换入票用**已回款部分**建仓，避免「卖单回款未到账 → 买单资金不足拒单」（2026-09-30 C-08 实证）。仿真中 T 日卖出的票与 T 日买入的票**不得共用同一笔现金**——顺序：先卖（09:31~10:00）→ 回款确认 → 再买。
3. **做T腿不污染底仓语义**：腿的买/卖独立记账，腿未闭合时槽状态为 T_ENHANCING，禁止再开新腿（每槽每日腿数上限沿用 `MAX_ENTRIES=3`，与生产 `max_buy_times_per_stock` 对齐）。

## 四、L1 决策层：选股与换股

### 4.1 FactorRanker（盘前/收盘后日频）

- **输入**：截面面板 `t_io/validation/xsection/panel/`（5674 只 PIT，1992~2026-09-17，prevadj）；当日已收盘因子值矩阵。
- **因子来源**：`factor_mining` 框架存量（alpha191_seeds、regime_factors、ledger_baseline_v2.jsonl 中 KEEP 因子），以及后续 F1~F3 调研结论导入的新因子。**选股因子的验收口径与做T因子不同**：选股看截面 IC/RankIC、分组单调性、Top-N 组合 OOS 收益（ic_layer.py 口径），不做腿的 Δ vs random。
- **输出**：`{date, ranked: [{code, score, rank, sector}], meta: {factor_set_version}}`。

```python

# Universe 预滤：剔除 ST/停牌/上市<120日/近20日日均成交额<阈值(建议≥1亿，保证做T腿流动性)/一字板
```

### 4.2 RotationScheduler（换股节奏）

**规则（v1 基线，全部参数化、可扫描）**：

- 每日收盘后计算目标持仓 = 排名 Top-N 且通过预滤。
- **缓冲带防抖动**：持有票排名跌出 Top-M（M > N，建议 M = 1.5N ≈ 6~8）才调出；新票必须进入 Top-N 才换入。无缓冲带的「日频严格 Top-N」在仿真中换股率会被噪音打满（每换一次双边成本 0.138%）。
- **单票持有下限**：最短持有 `min_hold_days`（建议 3 日，参数化），防止排名日内噪声造成的 2 日往返。
- **调出优先级**：① 触发退出链全清的票（COOLDOWN 后）；② 排名跌出 Top-M；③ 排名下滑且浮盈已达止盈档（见 §5.2）。
- **换入约束**：可用现金 ÷ 单槽目标底仓 = 可新开盘数；排名靠前者优先。
- **板块集中度**：同一申万一级行业槽位数 ≤ 2（参数化），防因子在单一板块扎堆（owner 持仓集中于半导体链，回撤同源风险）。

### 4.3 SlotAllocator

- 目标底仓金额 = 账户净值 × (1 − cash_buffer_ratio) / N，取整百股。
- 复用 `core/position_sizer.py` / `position_builder.py` 的整手与资金约束逻辑（回测时以净值替代实盘资金查询）。

## 五、L2 盘中层：做T增强 + 退出链

### 5.1 TOpportunityGate——「有条件做T」的判定接口

**核心定义**：做T不是每日义务，是一个**条件事件**。门 = 三个既有资产任一通过 + 公共闸门。

| 通道 | 资产 | 判定（冻结口径，改动=重预注册） | 腿方向 | 状态 |
|---|---|---|---|---|
| OGR 开盘低开反转 | `core/open_gap_reversal.py`（影子中） | mkt_gap<0 且 rel_i ≤ −1.0%；09:30 买 10:00 卖；MIN_POOL=5 fail-closed；代理池 MARKET_PROXY_CODES 冻结 | 正T | L3 影子已跑，+0.52%/腿样本外 |
| trend30 状态机 | `analysis/trend30/adapter.py` + `core/trend30_alert.py` | 持仓票 30min 状态=BULL 且当日回踩不破 → 允许正T；BEAR → 禁一切做T（挂接到退出链） | 门控 | 告警链路已上线（纯通知） |
| 30min 背离 | `analysis/m30_features.py` / `divergence.py` | 30min 顶背离 → 禁正T、允许反T；底背离+支撑 → 允许正T | 门控+反向 | 1min 背离已证伪；30min 周期未证伪，须先走 eval_factor 预注册再进门 |

**公共闸门**（所有通道共用，任一不满足则 NO-TRADE）：

1. 槽状态 = HOLDING（非建仓日/非 EXIT_PENDING/非 COOLDOWN）；
2. 当日腿数 < MAX_ENTRIES(3)；
3. 正T需现金缓冲 ≥ 腿金额；反T需 available ≥ 100 股；
4. 当日该票未触发退出链全清（`_hard_stop_today` 语义迁移到三区间止损后 = 「深亏区全离日」）；
5. 波动率门槛复用 `volatility_screen.py`（腿的预期捕获 > 往返成本 × 安全边际，建议 ≥ 3×0.069% ≈ 0.21%）。

```python
@dataclass
class TSignal:
    code: str; direction: Literal['long','short']   # long=正T short=反T
    channel: Literal['ogr','trend30','div30']
    entry_time: time; exit_rule: Literal['hold1455','native','fixed30m']
    size_ratio: float                                # 腿量 = base_qty × ratio（建议 0.25~0.5）

def evaluate_gates(slot: Slot, ctx: BarContext, cfg: TGateCfg) -> TSignal | None: ...
```

### 5.2 ExitChain——三区间止损 + 止盈候选（与反省文档对齐）

**完全替换**现行 sell_channels.py 的 HARD_STOP 一键全清。优先级从高到低：

| 层 | 通道 | 触发 | 动作 |
|---|---|---|---|
| E0 | 深亏区分流（不恐慌） | 浮亏 < −8% **且** 30min 无底部确认 | **禁止市价全清**；挂「反弹分档减亏」：反弹至 VWAP/前高 −x% 分 2~3 档减，每档 ≤1/3 |
| E0b | 深亏区恢复 | 浮亏 < −8% **且** 30min 底部确认（底背离+放量止跌） | 不减仓，标记「底部区」，允许正T恢复仓位（owner 哲学原文） |
| E1 | 顶部区减仓 | 距 20 日高点 <5% **且** 30min 顶部特征（顶背离/放量滞涨） | 分档减仓（反省文档 §2 手册） |
| E2 | TRAIL 移动止盈 | 浮盈 > +8% 激活，回撤 > max(3%, 1.5×ATR, 上限8%) | 卖超额仓/全仓（沿用 sell_channels 现有口径） |
| E3 | 固定盈利档 | 浮盈达 +5%/+8%/+10% 三档（参数化扫描，现行 TARGET_SELL 只有 L1=10%） | 每档卖 1/3，到达档位移除该档（WP-B14 三段式状态机复用） |
| E4 | 趋势破位 | trend30 = BEAR 且浮盈>0 | TREND_EXIT 卖超额仓（沿用现有，F13 封顶 pos−base_ref） |
| E5 | 换股调出 | RotationPlan 计划调出 | 次日开盘卖，走 §3.3 回款顺序 |

**设计裁决**（待 owner 确认，标 ⚑）：
- ⚑ E3 三档止盈 vs 「合适盈利空间卖出」：owner 原话是「在合适盈利空间卖出」，v1 建议默认档 = {+5%:1/3, +8%:1/3, +10%:全清剩余}，与 TRAIL 并存（TRAIL 管激活后的回撤保护，E3 管未到 TRAIL 激活线的分批落袋）。回测时对 {纯 E3 / 纯 TRAIL / E3+TRAIL 混合} 三臂扫描。
- ⚑ 做T腿在途时 E0~E4 触发：先平腿（腿优先级最高，当日必须闭合），再处理底仓。

## 六、L3 账户层：指标与归因

### 6.1 AccountLedger 记账模型

```
账户净值 NAV(t) = 现金 + Σ 槽位市值
日收益分解（三层，互斥完备）：
  α_选股  = Σ槽 (close_t − close_{t−1}) × base_qty − 换股摩擦
  β_做T   = Σ腿 net_pct × 腿金额           ← 单独核算（owner 硬要求）
  γ_现金  = 现金缓冲的机会成本（对基准利率，可置 0）
摩擦 = Σ换股往返 0.069% + Σ腿往返 0.069%（ETF 0.019%）
```

### 6.2 必报指标（账户级回测报告固定栏目）

| 组 | 指标 |
|---|---|
| 收益 | 净值曲线、年化、超额(vs 沪深300/中证1000)、月度收益表 |
| 风险 | 最大回撤、回撤期长度、波动率、夏普、卡玛 |
| 交易 | 总胜率（按腿+按持仓期分开）、盈亏比、年换股次数、单边换手率 |
| 归因 | **β_做T 累计贡献 vs α_选股 累计贡献（双曲线叠图画在一图上）**；单票贡献分解（α/β 分列）；做T通道分解（OGR/trend30/div30 各自的腿数、净均、胜率） |
| 容量 | 单槽金额敏感性（10万/20万/30万档，验证 5 元最低佣金边界）、腿金额占成交额比 |
| 对照 | 三臂：① 纯选股不做T（β=0 基线）② 选股+做T ③ 纯持有不换股（现状基线）——**做T有没有用，看 ②−①，不看 ② 的绝对值** |

```
  09:31  先执行调出卖出(回款) → 回款确认后执行换入建仓(PENDING_BUY→HOLDING)

  14:55  未闭合腿强制平仓(hold1455 口径, 与 eval_factor 一致)
  14:57  尾盘归位检查(超底仓部分卖出, 沿用 TAIL 语义)
收盘后  AccountLedger 结算当日 α/β/γ → 净值序列追加
```

## 九、分阶段实施路线（离线 → shadow → live）

| 阶段 | 内容 | 验收门 | 预估 |
|---|---|---|---|
| **S0 纯离线仿真** | 在截面面板 + 分钟线上实现 AccountSim 全链（不动 execution/auto 任何代码）。先跑「纯选股不做T」基线确立 α，再叠加做T层看 β | 三臂对照报告（§6.2）；β 的 OOS 增量 > 0 且 Δ vs 纯选股 > 摩擦成本 | 最大工作量段 |
| **S1 参数扫描** | 止盈三臂（纯 E3/纯 TRAIL/混合）、槽位 N∈{3,4,5}、缓冲带 M、min_hold_days、cash_buffer 敏感性 | 参数高原（非单点尖峰）才可用，尖峰=过拟合弃用 | 中 |
| **S2 GM 仿真对齐** | 把 S0 定稿规则经 backtest_holdings.py harness 在掘金回测环境复跑（播种/孤儿闸/撮合伪影按既有坑清单处理） | GM 回测与离线仿真净值曲线偏差 < 可解释阈值（撮合滑点+手续费口径差），否则查齐再前进 | 中 |
| **S3 shadow 影子** | 生产引擎旁路：换股计划与做T信号只落日志不下单（沿用 OGR L3 影子模式与 ogr_shadow_glue） | ≥20 个交易日，影子信号与实际可成交性对账 | 小（模式已有） |
| **S4 live 小资金** | 单槽先行（1 槽 10~15 万），接 gm_main 通道 | 月度复盘：α/β 归因与 S0 仿真分布一致（允许滑点衰减） | 由 owner 裁决 |

**明确不做**：本框架不在 S0 阶段动 execution/auto 生产代码；30min 背离通道未过 eval_factor 预注册前不进门（1min 背离 16861 信号全负期望的教训）。

## 十、风险与已知边界（诚实声明）

1. **选股因子尚未定型**：本设计把 FactorRanker 当可插拔接口；α 的真实性取决于 F1~F3 路调研与 ic_layer 验收，本框架不保证 α>0。
2. **幸存者/前视**：面板是 PIT prevadj，但换股仿真的「当日收盘排名 → 次日开盘成交」假设开盘可得性良好；一字涨停买不进/跌停卖不出须在仿真中建模（否则换手收益系统性虚高）。
3. **做T β 的天花板**：OGR 每票每日至多 1 次、每槽 ≤3 腿、腿量 0.25~0.5 底仓 ⇒ β 量级上限 ≈ 0.5%×0.5×触发率，单票年贡献有限；**β 是增强不是主引擎，这正是战略转向的本意**。
4. **GM 撮合伪影**：S2 对齐前，S0 离线结论的绝对收益不可外推，只有臂间差（②−①）可辩护。
5. **深亏区机制的样本风险**：E0 的「不恐慌+分档减亏」目前只有 7 笔窄窗口证据（反省文档 §1.3），S0 须在大样本上复验。
