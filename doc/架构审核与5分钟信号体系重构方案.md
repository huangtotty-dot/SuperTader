## 0. 审核结论摘要

### 0.1 总体判断

当前系统**信号核心（SignalEngine.evaluate）健康度尚可**：sigmoid 归一化因子 × 权重聚合的评分骨架清晰，实盘/回测/优化器共用同一引擎入口，新指标可以以同构方式低成本接入。

但**工程架构已严重拖累迭代效率**，存在四个系统性问题：

1. **exec 共享命名空间架构**（最大问题）：所有模块被 `exec()` 进同一个 dict，无 import 边界、无显式接口，导致参数双副本漂移、stub 泛滥、无法独立测试。
2. **职责过度集中**：main.py 2074 行装 6 类职责，data_fetcher.py 1083 行装 4 类职责。
3. **死代码堆积**：至少 8 处死状态机/死配置/死指标/死函数，误导后续开发（文档也已被误导）。
4. **指标周期错配**：用户研究结论要求的 5分钟 MACD(12,26,9)、5分钟 BOLL、5分钟 RSI **当前一个都不存在**——MACD/RSI/BOLL 全部算在 1分钟线上，5分钟线上只有一个非标准 MACD(6,13,5)。

### 0.2 关键事实速查（重构决策依据）

| 事实 | 位置 | 影响 |

## 2. 与用户新研究方向的对标分析

### 2.1 研究结论 → 代码现状差距矩阵

| 用户研究结论 | 现状 | 差距 |
|---|---|---|
| 5分钟 MACD 判断全天多空趋势 | 5分钟线只有 MACD(6,13,5) 柱状体（`data_fetcher.py:1073`），且**仅用于量能反转内部判断，未进入评分**；趋势方向（DIF/DEA 零轴位置、金叉死叉）完全未计算 | 需新建标准 MACD(12,26,9) + DIF/DEA 零轴趋势状态机 |
| 布林线辅助 MACD 判断多空 | BOLL 只在 1分钟线且无人消费（死指标） | 需新建 5分钟 BOLL(20,2)，定义"中轨方向+通道开口"趋势确认规则 |
| RSI 捕捉全天超买点/超卖点 | RSI(6) 只在 1分钟线，评分用硬编码 78/35 阈值（`signal_engine.py:1150/1156`），与 PARAMS 键不同步 | 需新建 5分钟 RSI，作为**择时触发器**（在 MACD/BOLL 定方向后找具体买卖点） |
| 5分钟比 1分钟更靠谱 | 现有体系评分因子全部基于 1分钟指标 + 日内统计 | 需要建立"5分钟定方向、1分钟定价格"的双层结构 |

### 2.2 理念融合方案：三层信号架构（核心设计）

不建议推翻现有评分体系另起炉灶。用户的研究结论本质上是为现有体系**补一个"趋势层"**——现有体系最大的盲区正是"当前处于全天多头还是空头阶段"这个状态判断（V1.18/V1.19 曾用 45度斜率/VWAP穿越等 ad-hoc 方法尝试，效果不稳且特征已死）。5分钟 MACD+BOLL 恰好是这个问题的标准解。

```
┌─────────────────────────────────────────────────────────┐
│ 第一层：趋势层（5分钟线，每根新K线收盘时更新）              │
│   MACD(12,26,9)：DIF/DEA 零轴上方=多头区，下方=空头区     │
│                  金叉/死叉 = 趋势切换事件                  │
│   BOLL(20,2)：  中轨斜率方向 + 带宽开口/收口 辅助确认      │
│   输出：trend_state ∈ {STRONG_BULL, BULL, NEUTRAL,       │
│                        BEAR, STRONG_BEAR} + 置信度        │
├─────────────────────────────────────────────────────────┤
│ 第二层：择时层（5分钟 RSI，在趋势方向上找具体点）           │
│   多头区：RSI 从超卖区(≤30~35)回升 → 低吸买点候选          │
│   空头区：RSI 从超买区(≥65~70)回落 → 高抛卖点候选          │
│   NEUTRAL：双向 RSI 极值都做（区间做T）                    │
├─────────────────────────────────────────────────────────┤
│ 第三层：执行层（现有体系，保留）                            │
│   1分钟 VWAP 偏离 / ATR / 量能确认 / 形态因子             │
│   awaiting_buyback 闭环 / 风控 / 动态份数                  │
│   → 趋势层结论作为"方向门控+分数加成"注入现有评分          │
└─────────────────────────────────────────────────────────┘
```

**融合方式**：trend_state 以两个通道注入现有 `calc_buy_score / calc_sell_score`——

1. **方向门控**（替代已死的 V1.19 弱势震荡门控）：STRONG_BEAR 时买入门槛大幅提高/禁止，STRONG_BULL 时卖出门槛大幅提高；这比"VWAP下方时间占比"更贴近用户"全天多空趋势"的直觉。
2. **分数加成**：5分钟 RSI 超卖回升 + 趋势非空头 → buy_score 加分（取代/合并 V1.17 量能反转与 V1.26 higher-low 的职责）；超买回落 + 趋势非多头 → sell_score 加分（与 V1.23 双顶保护互补）。

### 2.3 周期参数的口径统一（必须先做）

| 指标 | 现状 | 统一为 |
|---|---|---|
| MACD | 1分钟(12,26,9) 评分用 + 5分钟(6,13,5) 内部用 | **5分钟(12,26,9) 为趋势层唯一口径**；1分钟 MACD 因子降权或下线 |
| RSI | 1分钟 RSI(6)，config=6 / stub=14 已漂移 | **5分钟 RSI(14)** 为择时层口径（个股可在 STOCK_PARAMS 覆盖为 6）；删除 stub 副本 |
| BOLL | 1分钟 BOLL(20,2) 死指标 | **5分钟 BOLL(20,2)** 复活为趋势辅助 |

## 3. 重构方案（四阶段）

### 阶段一：架构治理（不改信号行为，纯工程）

**目标**：消灭 exec 共享命名空间，让模块可以独立 import 和测试。

1. 改 `main.py:35-99` 装载方式：`exec` → 正规 `import`。按依赖序 `config → utils → data_fetcher → multi_timeframe_fetcher → signal_engine → ...`，各模块顶部改为显式 `from config import PARAMS, STOCK_PARAMS`。
2. 删除 `signal_engine.py:17-228` 的全部 stub（PARAMS 副本首当其冲——双副本漂移已造成 rsi_period 6/14 不一致这种实质 bug）。
3. 参数读取唯一化：只保留 `_sp_param`（`is not None` 语义），main.py 内联的 `or` 写法全部替换。
4. 删除 1.4 节死代码清单全部条目（T_MODE 分支除外，移交阶段二接入）。
5. 拆分 main.py：飞书卡片函数（约600行）→ `notify_cards.py`；两个回放器 → `replay.py`；T模式决策 → `t_mode_decision.py`。main.py 只留装载+主循环+scan_once 编排。
6. 拆分 data_fetcher.py：指标计算（add_indicators/resample/add_*min_indicators）→ `indicators.py`；日线上下文状态机 → `daily_context.py`。
7. 统一回测/实盘编排：抽出 `orchestrator.py`（通知阈值/轮次上限/记账/份数），实盘与 replay 共用，消灭手工对齐。

**验收**：`python -c "import signal_engine"` 独立成功；pytest 可对 ScoringEngine 单测；全量回放 07-24 对照日输出与重构前逐信号一致。

### 阶段二：5分钟趋势层（本次重构的业务核心）

1. **指标层**（新 `indicators.py`）：
   - `add_5min_indicators` 扩展：标准 MACD(12,26,9) 输出 DIF/DEA/HIST；BOLL(20,2) 输出中轨/上轨/下轨/带宽/%b；RSI(14)。
   - 保留旧 MACD(6,13,5) 一个版本周期用于 V1.17 因子对照回测，稳定后下线。
2. **趋势状态机**（新 `trend_regime.py`）：
   - `trend_state` 五档判定：DIF>0 且 DEA>0 → BULL 区；<0 → BEAR 区；金叉/死叉为切换事件；BOLL 中轨斜率同向 + 带宽扩张 → STRONG 档；中轨走平 + 带宽收窄 → NEUTRAL。
   - **防抖动**：状态切换需连续 2 根 5分钟 K线确认（借鉴已删除的 V1.20 观察-确认思想，但以极简形式实现并配单测）。
   - 状态持久化进 intraday_state（重启恢复，复用 `_persist_intraday_state` 机制）。
3. **择时层**：5分钟 RSI 极值反转检测（超卖回升/超买回落），输出 `rsi5_buy_trigger / rsi5_sell_trigger` 布尔事件。
4. **接入评分**（`ScoringEngine` 新增三个同构因子 + FACTOR_WEIGHTS 键）：
   - `score_5m_trend`：趋势方向门控与加成（权重建议初始 0.15，从 vwap/pattern/index_regime 中匀出）；
   - `score_5m_rsi`：择时触发加成（初始 0.10，从 1分钟 rsi 的 0.12 中转移，1分钟 RSI 降权至 0.04 或下线）；
   - BOLL 不单独成因子，作为 trend 置信度内部输入。
5. **接入 T_MODE**：FeatureExtractor 提取 t_mode；反T（short）标的在 BULL/STRONG_BULL 趋势中优先推送卖点、买点从严；正T反之。
6. **实盘性能**：5分钟指标每轮 15s 轮询中**只在 5分钟边界重算**（否则 N 只持仓 × 15s 的重复聚合是浪费）；实盘启用 cached_5m 机制（目前仅回测在用）。

### 阶段三：回测验证（信号行为变更必须过此关）

1. 用 `tushare_range_backtest` / `optimizer` 对 8 只持仓近 90-125 个交易日做 A/B 对照：baseline（当前 V2 评分）vs 新三层体系。
2. 重点观察指标：信号总数（预期下降——趋势层应过滤逆势信号）、胜率、单笔盈亏比、逆趋势信号拦截率。
3. 逐股验证 trend_state 与人工复盘结论的一致性（抽查华工科技 07-08、特变电工 07-07 等已知场景日）。
4. **统一回测成交口径**：回测也走 position_sizer 动态份数（消灭"回测固定200股"的口径风险）后再下结论。

### 阶段四：清理与文档同步

1. 更新 `doc/signal_engine_设计文档.md` 至 V2.0（当前文档已与代码脱节，必须在本次重构后重写核心章节）。

### 阶段排序与风险

- **阶段一必须先做**：在 exec 架构上加新指标，只会加剧 PARAMS 双副本漂移和 stub 腐烂。
- **阶段二不改风控骨架**：RiskManager、awaiting_buyback 闭环、止盈止损追踪全部保留，趋势层只影响评分与门控。
- **最大风险**：trend_state 误判导致全天方向性踏空/逆势。缓解：STRONG 档判定从严（需 BOLL 确认）、NEUTRAL 档双向放行、shadow_signals 持续记录被拦截的信号供复盘。
