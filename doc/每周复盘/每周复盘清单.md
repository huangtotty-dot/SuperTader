# 每周复盘清单 · 做T报警系统

> **版本**：V1.0（2026-08-02 建立）
> **执行时间**：每周六/周日，约半天
> **输入**：本周 `doc\每日复盘\` 下的 5 份日复盘报告 + 每日复盘清单 §5 观察项追踪表
> **输出**：`E:\06_T\doc\每周复盘\YYYY-W##_周复盘.md` + （如有采纳变更）生产 commit + 更新后的观察项表
> **铁律**：本周所有候选变更已在日复盘中"只登记未实施"；本周度流程是唯一合法的优化入口。破闸即放弃，保持现状不碰生产。

---

## §1 汇总（约 30 分钟）

- [ ] 收集本周 5 份日复盘报告的所有「候选变更登记」，逐条抄入候选池
- [ ] **合并同类项**：同一根因的多条登记合并为一个候选变更（例：3 天都登记"漏单-阈值差 1 分"→ 合并为 1 条阈值候选）
- [ ] **剔除单日噪声**：仅 1 天出现、且无 shadow_signals/decision_trace 数据支撑的登记，直接归档（写明归档理由，不删除痕迹）
- [ ] **分流**：运营/bug 类（qty=0、告警失效、数据缺失）——若本周日盘已处理，记录处理结果；未处理的**立即处理，不进优化队列**

## §1.5 周 KPI 表（观察期：只记录不考核）

> 三阶段定位：**①观察期（~8 月底）只记录 → ②基线期（9 月，首次月度架构复盘定正常带）→ ③考核期（10 月起，KPI 变动纳入闸门）**。当前处于观察期——KPI 异常只触发排查，不触发调参。

- [ ] 从本周 5 份日复盘报告汇总下表（每周一行，滚动累积）：

| KPI | 口径 | 数据源 | 当前关注 |
|-----|------|--------|---------|
| K1 周闭环净盈亏 | 按股分解，求和（做T降本最终口径） | 日复盘闭环统计 | 趋势，不看单周正负 |
| K2 持仓成本下降 | 各股 cost 对照上周 holdings.json | holdings.json 周快照 | 做T初心的本质指标 |
| K3 底仓漂移 | 各股底仓股数净变动（未接回/未卖出所致） | 日复盘+收盘同步记录 | **目标=0 或符合意图**；漂移=做T系统悄悄变减仓系统（08-03 588170 −800 为首个案例） |
| K4 滚动 20 条胜率 | 买/卖分开，滚动窗口（不看单日） | decision_trace 累积 | 与回测基线（买 0.50/卖 0.46）的偏离度 |
| K5 qty 冻结拦截数 | 当日 qty=0 信号数（按股） | 日复盘 qty 检查 | 计量健康度；000988 解封前应每日有数 |

- [ ] 周复盘报告开头放本周 KPI 行 + 累计 4 行趋势；异常项（K3 漂移、K4 偏离 >10pp、K5 突增）标黄并写入下周盯盘重点

## §2 排序（约 15 分钟）

按预期影响面排序，参考历史归因规律：

| 优先级 | 类型 | 历史依据 |
|--------|------|---------|
| P1 | 因子失配（某因子在某日型/个股上系统性反向） | 000988 买侧映射失准、趋势层退出 |
| P2 | 阈值失配（信号被阈值错杀/错放） | E1 买阈 42→36、t55 卖阈采纳 |
| P3 | 权重微调（因子贡献度再平衡） | vwap/pattern/index_regime 还权 |
| P4 | 体验优化（告警文案、卡片展示） | trend_state 产品化 |

- [ ] 产出本周 Top 候选清单（**最多 3 个进入下一步**，贪多必失——验证管线容量有限）

## §3 离线筛查（约 1 小时，Top 候选逐个过）

- [ ] 用统一口径数据（`t_io/minute_snapshots_ts/`，450 stock-day 全 Tushare）离线预估每个候选的效果
- [ ] **两层耦合检查（E1 教训，必做）**：候选改动涉及引擎阈值时，同步检查 notify 记录层阈值是否会架空/放大改动；harness 是否需新增对应注入开关
- [ ] 筛选出 **1-2 个决赛档**（被支配的档位直接淘汰，写明支配关系）
- [ ] **锁定预注册闸门**（跑进全管线之前写死，模板见 §5）

## §4 全管线决赛 + 上线（约 2-3 小时，可委托执行代理跑批）

- [ ] 同参数 A/B：决赛档 vs control（当前生产语义），统一数据、信号事件化、确定性双跑（两跑字节级一致）
- [ ] 校验三件套：完整性（块 0 失败、日覆盖 0 失配）+ 回测校验器 + 合并双跑 MD5 一致
- [ ] **按 §3 锁定的闸门逐条判定**：全过 → 采纳；任一破闸 → 放弃，保持现状
- [ ] 采纳变更生产 commit（注释写明依据的周复盘编号与验证产物路径）
- [ ] `signal_engine.py` 头部版本注释：`# Vx.y.z 调优: YYYY-MM-DD 依据 W## 周复盘，改了什么、为什么、预期效果`

## §5 预注册闸门模板（按需裁剪，跑前锁定）

```
闸门① 主口径胜率不低于 control（或 ≥ 指定下限）
闸门② 闭环对数 ≥ control 且 PnL ≥ control（金额口径，防"胜率高不赚钱"）
闸门③ 对侧（改买看卖、改卖看买）退化 ≤ 1pp
闸门④ 弱势日型（阴跌）对应侧胜率不恶化超指定下限
闸门⑤ 信号密度 ∈ [指定区间]（防信号稀释/爆炸）
附加闸（按需）：单股无显著恶化（任一股 wr 降幅 >10pp 且 n≥20 即破）
```

## §6 观察项维护（约 15 分钟）

- [ ] 逐条过每日复盘清单 §5 观察项：已解决的关闭（写明关闭依据）、有新证据的更新、新发现的登记
- [ ] **升级规则**：连续 2 周无结论的观察项 → 升级进月度架构复盘（可能是问题问错了）
- [ ] 更新后的观察项表同步回 `doc\每日复盘\每日复盘清单.md` §5

## §7 周复盘报告（约 30 分钟）

保存至 `E:\06_T\doc\每周复盘\YYYY-W##_周复盘.md`，结构：

1. 本周信号总览（信号数、买/卖胜率、闭环盈亏，对照上周）
2. 候选池处置表（每条：采纳/验证中/归档 + 理由）
3. 决赛结果与闸门判定（如本周有上线变更）
4. 观察项变更记录
5. 下周盯盘重点（1-3 条，写进下周一的日复盘）

**允许"零变更周"**：本周无候选通过筛查/闸门，报告写明"保持现状"即为合格的周复盘。不为了变更而变更。
