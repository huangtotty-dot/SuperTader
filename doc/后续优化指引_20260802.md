**最终口径（V1.1 定论）**：

- **降级残留效应 = degraded − baseline_live = 46.15% − 42.50% = +3.65pp（信号 126 vs 130，密度 0.28 vs 0.29）**。点估计超预注册 ±2pp 闸但**方向为正**（降级残留物 5m_rsi+rsi trigger+timeline 未损害反而微助），且 Fisher 双侧 p=0.60 远不显著——结论：**降级无负面残留证据，验收通过**。
- **簿记激活效应 = baseline_live − baseline@55 = 42.50% − 52.80% = −10.3pp，信号 130 vs 406（−68%），密度 0.29 vs 0.90**。死簿记时代的 52.8%/0.90 主要由"卖穿底仓不受约束"贡献，不可作为活簿记时代的预期基准。

**归因结论：46.15% ≠ 52.8% 的差值不是降级造成的，而是簿记激活造成的（V1.1 同簿记对照已证实）。** 证据链：

1. `post_sell_rebuild_minutes` 补定义前，harness 与 main.py 调 `engine.record_trade_action` 必抛 KeyError 并被 try/except 静默吞掉 → VIRTUAL_TRADES 从不记账 → V1.30 底仓地板保护（signal_engine.py:575-580，`sell_floor_protect`，floor=base×`sell_floor_ratio`=0.5）从不触发。**此前所有验证轮（v107/v108/v109）的绝对数字都是在"死簿记"下测得的**；两组同死法，A/B 对比结论仍有效，但绝对胜率/密度不可跨簿记状态比较。
2. 簿记激活后：588170 首日卖出 2000 股即触底（地板 2000 股），整周剩余天全部 `HOLD_SELL_BLOCKED:sell_floor_protect`。07-21 逐分钟对比显示 degraded 分数反而更高（63-75 vs t55 组 55-60），但全被地板拦截；对照组 t55_v102 一周卖出 10×1300=13000 股 > 初始持仓 4000 股却畅通无阻（死簿记）。
3. **生产侧附带修复声明**：main.py 实盘推送卖出时同样存在静默死簿记（`record_trade_action` 每次抛 KeyError 被外层吞掉），`4ecbec7` 补定义后生产簿记同步激活——实盘地板保护与卖出次数上限（`max_sell_times_per_stock`，signal_engine.py:581-583）自此真正生效，行为与此前实盘不同，需纳入实盘观察。

**收尾口径（V1.1 已完成）**：同簿记对照组 `t_io/validation/v110_baseline_live/` 105 块已全部跑完并合并（见 §0.3 终行）。降级残留效应 +3.65pp（方向为正、Fisher p=0.60 不显著）；簿记激活效应 −10.3pp。验收证据链闭环。

## 1. 买入侧信号产生能力（头号问题）

**现状**：统一口径下所有实验组零买入——v109 baseline@55 的 406 条与 v110_degraded 的 126 条全部 SELL_HIGH。系统实质是"纯卖出信号机"，做 T 闭环（卖出→接回）无法形成，PnL 口径（W2 闭环）因 0 对闭环而退化。

**~~已知线索~~ 诊断结论（✓ 第一步已完成，2026-08-02，`t_io/validation/buy_score_dist/买分分布诊断报告.md`）**：

- ~~买阈值 68 从未做过阈值阶梯实验~~ **前提修正**：68 是全局兜底（config.py:324），5 股个股覆盖实为 40-43（000988/600481=43，其余 40），68 对做 T 池从未生效；引擎决策阈值基础值 42（signal_engine.py:524）。
- **零买入因果链（trace 107,433 tick 实证）**：引擎 90 天 **0 次 BUY_LOW 决策**；23,500 次引擎级 buy-worthy 事件被 `daily_gate`（`daily_buy_t_ok`，signal_engine.py:586/738）~100% 拦截——**daily_gate 是头号瓶颈，不是分数**。
- 买分天花板：68≈全样本 p99（p50=43.3 / p99=68.2 / max=88.1）；恒定底座 30 分（VWAP 恒满分 20 + index_regime 恒 10）+ 可变因子难共振；000988 缺 +15 接回加分（不卖就永不 awaiting，死锁），max 仅 75.8。
- 各档观测预估：68→42 降档**胜率几乎平坦**（0.32-0.55，无单调），但候选 57-100% 被 daily_gate 拦（600176/603667 ≥52 档近 100%）；600481 结构性低质（wr 0.32-0.37）。
- 000988 双向压缩：买 p99=62.7 距 68 差 5.3、卖 max=55.9 贴线——阈值治理双边无效，归 W5 专题或移池。

**路线（V1.2 修正版）**：

1. ~~买分分布诊断~~（✓ 已完成，产物 `t_io/validation/buy_score_dist/`：报告 + buy_score_dist.json + buy_score_diag.py）。
2. **E2 daily_gate 口径专项（优先）**：评估放宽 `daily_buy_t_ok`（ma5_state 集合 / 深跌 bypass 变体）；预注册闸门：买入闭环 ≥10 对且胜率 ≥50% 且卖侧胜率不退化超 1pp。
3. **E1 引擎阈值阶梯（E2 之后）**：基础 buy_threshold 42→36→30 三档全管线重跑；闸门：BUY_LOW 决策密度 1-8/股/日 + 全管线胜率 ≥45% + 闭环 ≥10 对。~~原 68→60→52 通知档方案废弃~~（通知层 40-43 非瓶颈）。

## 2. RSI trigger 强化

**路线**：

1. 离线评估 trigger 的边际区分度：以 v110_degraded 的 signals jsonl 为样本，比较 trigger=True/False 子集的胜率差。
2. 调优路径：trigger 阈值参数化进 config（当前硬编码于 trend_regime.py），做 ±档 A/B；若边际增益 <1pp 则降权或退出，避免重蹈 5m_trend 覆辙。
3. 与 §1 联动：买入侧恢复后，rsi5_buy_trigger 是买信号质量的第一道筛子。

## 4. 密度治理

**现状**：t55 档死簿记密度 0.83-0.90 信号/股日，仍低于 3-8 的目标区间；活簿记下 degraded 密度降至 0.28——地板保护成为密度的新硬约束（588170 首日即触底锁死全周）。

**路线**：

1. **联调地板参数**：`sell_floor_ratio`（默认 0.5，signal_engine.py:578）与 `max_sell_times_per_stock`（默认 3，signal_engine.py:581）需与卖阈值联调——t55 放宽了信号产生，地板却按老密度假设设定。做 (floor_ratio × max_sells × 阈值) 小网格，目标密度回到 1-3 且不穿底仓。
2. per-stock 校准：600176 保留 51 的个案说明一刀切不合理；以各股 score 分布分位数定个股阈值。
3. 信号分级推送：分数带（如 55-60 观察 / 60-70 常规 / 70+ 强推）替代单阈值，缓解"低频但想多看"的矛盾。

## 5. P1 闸门修订

降级后 P1 体系（一致率/反转检测/NEUTRAL 口径/偏差比）整体退役为展示指标，不再作为评分组件的验收闸门。修订要点：

- **P1② 反转检测撤销**：24.1 根 K 线滞后是结构性的——趋势层是状态识别器而非反转检测器，用反转检测考核它属于口径错配（v106 第三轮已定论）。
- **P1③ NEUTRAL 口径**：v110_degraded 复测 neutral_ratio=0.101，与 v105/v106 的 9.7% 一致，口径已稳定，仅作展示。
- 若未来有新的评分因子候选，闸门重起炉灶：预注册 + 统一口径 + 同簿记 A/B（见 §8）。

## 8. 防回退纪律（固化为实验标准）

以下五条经 v105-v110 五轮验证确立，后续一切实验强制执行：

1. **统一数据源**：只用 `t_io/minute_snapshots_ts/`，经 `T_SNAPSHOT_DIR` 切换；新增数据先入该库再实验。
2. **事件化**：信号判定逐分钟事件驱动，禁止日级近似回填。
3. **确定化**：合并结果双跑 MD5 一致才算产物；任何随机源必须种子固定。
4. **同参数 A/B + 同簿记状态**：对照组与实验组共享代码、config、簿记状态，唯一变量为待测因子；跨簿记状态的绝对数字比较一律无效（本轮最大教训）。
5. **预注册**：闸门标准（胜率差、密度区间、闭环对数）在实验开跑前写入方案文档，禁止事后调闸。
