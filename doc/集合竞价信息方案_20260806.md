# 集合竞价信息层方案（2026-08-06）

> **版本**：V1.0（2026-08-06 建立）
> **定位**：把集合竞价从"单一 regime 标签"升级为"四层可验证信息流"。本文为设计 + 数据审计 + P0 采集补全记录；**任何策略接入（regime 修正、作战计划、门控）一律走周复盘验证管线**，本方案不授权任何生产参数改动。
> **背景痛点**：①盘前 regime 预判连续 2/2 天方向踏空（08-04 uni_down 熔断→幻影减仓；08-05 risk_off→全池收涨），竞价解读层太薄是根因之一；②08-05 竞价三层引擎取数全失败静默降级，与 preopen 自有 Top20 路结论并存，**双源矛盾无人仲裁**；③竞价时段（9:15-9:25）个股数据零落盘。
> **配套产物**：`t_io/preopen/auction_collector.py`（采集器，本方案 P0 落地）、`t_io/preopen/auction_2026-08-05.json` / `auction_2026-08-06.json`（首批数据）。

### 1.2 08-05 实例：三层引擎静默全灭（双源矛盾实证）

`preopen_2026-08-05.json`：
- **preopen 自有路（成功）**：market_score=40 risk_off；Top20 竞价额 8 涨/12 跌 → bearish
- **auction_analyzer 三层（全灭）**：`index_signals=[]`、`market_bias="unknown"`、`sector_top5=[]`、7 只持仓 `change_pct=0.0 / amount_wan=0.0 / vol_ratio=1.0`（全默认值）——取数异常被静默 `except: pass` 吞掉，**失败与"真 unknown"无法区分**

## §3 四层信息模型

> 目标：每一层都可落盘、可回测、可证伪。字段以 `auction_YYYY-MM-DD.json` 为载体。

1. **量**：个股竞价成交量 / 昨日总量比（`auction_vol_vs_yday`）、竞价额池内排名、竞价量同比异动（vs 近 5 日竞价均量，样本积累后启用）。
   - 08-05 实例：000988 竞价占昨日 **2.47%**（放量）+ 低开 −7.4% → 当日 V 型 +4.3%（低开放量反转样本）；588170 1.02% / 600176 0.94% / 603667 0.28%。
2. **价**：竞价涨跌幅（vs pre_close）、**9:20→9:25 不可撤段价格轨迹**（上抬/下压/钉平，三点连判）、开盘价 vs 日内 VWAP 初始偏离（开盘位置对早盘节奏的预示）。
3. **构**：匹配量/未匹配量、买卖盘失衡方向——**公开数据源缺口（§2）**；P1 以"不可撤段轨迹方向 × 量比"近似替代（上抬+放量≈买方失衡），并显式标注近似口径。
4. **共振**：持仓池同向率（7 只中同向只数，如 08-06 竞价 7/7 全低开）、池与指数竞价方向一致性、hot_theme 与持仓板块（半导体 ETF/巨石-建材/双良-光伏/华工-CPO/雪人/科泰-AIDC）相关性（复用 auction_analyzer 板块层，修复其静默失败）。

## §4 关键时间窗语义与采集点

| 时段 | 机制 | 语义 | 采集点 |
|---|---|---|---|
| 9:15-9:20 | 可撤单 | 噪音（试盘） | 不采（或低频 1 点作对照，P1 再定） |
| **9:20-9:25** | 不可撤单 | **真实意图** | **09:20 / 09:22 两个快照**（轨迹两端+中点） |

现状只有盘前一次（≈09:31）。采集器落地后每日 3~4 点。

## §5 双源矛盾仲裁规则（设计）

**源清单**：A=index_regime 跨日 S 值/uni_down 等 regime 预判；B=preopen Top20 竞价额偏向；C=auction_analyzer 三层（指数+板块+持仓）。

1. **失败显式化**（P0 即可做，属数据质量）：C 路取数失败必须落 `status:"fetch_failed"` 而非静默空值——失败与"真 unknown"分离，禁止失败源参与结论。
2. **优先级**：竞价真实资金流（B/C 成功时）> 昨日延续外推（A）。理由：两日踏空均为 A 类外推误判（uni_down/risk_off）与当日资金方向相反。
3. **冲突处理**：两源方向相反 → 落 `disagree_flag=true` 并记录双源各自结论（复盘追踪分歧日表现）；熔断类动作（uni_down 买入熔断）在分歧日**降级为观察**——注：此条涉及策略行为，**属 P2，必须走管线闸门**，此处仅登记规则设计。
4. **权重示例（P1 研究素材）**：最终竞价基调 = 0.5×B（Top20 额向）+ 0.3×C-指数层 + 0.2×池共振（§3.4）；A 仅作分歧标记输入，不直接加权。

## §6 三层应用设计

1. **盘前 regime 预判修正**：竞价四层特征 → §5 仲裁输入 → 盘前基调卡（修正连续踏空）。P2，走管线。
2. **个股早盘作战提示**：规则草案——高开 >1% + 放量（竞价量/昨日 ≥1.5%）→ 反T 先卖节奏提示；低开 + 缩量（<0.5%）→ 正T 等回踩提示；**与 V1.25 早盘预警状态机的关系**：竞价层是状态机的**输入源**而非替代——状态机管盘中响应，竞价层管开盘前初始倾向；接入点=状态机初始状态建议字段（接口契约层，V1.25 实现细节未在本次审计范围，接入设计待 P2 立项时核对源码）。P2，走管线。

## §7 GUI 嵌入点（勘察结论 + 设计）

**勘察结论**：用户 GUI = `t_gui.py`（pywebview 桌面壳，805 行）+ `web/`（纯 HTML/CSS/JS：index.html/app.js/style.css + vendor echarts）。js_api 桥：前端调 `Api` 方法（`load_day/kpi_trend/load_quotes/load_live/poll_new_signals/_load_stage_board` 等），**数据只读全部来自现有落盘**。Tab 结构：overview（持仓行情/KPI/盘中实时概览）/ charts（大盘趋势/收益/信号胜率）/ signals（盘中实时/shadow/建仓扫描/**加仓观察**——昨日新段已嵌入）/ archive（持仓对照/结算/阶段看板）。

**嵌入点设计**：
- 后端：`t_gui.py` Api 新增 `load_auction(date)`——读 `t_io/preopen/auction_{date}.json`（只读，同 add_watch 模式）；盘中 9:15-9:25 由前端定时器轮询（参照 `poll_new_signals` 模式）。
- 前端：Tab1 overview 顶部新增 section「集合竞价信息层」：①池内竞价量热榜（auction_vol_vs_yday 排序，条形）②9:20/9:22/9:25 轨迹迷你图（每股 sparkline，上抬/下压/钉平着色）③共振仪表（池同向率 + 与 Top20/指数一致性）④四层明细表（量/价/构/共振四列，§3 字段）。
- 展示层只读已落盘数据，**可先行走 P0**；涉及"作战提示"文案的展示（§6.2）等 P2 验证后上线。

## §8 验证路径

1. **样本积累**：16 天 preopen 历史（市场层）+ `auction_*.json` 自 08-06 起逐日积累（个股层）。
2. **离线研究（P1，周六周复盘立项）**：竞价特征 × 当日日型（bull/bear/chop，`harness_backtest.classify_day_type` close-only 统一口径）条件概率——重点假设：①竞价量/昨日比与当日振幅正相关 ②不可撤段轨迹方向与首 30 分钟方向一致率 ③池同向率 ≥6/7 时当日单边概率 ④低开+放量 vs 低开+缩量的日内反转率差异（08-05 000988 为前者样本）。
3. **预注册闸门草案**（P2 接入前锁定）：
   - 闸门① 竞价基调判向 vs 实际日型准确率 ≥55%（16 日+样本），且**优于同期 regime 预判基线**（当前 0/2，基线易超，正式评估用更长窗）
   - 闸门② 分歧日（disagree_flag）子集：以竞价为准的判向准确率 ≥ A 源
   - 闸门③ 作战提示接入：提示日 vs 非提示日的早盘 30 分钟执行收益差 ≥ 指定下限，且对侧（卖侧节奏）退化 ≤1pp
   - 闸门④ 信号密度 ∈ 指定区间（防竞价提示泛滥稀释）
   - 附加闸（加仓类联动）：竞价低开 + 回踩支撑确认的组合信号，纳入周六「加仓逻辑 V1」一并评估
