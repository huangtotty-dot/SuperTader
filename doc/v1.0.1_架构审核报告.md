## 0. 审核结论摘要

### 0.1 总体判断

重构的**方向与设计忠实度值得肯定**：三层架构按方案落地，权重重平衡数学正确（总和=1.00，匀出来源与方案一致），死代码清理基本到位（stub PARAMS / scenario_factor_state / peak_tracker / SHORT_MODE_PARAMS 等实体已删），TrendRegime 单体逻辑（五档判定、BOLL 从严确认、门控对称性、持久化接口）经合成数据测试**功能正确**。

但**接线（wiring）失败**：新模块从未被装载进运行路径。所有失效都被 `except Exception: pass` 和 `.get(默认值)` 兜底掩盖——这正是 exec 共享命名空间架构的典型病症：**任何断线都不会表现为错误，只表现为"信号悄悄变了"**。

## 1. P0 — 确认断线 / bug（阻断趋势层生效，必须修复）

### B1. indicators.py 孤儿化，新旧两套 5分钟指标并存

- main.py:79 与 replay_day.py 的 exec 装载列表均不含 `indicators`、`trend_regime`。
- 实盘路径 signal_engine.py:452-453 通过 exec globals 解析到 **data_fetcher.py:1058/1078 的旧版** `resample_to_5min/add_5min_indicators`——旧版只产出 MACD(6,13,5)/mom2/量比，**不产出 dif_5m/dea_5m/bb_mid_5m/bb_width_5m/rsi_5m**。
- **修复时的语义陷阱**：换入新版后 `macd_hist_5m` 将从 (6,13,5) 变成标准 (12,26,9)（旧值改名 `macd_hist_5m_fast`，indicators.py:175），而 V1.17 量能反转因子读的是 `macd_hist_5m`（signal_engine.py:830-831）——必须同步改读 `macd_hist_5m_fast`，否则旧因子行为被静默改变。

### B2. 趋势层实盘静默死亡（KeyError 被吞）

- 链路：signal_engine.py:460 `tr.update(_df_5m)` → trend_regime.py:124 `df_5min["bb_mid_5m"]` 直接取列 → 旧版 df 无此列 → KeyError → signal_engine.py:465-466 吞掉。
- 后果链：`trend_regimes[code]` 实例已创建（:457-458）但永远 NEUTRAL/conf=0；门控乘数恒 1.0、阈值惩罚恒 0；trigger 恒 False。**不报错、不留日志**——这是最危险的失效模式。
- 独立 import 模式下同样死亡：signal_engine.py:67-70 保留了返回空 DataFrame 的空壳 stub（冒烟测试 T2 实锤，`se.resample_to_5min` 解析到 signal_engine.py:68）。即 stub 清理时漏了这两个函数，**所有运行路径趋势层全灭**。

### B3. `f5_` 前缀 bug：5m_rsi 是死权重（即使 B1/B2 修好也死）

- 写入侧：extract_all 把 extract_5min_features 的全部键加 `f5_` 前缀（signal_engine.py:712-714）→ 实际键为 `f5_dif_5m` / `f5_rsi_5m`。
- 读取侧：ScoringEngine 读**无前缀**键 `feats.get("dif_5m", 0.0)`（:1106/:1131）、`feats.get("rsi_5m", 50.0)`（:1153/:1168）。
- evaluate 趋势块只补写了 `trend_state/trend_confidence/两个 trigger`（:461-464），从未补写无前缀 `rsi_5m/dif_5m/dea_5m`。
- 后果：`rsi_5m` 恒为 50.0 → trigger 分支 sigmoid(35-50) ≈ 0.0025（×100×0.10 ≈ **0.02 分**）；非 trigger 分支 `rsi5 < 40` 永不成立。**factor_weight_5m_rsi = 0.10 完全没有信号输入。**

### B4. T_MODE 读错 daily_ctx 键，apply_t_mode 永不执行

- signal_engine.py:539：`feats.get("t_mode", daily_ctx.get("trade_gate", "long"))`——`trade_gate` 的值是 `"normal"/"clear"`（daily_sentiment.py 产出），不是 long/short。
- 真正的逐股模式写在 `daily_ctx["t_mode"]`（main.py:1861-1862 注入）和全局 `T_MODE`，两处都没被读。
- :555 守卫 `if _t_mode_str in ("short", "long")` 永远失败 → trend_regime.py:285-309 的 apply_t_mode 是死代码。README.md:99 声称的"T_MODE 集成"未接通。

## 2. P1 — 潜伏 bug（B1/B2 修复后立即激活，必须在同一轮修掉）

### B5. 防抖被 15s 轮询击穿（冒烟测试 T6 复现）

- trend_regime.py:191-203：`_pending_bars += 1` 按 **update() 调用次数**计，不按新K线。实盘每 15s 调一次，一根 5分钟K线内约 20 次调用。
- 设计意图 `trend_debounce_bars=2` = 连续 2 根K线（10分钟）确认；实际 **2 次轮询（约 30 秒）即确认切换**，防抖名存实亡。NEUTRAL 置信度平滑（:210）也被高频调用加速失真。
- 修法：tr.update 只在"新 5分钟边界"时调用——`_5min_cache` 已有 boundary 判等（signal_engine.py:449），仅 boundary 变化时 update 即可一并解决 B5/B6/B7。

### B6. RSI trigger 是单轮事件（冒烟测试 T7 复现）

- trend_regime.py:141-142 每次调用都执行 `_prev_rsi = _last_rsi`。新边界第一次轮询 trigger 可触发；**第二次轮询同一根K线 prev=last → delta=0 → trigger 被吞**。
- 后果：trigger 只在新边界后第一个 15s 轮询窗口可见；该轮评分若未过阈值，本次 trigger **永久丢失**。
- 修法：除按边界调用外，trigger 宜改为"持续 1 根K线有效期"的事件标志（由 evaluate 消费后清除），而不是瞬时布尔。

### B7. _state_history 被轮询刷屏（冒烟测试 T8 复现）

- trend_regime.py:219 每次调用无条件 append；同一边界重复条目淹没真正的状态变迁记录。随 B5 的修法一并解决。

### B8. TrendRegime 持久化完全未接

- `_persist_intraday_state`（signal_engine.py:192-208）只存 cycle/次数/冷却，无 trend_regimes；`to_dict/from_dict`（trend_regime.py:313-345）**全库零调用方**。
- signal_engine.py:108 注释"重启从盘中状态恢复"为虚假声明；重启后全部 NEUTRAL 从头累积（早盘前 25 分钟 `len(df_5m)<5` 连 update 都不执行）。
- 另：`_reset_daily_state_if_needed`（:160-178）重置了 `_5min_cache` 但**不重置 trend_regimes**——昨日收盘趋势/防抖状态被带入今晨，跨日携带未文档化。修复持久化时必须同时定义"每日开盘重置 trend_regimes"的语义。

## 4. 设计确认项（非 bug，需用户拍板）

### S1. 双重惩罚的副作用：强空头下"卖出→接回"闭环实质失效

- 门控应用点 signal_engine.py:537-556：评分后、仲裁前；顺序 风控阻断 → 早盘保护 → awaiting_buyback 加分 → **趋势门控×+阈值惩罚** → 止盈/高抛 boost → 仲裁。顺序合理，与方案一致。
- STRONG_BEAR 下 ×0.3 且阈值+12：需门控前买分 ≥ (42+12−5)/0.3 ≈ 163（满分100）→ **实质禁买**，符合方案"大幅提高/禁止"的意图。
- **但**：awaiting_buyback 的接回 boost 加在门控**之前**，也被 ×0.3 压缩 → 强空头日卖出后接回信号实质失效；且即使 B4 修好，apply_t_mode 的 ×1.15 补偿净效果仅 0.345，象征性。**需拍板：STRONG_BEAR 下反T是否应完全锁死接回？还是接回闭环应豁免趋势门控（毕竟接回是降成本的既定动作，不是新开仓）？** 我倾向后者：awaiting_buyback 接回应豁免门控乘数，只保留阈值惩罚。

### S2. _5min_cache 冻结"残缺成型K线"

- signal_engine.py:447-455：新边界第一次轮询时，成型K线仅约 1 分钟数据即算出指标并**冻结整根 5 分钟**。tr.update 消费的最后一行就是这个残缺K线（开盘第一根尤其失真：1分钟数据算出的 RSI/BOLL 当 5分钟用）。
- 建议：tr.update 只消费**已收盘**的K线（`time <= now.floor("5min") - 5min` 或 cutoff 取上一完整边界），盘中实时性由 1分钟执行层负责——这与"5分钟定趋势"的设计哲学一致（趋势不需要 15 秒级新鲜度）。

### S3. exec 环境下显式 import 的双实例（潜伏雷）

- main.py:80-91 的 exec 装载**不注册 sys.modules** → signal_engine.py:15 `from config import PARAMS` 触发 config.py **第二次真实导入**，产生与 shared dict 不同的第二个 PARAMS/STOCK_PARAMS 实例；config.py 顶层副作用执行两遍。
- 当前对 PARAMS 只读不写 → 暂无实际分歧；未来任何运行时写 PARAMS/STOCK_PARAMS（如 optimizer 的 `PARAMS.update(params)` 模式）即双实例分叉。
- 彻底解法是回到方案阶段一：装载时 `sys.modules[mod_name] = module` 注册（已删除的 tushare_range_backtest.py:118-122 曾是唯一正确姿势），或全面转 import。
- 小瑕疵：signal_engine.py:2-6 的 sys.path 插入算的是 `dirname(dirname(__file__))` = **E:\\**（不是 E:\06_T），无效且误导，应删。
