## §2 G1：sizing_advice 结构化落盘（最关键）

**问题**：`calc_buy_qty`/`calc_sell_qty` 的建议结果只写日志文本，V2 下"qty=0 仅供参考不记账"使满仓参考推送连虚拟账都没有——加仓建议的完整画像无处可查，每日 Review §3 只能解析日志文本（脆弱）。

**方案**：新增落盘 `t_io/traces/sizing_advice_YYYY-MM-DD.jsonl`，每次 sizing 调用写一行。

**字段 schema**：

```json
{
  "ts": "2026-08-13 10:15:30",
  "code": "600481",
  "name": "双良节能",
  "action": "BUY_LOW",
  "buy_kind": "rebuild | first_add",
  "price": 4.41,
  "vwap": 4.4537,
  "suggested_qty": 100,
  "score": 100,
  "t_qty": 100,
  "net_qty": 80,
  "unrebuilt": 20,
  "max_buyable": 20,
  "pushed": true,
  "note": "满仓参考(qty=0) 等异常说明"
}
```

**写入点**：`main.py` 动态份数计算完成后（现"📊 动态份数"日志行同位置），买卖双侧。约 20 行代码。

**验收**：任一日该文件行数 = 当日 sizing 调用次数（与日志"动态份数"行数一致）；字段无缺失。

## §3 G2：forward_tracker 前瞻回填工具

**问题**：两张滚动前瞻表（加仓/建仓）的"次日/3日/5日浮盈"目前要手工算，不可持续。

**方案**：新建 `t_io/validation/daily_review/forward_tracker.py`，每日 Review 时运行：

1. 读取当日报告两张前瞻表的未完结行（次日/3日/5日浮盈任一为空）
2. 按日期差用日线收盘价回填：浮盈% = (当日收盘 − 加仓价/确认价) ÷ 加仓价/确认价
3. 回填判定列：
   - 加仓：次日浮盈 >+0.5% 优 / ±0.5% 内 平 / <−0.5% 劣
   - 建仓：3 日内跌破触发日最低点 → 伪信号；5 日浮盈 >0 → 成功
4. 幂等：已填行不重算；输出汇总行（本周加仓 X 笔，优 X/平 X/劣 X）

**验收**：用 08-13 的实盘 4 笔操作（600481 卖/000988 买/300153 清/603667 摊薄）手工验算一行，工具结果与手算一致。

## §4 G3：建仓确认链路验证与补齐

**现状**：`watchlist_buy.json` 有 `signal_history` 字段，但未发现"人工确认 → 回写确认价"的执行链路（无 confirmed 状态记录）。

**方案**：
1. 周六先验证：GUI 建仓扫描卡片确认按钮是否存在、点击后回写什么
2. 若无链路：在 GUI 概览页建仓区块加"确认建仓"按钮 → 回写 `signal_history`（确认价/确认时间/确认股数）→ forward_tracker 以确认价为基准算前瞻
3. 若链路已在：仅需在每日 Review 模板注明操作路径

**验收**：对一只 approaching 股做确认操作，signal_history 出现完整记录。
