#### A-3 异常三分类判定与处置（复盘的核心动作；来源：掘金 §四）

每个发现的问题/现象，必须归入唯一一类，按类处置：

| 类别 | 定义 | 处置 | 示例 |
|---|---|---|---|
| **① 执行 bug** | 代码行为与设计意图不符，有明确对错 | **随时修**，独立 commit，次日验证 | 假现金、通知漏推、拒单 |
| **② 结构问题** | 规则组合产生的 emergent 行为，无单点对错 | **进 backlog**，走"改→回放→审计"流程 | 绞肉机、通道打架、亏损高抛 |
| **③ 数值问题** | 阈值/参数松紧的感受 | **只记录**，写入数值观察日志，周六/Phase 寻优统一处理 | "感觉 -12% 太松"、"43 分阈值太高" |

**判定口诀**：能指出哪一行错了 → ①；每条规则都对但结果不对 → ②；规则没错只是想调大小 → ③。

**红色判定标准（任一命中即当日总判定红）**：拒单未归因 / 大跌无止损动作 / 仓位超限 / 绞肉机模式（同票连续 ≥3 日分批割肉）/ backtrace 缺失 / 心跳长时间中断未察觉 / **硬止损未全离或硬止损触发日买入**。

#### §5.1 当前排队议题（自 V2.1 §4.1 迁入，随周复盘维护）

> 证据：`doc/experiment/建仓因子挖掘与分批建仓实验_2026-08-27.md`（127 万股票-日 + 34 万 range 股票-日）

1. **分批建仓梯级补全**（优先级高）：首笔已是 1/3，缺第 2/3 笔触发机制——深回撤时追强门控不再出信号，梯级走不完。待决：梯级参数（-3%/-6%/-9% vs -5%/-8%/-12%）、"仅 1/3 成交后反弹"是否允许右侧补第二笔。依据：分批使胜率 +3.4pp、尾部 p5 -2.2pp、满仓成交亏损 -1.9%→-1.1%。
2. **trend_dn 抄底梯级设计**（优先级高）：现行抄底是全表最强信号（w10=66.5% / w20=72.4%）但尾部 p5=-20.4%，适合 -10%/-15%/-20% 梯级摊低（数据：该档 w10=67.9%）。
3. **MACD 金叉加分去留**：因子挖掘显示无边际贡献（金叉 w5=47.6% vs 无金叉 48.3%），建议移除或降权，避免评分虚高。
4. **regime MA60 斜率细化**（仅线索，先验证再议）：[0.97,0.99)+MA60下行是毒区（w10=39.1%）；[1.0,1.005) 带子带有正 edge 但模式不单调。先跑样本外离线验证，过了才进管线。
5. **震荡市门控维持现状**（已裁决，无需动作）：13 个 range 段落 6 向下 6 向上，段内入场期望≈0 且向下段落灾难级，**不开"震荡市小仓位首笔"**。每周仅需确认当前 range 段落（ep13，08-06 起）是否已出方向。
6. **已上线（观察中）**：爆量/远离MA60 双否决因子（每日 C-2 健康检查跟踪）；建仓数据失败路径修复（数据不足不再白送通过、指数断供有 trace 标记）。

**启动前置**：P4 用户执行项 4 件闭环——①回放对比换有持仓窗口重跑；②GUI 自动盘目视；③新终端「启动」复跑；④实盘观察否决因子实运行生效。

**放行标准（2 周日历时间，全部满足）**：

1. 连续 10 个交易日双通道并行，每日 `merge_parity` 对账**无未解释差异**（信号/成交/持仓双侧日终对账逐日通过）⚓（方案 P5）

### L2 模拟盘稳定运行期（证明系统长期可靠 + 执行质量达标）

**时长**：≥ 连续 4 周（📝 owner 拍板项）。

**放行标准（全期累计口径）**：

1. 连续 4 周日复盘总判定**无红**；黄日 ≤ 每周 1 次且全部有归因 📝
2. 拒单：全期 **0 未归因拒单**（每条 reject 当日归因落档）⚓
3. 执行质量：信号→委托延迟 ≤2 bar 达标率 ≥ 95% 📝；滑点单日系统性同向偏移 < 0.1% ⚓
4. 风控全项连续达标：仓位峰值 ≤80% ⚓、硬止损纪律 0 违规 ⚓、绞肉机 0 ⚓、地板穿透 0 ⚓、uni_down 日 0 买入 ⚓

6. 做T 绩效（模拟口径、三栏归因之①栏）：累计做T差价（费后）**为正**，闭环胜率 ≥ 回测预期下限（75%）的 90% 折算（即 ≥67.5%）📝

### L3 小资金实盘试点（自动化交易首次上真钱）

**前置**：L2 全绿 + 下列「实盘硬条件」全部打勾（缺一不上）。

**实盘硬条件清单（最终可以实盘的条件）**：

1. **合规与通道**：券商程序化交易接口开通（掘金实盘/QMT 等）+ 程序化交易报备完成（监管要求）📝 owner 办理项
2. **风控硬兜底实盘复测**：KILL_SWITCH、watcher 旁路仓位（>80% 加急告警）/现金水位告警、单日最大亏损线（-3% 告警 / -5% 建议急停）在实盘环境实测触达 ⚓
3. **止损链路实测**：PANIC / HARD_STOP_EXIT 在实盘环境的触发链路有小单或合成实测证据（N9 类"止损不可达"不得带隐患上实盘）⚓
4. **费用口径校准**：实盘费率与回测/模拟口径一致（0.00015 防线，N11 教训）⚓
5. **应急演练三场景通过**：断网恢复 / 终端崩溃重启仓位核对 / 拒单风暴处理 ⚓（崩溃场景）+ 📝（另两个）

**L3 试点放行标准（→ L4）**：
