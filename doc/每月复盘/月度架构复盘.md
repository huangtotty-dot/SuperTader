# 月度架构复盘 · 做T报警系统

> **版本**：V1.0（2026-08-02 建立）
> **执行时间**：每月最后一个周末，约 1-2 小时
> **定位**：日（记录）→ 周（参数优化）→ **月（架构层）**。日/周循环只能在现有架构内调参；本复盘负责回答架构本身是否还成立。
> **输出**：`E:\06_T\doc\每月复盘\YYYY-MM_架构复盘.md` + 更新后的《后续优化指引》
> **铁律**：本复盘只产出"架构级判断与立项"，不直接改参数（参数仍走周度管线）；架构级立项（新信号源、因子增删、窗口迁移）需单独排期验证。

---

## 核心三问（每问必答，用数据回答，不用感觉回答）

### 问 1：回测窗口是否还代表当前市场？

我们的全部验证基于 2026-03 ~ 2026-07 的 450 stock-day 统一口径数据。市场 regime 漂移会使验证结论失效。

- [ ] 本月指数 regime vs 回测窗口 regime 对比：趋势方向、波动率水平、涨跌家数结构——拉取本月沪深 300/中证 1000 的 20 日波动率与月收益，与回测窗口（3-7 月）同指标对比
- [ ] 持仓 5 股本月日型分布 vs 回测窗口分布：阴跌/盘整/上涨/bull 占比是否显著偏移（任一日型占比偏移 >15pp 即亮黄灯）
- [ ] **判定**：两项均黄灯 → 立项"验证窗口迁移"（用最近 90 日重建统一口径数据集，重跑关键基线）；单项黄灯 → 记入下月继续观察

### 问 2：因子池是否需要增删（而非仅调权）？

- [ ] 各因子边际贡献审计：从本月 decision_trace 分解每条信号的因子贡献，统计各因子"出现在胜信号 vs 负信号"的区分度——区分度趋零的因子标记为**退役候选**
- [ ] 当前退役/降级因子复核：trend_state（纯信息层）展示价值如何？是否该正式产品化（飞书卡片）或彻底移除计算？
- [ ] 新信号源立项评估：本月日复盘/周复盘中是否反复出现现有因子解释不了的漏单/误报模式？（例：连续多周"板块强但个股信号不触发"→ 可能需要板块联动因子）
- [ ] **产出**：因子增删立项清单（每条附证据，排期进下月验证计划）

### 问 3：观察项里有没有"问题问错了"的？

- [ ] 审查周复盘升级上来的"连续 2 周无结论"观察项：是数据不足，还是问题本身 framing 错误？（历史案例：000988"双向压缩"问错了——实际不对称，买弱卖强；"小盈大亏"问错了——实际是 qty=0 幽灵）
- [ ] 对每个此类观察项给出处置：重新表述问题 / 扩大数据窗口 / 关闭并记录教训
- [ ] **教训登记**：本月被证伪的假说写入《后续优化指引》的"已证伪假说"区，防止未来重蹈

## 附加检查项（每月过一遍，约 20 分钟）

- [ ] **系统健康**：数据管线（Tushare 拉取完整性）、飞书告警（本月延迟/丢失次数）、定时任务运行状态（新闻推送、行情报告、日复盘）
- [ ] **参数漂移总账**：本月所有上线变更列表（从 signal_engine.py 版本注释提取）——累计变更方向是否一致？有无互相打架的改动（A 变更放宽、B 变更收紧同一侧）？
- [ ] **实盘对齐**：holdings.json 与实盘持仓是否一致（成本、可T底仓、账户分布）；冻结类运营项（如 000988 qty 链）是否已全部清零
- [ ] **验证纪律自检**：本月上线变更是否 100% 走了"离线筛查→全管线决赛→预注册闸门"全流程？有无破例？破例原因是否可接受？

## 月度报告结构

`E:\06_T\doc\每月复盘\YYYY-MM_架构复盘.md`：

1. 核心三问的回答（每问：数据 + 判定 + 立项/归档）
2. 附加检查项结果（异常项标红）
3. 架构级立项清单（含优先级与排期建议）
4. 已证伪假说登记
5. 下月验证计划（与《后续优化指引》路线对齐更新）
