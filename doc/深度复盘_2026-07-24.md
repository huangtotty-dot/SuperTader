## 一、本质问题：不是阈值，是三层机制叠加导致买入端"制度性瘫痪"

588170 买分 47 > 阈值 32 仍然 HOLD，真正的阻挡是三层叠加：

```
第1层 评分不对称（signal_engine.py:1069-1165）
  uni_down 日卖出端常驻：大盘态势 +20、日线破位风险 +20
  买入端同因子 +0
  → 卖分实测 max 106.8，p90 = 79.9，98% 的评估超过卖出阈值
  → 另有 V1.28 止盈隐形 boost +30，不写入 factors 明细
    （588170 下午卖分被钉死在 75 长达两小时的主因之一）

第2层 风控熔断（signal_engine.py:936）
  if index_regime == "uni_down": buy_block.append(...)  # 硬否决一切买入

第3层 仲裁卖优先（signal_engine.py:597-602）
  can_buy 要求 buy_score > sell_score，且 if can_sell ... elif can_buy
  → 11:10 买分 47 vs 卖分 95.1，买入永远轮不到
```

**关键判断：单边下行日不买，方向上是正确的风控。** 反事实测算：尾盘若把 6 笔实卖接回，约 -0.35%，基本持平——今天"只卖不买"没有造成实际亏损。真正的问题是：

1. 这套防御是**隐性**的——评分、阈值、推送体系没有任何一处明示"今日买入已熔断"，于是呈现出"买分超阈值却 HOLD"的假矛盾，诱使另一份报告（以及人工排查）去改一个无关的阈值；
2. 它是**不可逆**的——卖出没有仓位地板（588170 从 4000 股卖到 300 股，**卖穿 92.5%**），接回机制（阈值降 32 + 15 分）被仲裁和熔断架空，真正的风险敞口是**周一高开的卖飞**；
3. config 里的 `max_sell_times=2` **未生效**，`cycle_count` 是内存态，10:51 进程重启后清零，于是上限 5 次实推了 6 次。6 次卖出不是网格设计，是同一组常驻因子反复越阈的重复触发。

## 二、三只股票"买了就套"：买的是 regime 误分类窗口，卖的是推送阈值静默

**买入侧**：三笔买入（600481 10:17、603667 10:20、000988 10:41）全部打在 10:17–10:41 这个"反抽被误判为 range"的窗口。根因是**日线 regime 状态机（enter=25 / exit=15）被盘中不完整 K 线逐次重算**，range ↔ uni_down 来回抖动——大盘上午已经在恶化，但用不完整的日线算出来还是 range，买入门控放行。这是设计错配：日线语义的状态机不该被盘中复用。

**卖出侧**：买入之后 v2 卖信号**实际触发了**——600481 13:02 sell=53.1 @3.86、000988 最高 61.3、603667 53.0——但全部被 62–67 的推送阈值静默。且触发价已经低于买价。真正缺的不是更低的卖出阈值，是**保本退出/止损通道**（止损明天才生效，方向正确，但需要验证它与 uni_down 熔断、推送阈值的交互）。

## 三、600481 三连买：不是推送重复 bug，是四个子系统状态断裂

链路还原（signal_engine + position_sizer + main.py 走读）：

1. 10:17 买入信号分数达标 → 进入仓控；
2. `position_sizer.py:186-189`：正T满仓首买算出 `max_buyable=0` → 日志"🛑 仓控阻断…跳过交易记录"×3——**系统一股没买，也没记账**；
3. 但推送门控只看分数、不过仓控 → **推送照发**；
4. `record_signal` 写在 `qty>0` 分支内 → **冷却时间不设**；
5. 同一根缓存分钟线在 49s / 67s 内重复评估 → **3 条加急推送**。

本质：信号、仓控、记账、冷却是四个互不通气的子系统，状态在"分数达标但零成交"这个中间态上彻底裂开。表层报告说的"检查是否重复推送 bug"只是第 5 环的表象。

## 四、+13018：记账链路系统性失真，且在污染地基

除了 price=0 伪影，还有三个同源的记账缺陷：

- **静默信号照记账**（main.py:1236-1240，记账在推送分支外）→ 未推送的"幽灵卖出"也参与配对，还会为后续买入腾出虚拟仓位；
- **14:50 收盘同步把虚拟净额直接写进 holdings.json**，固化为次日底仓——今天收盘后 `virtual_trades.json` 已是空 `"trades": {}`，账实核对零依据；
- **07-24 全天 qmt_orders.jsonl 无任何委托落盘**（记录停在 07-18），真实成交侧没有本地凭据。

也就是说：今天的收益数字、持仓快照、次日底仓，三层账都建立在错误的记录上。这比任何阈值问题都紧急——**每天在错误的地基上做决策和反馈**。
