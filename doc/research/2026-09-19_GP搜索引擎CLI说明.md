## 一键启动

```bash
# 冒烟（已验证，3.4 min 端到端通）
python t_io/validation/factor_mining/gp_miner.py --smoke

# 正式轮（单 seed，pop=1000/gen=40，全部默认即设计口径）
python t_io/validation/factor_mining/gp_miner.py --pop 1000 --gen 40 --seed 0

# 多 seed 稳定性（设计 §6.2：≥2 个 seed 的 top 池交集才进终审）——各自独立进程
python t_io/validation/factor_mining/gp_miner.py --pop 1000 --gen 40 --seed 1
python t_io/validation/factor_mining/gp_miner.py --pop 1000 --gen 40 --seed 2

# 终审桥：单个候选表达式走 eval_factor 固定规则裁决（双向都要测！）
python t_io/validation/factor_mining/gp_miner.py --review "<expr>" --sign 1 --exit hold
python t_io/validation/factor_mining/gp_miner.py --review "<expr>" --sign -1 --exit hold
```

## 预估时长（诚实声明）

| 轮次 | 配置 | 实测/预估 |
|---|---|---|
| 冒烟 | pop50/gen3，IS 截 45 日、隔日抽样、init_depth (2,4)、expr_timeout 8s | **实测 3.4 min**（39 只，84 唯一表达式） |
| 正式 | pop1000/gen40，全 IS ~167 日、init_depth (2,6)、expr_timeout 30s | **预估 2~6 小时/seed**（4 万评估、cache 去重后 ~1-2 万唯一；逐表达式成本随树深差异大，子树记忆化在进化中后期命中率升高。比设计文档 §6.1 的 1-3h 略保守，因为 gp_ops 参考实现是逐 bar Python 循环，本引擎虽已用向量化对齐层 gp_fast_ops（提速 10-500 倍），深树仍贵） |

## 关键参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--pop / --gen` | 1000 / 40 | 设计 §1.5 沿用 gp.py：tournament=600、p_cross=0.3、p_sub=0.1、p_point=0.1、p_hoist=0.01 |
| `--corr` | pearson | 单票时序 IC 口径；`spearman` 可选 |
| `--label` | close30 | **修正口径** r=C[t+30]/O[t+1]−1（可成交）；`maxh30` 为原口径A（乐观偏差，仅参照） |
| `--sample-every` | 1 | IS 隔 N 日抽样（>1 仅加速用） |
| `--max-is-days` | 无 | 截 IS 样本量（仅冒烟；正式勿用） |
| `--init-depth` | 2,6 | 初始树深（冒烟 2,4） |
| `--expr-timeout` | 30s | 单表达式全池评估超时判死，防重树拖垮种群 |
| `--no-trig-gate` | 关 | 关闭触发密度闸门 [0.5%, 10%]（不建议） |
| `--mc-every / --n-mc / --topk` | 4 / 30 / 5 | 每 4 代：① |ρ|<0.7 去重组池 ② top-20 日块打乱 MC ③ top-k 费后抽检 |
| `--include-csrank` | 关 | cs_rank 默认排除（单票时序口径下语义扭曲） |

## 硬编码纪律（gp_miner.py 顶部常量）

- IS/OOS 硬边界 **2026-06-01**；适应度只用 IS，OOS-IC 只在 finalize 记录一次、不参与选择
- token_len > 20 硬闸；触发密度全域 [0.5%, 10%] 闸门（S2-7 教训内置）
- fitness = mean_i(IC_i) − 0.05 × 负 IC 票占比（票间一致性惩罚）
- 费后抽检：双边 0.136%，穿越触发（z 上穿 +1），次根开盘成交，30 根后收盘出场，每日 ≤3 次
- n_jobs=1 单进程；表达式字符串全局 cache + AST 子树记忆化（float32 LRU 1500 条）

## 台账（results/gp_mine/gp_ledger_*.json）

每候选字段：`expr / fitness / is_ic / is_ic_std / neg_frac / trig_rate / oos_ic /
mc{null_mean, null_q95, real_ic, verdict} / fee{n, net_mean, rand_mean, delta} /
sign_hint / final_review（终审桥命令）`。SUSPECT = 真实 IC ≤ null 95 分位，不进终审。

## 已知落差（诚实声明）

- 搜索期 label（close30）虽修正了口径A 的「卖在最高」乐观偏差，仍是固定 30 根出场
  的代理；终审由 eval_factor 的 hold/native 出场臂裁决，两者落差须在报告中声明。
- 冒烟费后抽检结果：前 3 候选 fee delta 全部 ≤ 0（-0.0007 ~ -0.0010），再次印证
  S2-7 结论——时序 IC 与费后可交易性之间存在系统性落差，正式轮筛因子应以
  「MC PASS + fee delta > 0 + 终审 KEEP」三重闸门为准。
