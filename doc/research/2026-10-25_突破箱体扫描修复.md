# 突破箱体扫描：跑不出结果的根因 + 筛选质量收紧（2026-10-25）

## 1. 为什么「经常跑不出结果」

截图那条「非北交所 5048 只无日线 —— 掘金终端可能未连接」就是根因，链路是这样的：

1. 扫描每批 200 只走 `facade.daily_many`（掘金 `history`）；
2. **GM 没连上** → 返回 `{"status":1001,"无法连接到终端服务"}` → facade 进 60s 冷却，**窗内所有调用转腾讯逐只兜底**；
3. 200 只逐只兜底要好几分钟，整轮 5000+ 只根本跑不完；中途拿到的帧也不全；
4. 最后 `ok==0 / 缺帧≥50%` 触发「结果不可信」，一屏红字、0 命中。

**改法（三层）**：
- **缓存优先**：开扫前抽样 80 只检查本地日线缓存对目标日的覆盖率，≥80% 就**完全不碰 GM**（猎手每天本来就在写这份缓存）；
- **硬超时**：单批 `daily_many` 给 25s 预算，超时即放弃 GM、后续批全走缓存（不再无限等）；
- **逐只兜底**：GM 缺帧的票改用 `t_io/cache/daily_kline/{code}.json`，只有缓存也没有才算 no_data；
  「结果不可信」只在**真的没数据**时才报（stale/缺帧分开计）。

实测（本机 GM 完全未连）：**全池 5789 只 → 90 秒跑完**，
`ok=1918 / stale=3470 / cached=1918 / no_data=12 / fetch_failed=False`，命中 7 只。
不再出现"整池不可信"。

### 顺带发现的坑：成交量单位迁移污染量比

日线缓存在 10-22 做过一次成交量单位迁移（`daily_kline_bak_20261022_volunit`），
前后段一手一股混在一起 —— 实测 600887 相邻两天差 27 倍，直接算量比会得到 0.07x，
被误判成"缩量"反而加分。已加单位一致性闸：20 日窗口内相邻日比值超出 [0.1, 10] 就
**不报量比**（显示为空），宁缺勿错。迁移满 20 个交易日后会自然恢复。

## 2. 筛选质量（依据仓库自己的研究）

依据 `doc/research/2026-10-23_箱体突破_第二轮_回踩与站稳.md` §3 的分档结果：

| 分档 | T+5 超额 | 处置 |
|---|---:|---|
| 幅度 0.3~1% | −0.15% | 保留（相对最好） |
| 幅度 3~5% | −0.65% | **上限 8% → 3%**，剔掉 |
| 当日涨幅 >7% | −0.58% | **新增硬闸，剔除** |
| 量比 >2.5（放量） | −0.47% | 不打"放量确认"，改成**缩量加分** |
| 量比 <1（缩量） | +0.05% | 唯一不亏的一档 ⇒ 排序优先 |

具体改动：
1. `_BK_MAX_PCT` 8 → **3**；新增 `_BK_MAX_CHG = 7%` 硬闸；
2. 每只票算 **量比**（当日量/20 日均量）与**质量分**（缩量+2、幅度≤1.5%+2、当日涨幅≤3%+1）；
3. **排序从「超出上沿越多越前」改成质量分优先** —— 原来那个排序正好把最差的 3~8% 档排在最前面；
4. 界面：标题写清新口径，行内显示「缩量 x.x / 放量 x.x / 量比」，悬停看当日涨幅与质量分。

## 3. 仍然要说清的

这份研究的总判词是**箱体突破本身是负 alpha**（T+5 超额 −0.28%），本轮的取舍是
「在已知为负的信号里，把最差的几档剔掉、把不亏的那档提前」，不是把它变成正期望。
真要当买入依据，还需要重做信号定义（研究建议先重测"放量确认"那条反指）。
