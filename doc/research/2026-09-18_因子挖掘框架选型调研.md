# 因子挖掘框架选型调研报告

> 2026-09-18 · 五路并行调研（Qlib / RL+LLM 生成式 / 遗传规划+公式库 / A股本土生态+回测 / 本地资产勘察）整合
> 目的：为「高波动标的 + 底仓不动 + 活动仓日内获利」与「震荡末期/单边上涨波段低吸高抛」两条策略线选择开源因子挖掘框架

---

## 一、关键发现：我们不是从零开始

本地勘察（方向E）证实 `t_io/validation/factor_mining/` **已存在一条跑过两轮的因子挖掘链**：

- `factor_ops.py`：严格因果的日内时序算子（ts_corr/ts_rank/decay_linear/vwap_dev/smart_money_dev…）
- `factor_lib.py`：22 个基线因子 + 阳性对照
- `eval_factor.py`：交易式终审裁决器（费后 0.136% 双边成本、双向都测、多重比较计数、--leak 前视自检、OOS 2026-06-01）
- `gp_mine.py`（GP 搜索，未跑出台账）+ `llm_mine.py`（LLM 臂 40 条候选**零条为正**，已证伪）
- 验证纪律编码化：预注册闸门、200 次蒙特卡洛随机基线、OOS 切分——与 B7 实验同套文化

**真正的缺口只有两层**（方向E 结论）：

| 层 | 现状 | 缺口 |
|---|---|---|
| 数据层 | ✅ 全市场 5,674 只（含退市）×8 年日线面板（parquet, 197MB）；39 只×1 年分钟库 | ❌ 分钟级全市场多年面板；⚠️ 面板复权口径未显式指定（fetch_panel.py:77 未传 adjust） |
| 因子计算层 | ✅ 单股日内时序算子 | ❌ 截面算子（rank/zscore/中性化） |
| **IC 评估层** | ❌ **全缺** | ❌ 无 RankIC/ICIR/分层多空——没有 IC 初筛，每个候选因子都要走交易仿真，吞吐量撑不起系统性挖掘 |
| 环境层 | managed 3.12 / 用户 3.11 | ⚠️ managed 3.12 连 pyarrow 都没有（读不了自家面板）；两边都无 qlib/ta-lib/xgboost |

## 二、五路调研评分总表（针对「日内做T+波段因子挖掘」场景）

| 框架 | 评分 | 一句话结论 | 来源方向 |
|---|---|---|---|
| **qlib（表达式引擎+HighFreq handler）** | **8.5 / 6.5** | 因子产出-验证流水线最成熟（Alpha158 可跑 1min、表达式字符串造因子、RollingGen walk-forward、IC 工具链）；但范式是截面选股，无 T+0 账户模型，分钟级是二等公民 | A/D |
| **QuantsPlaybook** | **8** | 券商金工高频因子复现集（APM/聪明钱/理想反转/高频量价相关）——**本来就是分钟线构造的 A股因子，即插即用** | D |
| **AlphaGen（ICT-FinD-Lab）** | **7** | RL/GP/LLM 三臂公式因子挖掘，白盒可审计，活跃维护（1235 star，2026-06 仍在提交）；**最大价值是其 AlphaCalculator 抽象接口 + 内置 GP baseline（改造版 gplearn）** | B/C |
| **vectorbt（开源版）** | **7** | 万组参数向量化扫描 + **内置 `from_random_signals` 蒙特卡洛随机基线**（与我们验证文化零摩擦）；T+1 需手工 sellable mask | D |
| **rqalpha（开源）** | **7** | A股 T+1+涨跌停+部分成交原生撮合，最忠实的**终验回测**引擎 | D |
| **TA-Lib + MyTT** | **7 / 6.5** | 分钟级指标计算主力（频率无关）；MyTT 中式口径源码可读可改 | D |
| **RD-Agent(Q)** | **5-6** | 微软 LLM 自动因子闭环（14.7k star），但日频截面导向、产出必须再过自有闸门；可作波段因子「假设生成器」 | B/D |
| **gplearn 0.4.3** | **6** | 2026-01 恢复维护，Windows/CPU 友好；时序/截面算子与 IC 适应度全要自建（1-2 周） | C |
| **Alpha101/191 公式库** | **5** | 全日频选股公式，无一分钟级；只配当**算子字典+GP 初始化种子库**（191 精选 ~30 个分钟化移植约 1-2 周） | C |
| vnpy 4.0 | 6.5 | 实盘基因最强，未来接实盘下单的桥；因子模块偏选股 | D |
| backtrader | 3 | 停止维护，不引入 | D |
| 聚宽/vectorbtpro | 4 / 6 | 云端锁定 / 闭源黑箱，与验证文化冲突 | D |

**所有框架的共性缺口**（方向B 点破）：它们的目标函数全是**截面选股 IC**；做T 是**单标的时序择时**。这个错配换框架解决不了，奖励函数/label 重设计的工程量必须预算进去。

## 三、最终选型：组合拳，而非单一框架

```
┌─ 因子思想库：QuantsPlaybook（APM/聪明钱/高频量价相关，分钟级原生）
│    + Alpha191 精选 ~30 公式（GP 种子/算子教材）
├─ 因子计算层：自研 IC 薄层（~300-500 行，pandas+scipy）
│    复用现有 factor_ops 时序算子 + 新增截面算子
│    （暂不引入 qlib——见下方「为什么不先上 qlib」）
├─ 因子搜索层：AlphaGen 的 GP baseline（改造版 gplearn + AlphaCalculator 接口）
│    适配 GM 分钟线，适应度=费后净均/条件 ICIR
├─ 快速筛选层：vectorbt 开源版（参数大网格扫描 + from_random_signals MC 基线）
├─ 终验层：现有 eval_factor.py 交易式裁决（预注册闸门+OOS+MC）
│    + rqalpha 做交割规则忠实的 OOS 终验（防向量化回测成交乐观偏差）
└─ 执行层：不动——因子产出评分/信号，喂给现有 t_engine_auto / signal_engine
```

### 为什么不先上 qlib（尽管它单项最强）

1. qlib 的四件套（数据层+因子层+模型层+IC 分析）里，数据层要 GM→CSV→bin 转换（1-2 天纯体力），IC 分析口径与我们既有闸门不一致要再适配；
2. 我们的缺口是「300-500 行 IC 初筛层」，用 qlib 解决等于为喝口水挖口井；
3. qlib 的截面选股范式与单票时序做T 错配，回测层用不上；
4. **保留升级路径**：IC 层跑通、确认需要 ML 非线性组合（LightGBM/XGBoost 因子合成）或 RD-Agent 自动假设生成时，再引入 qlib 不迟——届时数据转换器也已就位。

### LLM 臂的处理

llm_mine 臂 40 条零为正的结论与调研互证（方向B：RD-Agent 实测同样暴露「LLM 决定改什么」的黑箱环节 + SOTA 准入过松）。**LLM 臂降级为「假设生成器」**：只产出候选思想，因子必须走 GP/IC/终审管线，不接受直接入库。

## 四、落地路线（三阶段）

### 阶段 1：IC 初筛层 + 标的池因子化（1 周，纯自研，无新框架依赖）

1. **环境修复**：managed 3.12 装 pyarrow（或 IC 层跑在用户 3.11）；确认 xsection 面板复权口径（fetch_panel 未传 adjust——动量/反转类因子的生死题）
2. **IC 层**（~300 行）：面板 → 日频 forward return（T+1 开盘/T+1 收盘双口径）→ 按日 Spearman → RankIC 均值/ICIR/胜率 + 十分位分层净值；接口与 eval_factor 终审对齐
3. **波动选股因子包**（对应策略线①）：振幅（H-L）/C、ATR%、vol-of-vol、日内回转率、尾盘 30min 波动占比——在 5,674 只面板上跑 IC + 分桶，产出「高波动做T候选池」月度榜单（替代现在的持仓驱动池）
4. **波段 regime 因子包**（对应策略线②）：震荡识别（ADX<20 持续 N 日、布林带宽收缩=震荡末期）+ 单边上涨确认（均线多头+ADX 上穿）——作为低吸高抛的**入场过滤器**因子

### 阶段 2：分钟级 GP 因子挖掘（2-3 周）

1. 读 AlphaGen 的 GP baseline 与 AlphaCalculator 接口（1 天）
2. 在其改造版 gplearn 上接 GM 分钟线适配器（复用 run_experiment_v2.merge_days 双源管线），label = 日内回转收益（与 B7 实验口径同族）
3. Alpha191 精选 ~30 个短周期价量公式分钟化移植（窗口重标定：日×240 ≠ 分钟，跨日边界单独处理），作初始化种群种子
4. 过拟合控制沿用既有文化：IS/OOS + 因子池互相关去重（|ρ|<0.7）+ MC 随机标签基线（vectorbt from_random_signals 或现有 harness）
5. 候选因子 → eval_factor.py 终审 → 台账入库

### 阶段 3（可选，评审后定）：qlib + RD-Agent 升级

- 当 IC 层证明需要 ML 非线性组合时引入 qlib（Alpha158@1min + HFLGBModel + RollingGen）
- RD-Agent(Q) 作波段日频因子的自动假设生成器（DeepSeek API 成本几十元/轮），产出全部过自有闸门

## 五、风险与待验证项

| # | 事项 | 处置 |
|---|---|---|
| 1 | xsection 面板复权口径未确认 | 阶段 1 第一步，动量/反转因子前必须解决 |
| 2 | 分钟级全市场面板不存在（只有 39 只×1 年） | 先用 39 只跑通管线；扩容用 GM 60s×240/日 滚动采集 + fetch_panel 分片续拉模式 |
| 3 | 纯 CPU 跑 GP 分钟级适应度慢 2 个数量级 | 采样初筛（部分票×部分时段）+ numba/polars 加速 |
| 4 | 截面 rank 分钟级计算量 ×240 | 只在关键时点（5/15min）做截面，或只做单票时序因子 |
| 5 | RD-Agent/LLM 产出黑箱环节 | 只当假设生成器，全部过预注册闸门 |
