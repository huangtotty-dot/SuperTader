## 一、GP baseline 完整架构（①）

### 1.1 入口与总体结构

GP baseline 的实验脚本是**仓库根目录的 `gp.py`**（不在 `scripts/` 下，README 描述有滞后）。调用链：

```
gp.py
 ├─ gplearn.genetic.SymbolicRegressor   ← 改造版 GP 引擎（/gplearn）
 ├─ alphagen_generic.operators.funcs    ← 算子集（字符串构造函数）
 ├─ alphagen_generic.features           ← 6 个特征 + target 定义
 ├─ alphagen_qlib.calculator.QLibStockDataCalculator  ← 适应度后端（IC 计算）
 └─ alphagen.models.linear_alpha_pool.MseAlphaPool    ← 因子池（离线组装用）
```

### 1.2 改造版 gplearn 改了什么（实测 diff，仅 3 处、约 10 行）

将 `/gplearn` 与官方 0.4.2 逐文件 diff，`_program.py` **零改动**，改动集中在：

| 文件 | 改动 | 目的 |
|---|---|---|
| `genetic.py` | `fit()` 签名加 `callback=None`，每代结束调用 `callback()` | 每 N 代钩子：从 cache 取 top 因子组装池、落盘 JSON |
| `genetic.py` | 注释掉 `X, y = self._validate_data(X, y, y_numeric=True)` | 放行**字符串数组** X 和 dummy y |
| `functions.py` | `make_function` 删除闭包检查（zeros/negatives 输入必须返回 finite） | 自定义算子是**字符串拼接器**而非数值函数，过不了闭包检查 |
| `fitness.py` | `make_fitness` 删除「function 必须返回数值」的探针调用 | 适应度函数收到的 y_pred 是表达式字符串，探针会误伤 |

**核心 trick**：GP 不在数值上进化，而在**表达式字符串**上进化。

- `X_train = np.array([terminals])`：1×20 的 object 数组，元素是 `'open_'`、`'close'`、`'Constant(-30.)'` 等**字符串**；
- `y_train = np.array([[1]])`：纯占位；
- 每个算子是返回字符串的函数，如 `Mean` 的 GP 包装：`f(a) → "Mean(" + a + ",10)"`（见 `alphagen_generic/operators.py`）；
- 个体 `execute(X)` 的产物就是一条 alphagen 表达式字符串，如 `Div(Sub($close,Mean($close,20)),Std($close,20))`。

### 1.3 适应度函数怎么接

`gp.py` 的 `_metric(x, y, w)`（注意参数名有迷惑性：`y` 实为 y_pred，即字符串数组）：

```python
key = y[0]                          # 表达式字符串
if key in cache: return cache[key]  # 全局 dict 缓存，按字符串去重
token_len = key.count('(') + key.count(')')
if token_len > 20: return -1.       # 复杂度硬惩罚：表达式长度>20 直接判死
expr = eval(key)                    # 字符串 → alphagen Expression 对象
ic = calculator_train.calc_single_IC_ret(expr)   # 真适应度 = 训练段 IC
# OutOfDataRangeError / NaN → -1
cache[key] = ic
Metric = make_fitness(function=_metric, greater_is_better=True)
```

要点：**cache 字典是整套 GP 的隐形记忆库**——去重、终选（`Counter(cache).most_common`）、组池全走它。

### 1.4 算子集定义（`alphagen_generic/operators.py`）

| 类别 | 算子 | 窗口 |
|---|---|---|
| 一元 | Abs, Log | — |
| 二元 | Add, Sub, Mul, Div, Greater(max), Less(min) | — |
| 滚动一元 | Ref, Mean, Sum, Std, Var, Max, Min, Med, Mad, Delta, WMA, EMA | × {10,20,30,40,50} 各注册为一个独立函数（`Mean10`…`EMA50`，共 60 个） |
| 滚动二元 | Cov, Corr | × 同上 5 窗口（10 个） |

terminals = 6 特征（open/close/high/low/volume/vwap）+ 14 个常数（±30/±10/±5/±2/±1/±0.5/±0.01/0.5…），`const_range=None`（不允许随机常数）。

注意：GP 版算子集是 alphagen 完整算子表的**子集**（缺 Sign/Pow/CSRank/Skew/Kurt/Rank；Pow 和截面 Rank 不在 GP baseline 里）。

### 1.5 种群/进化参数（gp.py 实测值）

```python
SymbolicRegressor(
    population_size=1000, generations=40,
    init_depth=(2, 6), tournament_size=600,
    p_crossover=0.3, p_subtree_mutation=0.1,
    p_hoist_mutation=0.01, p_point_mutation=0.1, p_point_replace=0.6,
    max_samples=0.9, parsimony_coefficient=0.,   # 复杂度惩罚为0，靠 token_len>20 硬闸
    stopping_criteria=1., const_range=None, n_jobs=1,
    function_set=funcs, metric=Metric, random_state=seed,
)
est_gp.fit(X_train, y_train, callback=ev)   # ev: 每4代组池落盘
```

每 4 代 `ev()` → `try_pool(capacity=20, mutual_ic_thres=0.7)`：从 cache 按 IC 降序取候选，`calc_mutual_IC` 逐个过滤 |ρ|≤0.7 后 `force_load_exprs` 进 `MseAlphaPool`，分别在 train/test 计算器上 `test_ensemble` 记录 IC/rIC。

## 二、AlphaCalculator 抽象接口（②）

### 2.1 完整签名与语义（`alphagen/data/calculator.py` 实测）

```python
class AlphaCalculator(metaclass=ABCMeta):
    calc_single_IC_ret(expr) -> float          # 单因子 × 预置 target 的 IC
    calc_single_rIC_ret(expr) -> float         # 同上，Rank IC
    calc_single_all_ret(expr) -> (IC, rIC)     # 有默认实现（两次调用）
    calc_mutual_IC(expr1, expr2) -> float      # 两因子之间的 IC（注意：不是对 target！）
    calc_pool_IC_ret(exprs, weights) -> float  # 线性组合 Σwi·fi 后对 target 的 IC
    calc_pool_rIC_ret(exprs, weights) -> float
    calc_pool_all_ret(exprs, weights) -> (IC, rIC)
```

`TensorAlphaCalculator` 提供了**全部默认实现**，接自有数据真正要写的只有两个成员：

```python
class TensorAlphaCalculator(AlphaCalculator):
    def __init__(self, target: Optional[Tensor])   # target 是预求值的张量，不是表达式
    @property @abstractmethod
    def n_days(self) -> int                        # 时间轴长度
    @abstractmethod
    def evaluate_alpha(self, expr) -> Tensor       # 表达式 → (days, stocks) 张量
```

### 2.2 语义细节（决定适配正确性）

- **IC 的时间结构**：`batch_pearsonr(value, target)` 输入形状 `(days, stocks)`，**沿 dim=1（股票维）逐日算截面 Pearson**，返回 `(days,)` 序列，再 `.mean()`。即 alphagen 的 IC = 日频截面 IC 的均值。`_calc_ICIR` = mean/std（`calc_pool_all_ret_with_ir` 暴露 IC/ICIR/rIC/rICIR 四元组）。
- **NaN 处理**：`_mask_either_nan` 把任一 nan 的位置双边置 0，方差 <1e-3 的日期相关系数强制为 0。
- **归一化在计算器侧**：官方实现 `QLibStockDataCalculator` 对 `evaluate_alpha` 和 target 都做 `normalize_by_day`（按日截面 z-score）。**适配器也必须做截面归一化**，否则不同量纲因子的 mutual IC 与池线性组合全失真（README 也明确警告）。
- `calc_mutual_IC` 是「两因子值序列的逐日截面相关均值」，衡量因子暴露冗余，不是收益相关。

### 2.3 接自有数据的最小实现清单

1. 一个 `StockData` 等价物：`(n_bars, n_features, n_stocks)` 张量 + `max_backtrack`/`max_future` 元数据（`Feature.evaluate` 依赖 `data.max_backtrack_days` 做窗口偏移，越界抛 `OutOfDataRangeError`）；
2. `MinuteAlphaCalculator(TensorAlphaCalculator)`：实现 `evaluate_alpha`（表达式求值 + 截面/时序归一化）和 `n_days`；
3. target 张量：预计算的 label，形状对齐 `(days, stocks)`。

## 三、目标 label 形态与奖励函数重设计（③）——截面选股 → 单票时序择时

### 3.1 alphagen 原生 label

`alphagen_generic/features.py` 与 `scripts/rl.py` 一致：

```python
target = Ref(close, -20) / close - 1    # 20 个交易日前瞻收益（负 dt = 未来）
```

形态：**T 日收盘 → T+20 日收盘的截面收益**，`(days, stocks)`，评价单位是「日」，统计单元是「日截面」。这是典型截面选股范式。

### 3.2 我们的 label：单标的分钟级日内回转收益

候选两种口径（与 eval_factor.py 既有口径同族，次根 bar 开盘成交）：

```
口径A（日内回转）：r_{i,t} = max(high_{i, t+1 .. t+30}) / open_{i,t+1} − 1
   （买入信号于 bar t 触发，t+1 开盘成交，看 30 分钟内最高可及回报）
口径B（隔夜回转）：r_{i,d} = open_{i,d+1} / close-ish_{i,d 尾盘锚点} − 1
```

label 张量形状 `(bars, stocks)`，时间轴从日换成分钟 bar。**范式转换的核心：统计单元从「日截面 300 只」变成「单票时序 240 bar/日」，且全池只有 39 只——截面维度统计功效崩塌，时序维度成为主信息源。**

### 3.3 三种奖励函数候选

**候选一：条件 IC（conditional cross-sectional IC）**
只在触发条件满足的 (t, i) 子集上算截面 IC，如仅在「当日振幅>中位数」或「因子 z>0」的样本上。

```
fit_condIC = mean_d( corr_{i ∈ triggered(d)}( f_{i,d}, r_{i,d} ) )
```

- 利：保留 alphagen 接口形态与池机制（mutual IC/线性池语义不变）；截面逻辑与 RL 臂兼容。
- 弊：39 只截面太窄，单截面有效 n 可能 <10，IC 方差极大；触发稀疏时大量日期无截面可言；费后不可交易性不进入适应度。
- 判定：**不适合做主适应度**，可作辅助诊断。

**候选二：单票时序 IC（per-stock time-series IC，推荐主用）**

```
IC_i = corr_t( z(f_{i,t}), r_{i,t} )          # 每只股票内部时序相关，因子先做同日同时刻历史 z-score
fit_tsIC = mean_i(IC_i) / (std_i(IC_i) + ε)    # 类 ICIR 的跨票稳定性形态；或 mean_i 加权（成交额）
```

- 利：样本量 = 39 只 × 240 bar × ~245 日 ≈ 229 万点，统计功效充足；天然对齐「单标的择时」语义；每票一个 IC 还能给出**票间一致性**（IC_i 全正 ≫ 均值高但三七开）——这正是做 T 因子最需要的性质。
- 弊：时序自相关使 IC 名义值膨胀（需 MC 基线校准）；跨票波动率差异需要 z-score 前置；不直接含成本。
- 实现：`evaluate_alpha` 不变，重写 `_calc_IC` 为沿 dim=0（时间维）逐票相关——正好覆盖 `TensorAlphaCalculator` 的钩子点。

**候选三：费后净均（交易式适应度）**
把 eval_factor 的简化版嵌进适应度：z-score 触发 → 次根开盘成交 → 固定出场臂 → 双边 0.136% 成本。

```
fit_net = mean(net_ret) − λ·max(0, baseline_mc50)   # 减随机基线中位数，λ≈1
```

- 利：与终审 `eval_factor.py` 同口径，消灭「IC 高但费后不赚钱」的错配；直接惩罚触发过频（成本磨损）。
- 弊：每次适应度 = 一次小型事件回测，纯 CPU 成本比 IC 高 1-2 个数量级；目标面非平滑、噪声大，GP 选择压力差；把交易规则（z 阈、出场臂）烘进搜索结果，预注册口径有泄漏风险。
- 判定：**不做主适应度，做每代 top-k 抽检器**（见 §五链路图）。

**推荐组合**：主适应度 = 候选二（票间稳定化时序 IC）+ 触发率下限约束（每分钟 bar 全域触发率 ∈ [0.5%, 10%]，防「永不触发」和「常数触发」两种退化）；每代 callback 对 cache top-20 跑候选三抽检并记录；终审才走完整 eval_factor。

## 四、因子池管理与 |ρ|<0.7 去重的实现位置（④）

互相关去重**不在 gplearn 里**，分布在两层：

1. **`alphagen/models/linear_alpha_pool.py`（核心）**：
   - `LinearAlphaPool._calc_ics(expr, ic_mut_threshold)`：先入池检查——`calc_single_IC_ret < ic_lower_bound` 拒绝；再对池内每个因子 `calc_mutual_IC`，任一超过 `ic_mut_threshold` 拒绝。RL 在线路径 `try_new_expr` 用阈值 **0.99**（很松，靠后续权重优化挤掉冗余）。
   - 池满（>capacity）时 `optimize()` 重配权，删除 |weight| 最小者；`MseAlphaPool.optimize` 是带 L1 的 Adam：`loss = wᵀΣw − 2wᵀic + 1 + 5e-3·‖w‖₁`（Σ = mutual IC 矩阵），`l1_alpha=0` 时退化为 `lstsq(Σ, ics)`。
   - 注意 `_calc_ics` 里比较的是 `mutual_ic > threshold`，**没取绝对值**（`gp.py` 的离线筛选用了 `abs()`，两处口径不一致——负相关因子在 RL 路径不会被去重，适配时建议统一为 |ρ|）。
2. **`gp.py` 的 `try_pool(mutual_ic_thres=0.7)`（GP 实验的实际去重点）**：离线从 cache 组池时 `all(abs(calc_mutual_IC(e, new)) <= 0.7)`。

**适配含义**：我们的 GP 管线复用这一模式即可——搜索期只管单因子适应度 + cache 去重，|ρ|<0.7 去重放在**每代 callback 的组池环节**和**终审入库前**两次执行，且统一用 |ρ|。分钟级下 mutual IC 应取「时序相关」口径（与时序 IC 主适应度一致），不能沿用截面口径。

## 六、风险清单（⑥）

### 6.1 分钟级适应度计算成本（纯 CPU）

- 规模：39 只 × ~240 bar × ~245 日 ≈ 229 万格点/因子。表达式求值是滚动算子在 `(bars, 39)` 上的 numpy 操作，单因子评估估 50~500ms（视树深与窗口）；时序 IC 再 ~10ms。
- 总量：pop 1000 × gen 40 = 4 万次评估，cache 命中后实际 ~1-2 万次 → 单进程约 1~3 小时/轮，**可接受**。但：
  - 官方 `n_jobs>1` 走 pickling，我们的适应度闭包（calculator+cache）不可 pickle——**保持 n_jobs=1**，并行化改走「多 seed 多进程各自跑、cache 落盘合并」；
  - 费后净均抽检每次 ~1-10s，只给 top-k（≤20/代），预算 ≤3 分钟/代；
  - 进一步优化杠杆：float32、表达式编译缓存（相同子树）、初筛用半样本（隔日抽样）IC，终评才用全样本。

### 6.2 过拟合控制

| 措施 | 嵌入点 | 说明 |
|---|---|---|
| IS/OOS 切分 | 硬边界 2026-06-01 | GP 全程不见 OOS；终审一次性使用，禁止「看一眼 OOS 再改参数」 |
| MC 随机标签基线嵌入 GP 循环 | 每 4 代 callback | 对 label 做**日块级时间打乱**（block shuffle by day，保留日内形态、破坏可预测对齐），用当前 cache top-20 在乱序 label 上重算时序 IC，得 null 分布；真实 IC ≤ null 95 分位的因子打 `SUSPECT` 标记，不进候选 JSON。成本：20 因子 × 1 次重算 ≈ 秒级，可承受 |
| 复杂度控制 | 适应度硬闸 | token_len>20 判死（沿用）；可选 parsimony>0 软惩罚 |
| 多 seed 稳定性 | 3 seed × pop1000 | 只在 ≥2 个 seed 的 top 池出现的表达式才进终审 |
| 互相关去重 | callback 组池 + 入库前 | |ρ|<0.7，时序口径，统一取绝对值 |
| 多重比较 | 终审 | eval_factor 双向计数既有机制，不动 |

### 6.3 其他风险

- **截面→时序的 IC 口径切换**会改变 mutual IC 与池组合语义（§四），适配文档须随代码一并评审；
- **label 口径 A（30min 最高价）存在乐观偏差**（不可保证卖在最高），仅作搜索期代理，终审由 eval_factor 的实际出场臂裁决，报告须诚实声明此落差；
- 分钟级 rolling 算子的**跨日边界**：alphagen 的 RollingOperator 直接 unfold 时间轴，跨日窗口会把昨日尾盘拼进今日早盘——适配器必须按日分段或 mask，这是未来函数之外最容易漏的口径错误；
- vendor 的 gplearn 基于 0.4.2，`max_samples=0.9` 的 OOB 机制在字符串 X 下语义不明，建议设 `max_samples=1.0` 关闭。
