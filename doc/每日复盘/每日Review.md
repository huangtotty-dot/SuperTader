# 每日 Review · 做T报警系统

> **版本**：V2.0（2026-08-13 重建，对齐 V2 swing2pt 两点规则架构）
> **唯一目标**：持续提升**加仓质量**与**建仓质量**。其余条目都是为这两个目标服务的最小支撑集。
> **铁律**：每日只记录、不改参。候选变更写入当日报告「候选登记」，周六周 Review 统一走验证管线（离线筛查→全管线决赛→预注册闸门→上线）。唯一例外：P0 级故障（系统崩溃/告警失效/数据缺失/reconcile 类运营事故）当日处理。
> **报告落档**：`doc/每日复盘/YYYY-MM-DD_复盘.md`；自动数据段由 `python t_io/validation/daily_review/daily_review.py --date YYYY-MM-DD` 幂等注入。

---

## §1 晨间 reconcile（开盘前，~3 分钟）

- [ ] 用户发双账户持仓截图 → 更新 `holdings.json`（qty/base/cost/pre_close）
- [ ] **t_qty 铁律**：t_qty=活动T仓额度（can_t 闸门 + 买卖 sizing 基数），**reconcile 不碰 t_qty**；做T股严禁清零；纯底仓股（当前 603667/002639）保持 0
- [ ] 校验：按 qty × pre_close 逐户验算市值与截图一致（差 >1 元即查）
- [ ] 注意 eod_sync 每日会把 t_qty 钳到 ≤qty——若需保留"首买空间"（t>q），须当日开盘前重设并知会 Agent
- [ ] commit（message 注明口径来源：截图/口头）

## §2 收盘后自动采集（Agent 执行，~10 分钟）

- [ ] 跑 `daily_review.py --date 今日`，注入四段（KPI 日快照 / 阶段看板 / 加仓观察 / 建仓扫描）
- [ ] 读取 `decision_trace`：各股两点触发次数（触轨+RSI6）、时间分布
- [ ] 读取日志：推送条数（按股/方向）、防重桶拦截数、"qty=0 仅供参考"推送数
- [ ] 异常扫描：崩溃/重启、数据缺口（腾讯超时 akshare 兜底次数）、index_regime 断连

## §3 日内做T两点信号核对（V2 口径）

- [ ] 推送逐条列表：时间 / 代码 / 方向 / 价格 / 建议股数
- [ ] 对照行情：推送价 vs 当日高低点位置（卖在高位区/买在低位区？）
- [ ] 用户跟单情况（来自 §6 反馈）：跟了哪些、放弃了哪些、原因
- [ ] qty=0 参考推送：是否合理（满仓股两点触发=正常参考；非满仓 qty=0=异常需查 sizing）

## §4 加仓质量跟踪（主焦点 ①）

- [ ] 当日加仓建议逐笔：代码 / 类型（接回 or 首加）/ 建议价 / 建议股数 / 信号强度档
- [ ] 对照日内 VWAP：建议价优于 VWAP 还是劣于（买：低于 VWAP 为优）
- [ ] 用户实际加仓操作：价格 / 数量 / 与系统建议的偏差及原因
- [ ] **滚动前瞻表**（逐日更新，喂周 Review）：

| 日期 | 代码 | 类型 | 加仓价 | 当日VWAP | 次日浮盈% | 3日浮盈% | 判定 |
|------|------|------|--------|----------|-----------|----------|------|
| 例 | - | 接回/首加 | - | - | - | - | 优/平/劣 |

- [ ] 升级规则：加仓后次日浮亏 >3% 的占比 >50%（周内）→ 周六升级为加仓参数审查项

## §5 建仓质量跟踪（主焦点 ②）

- [ ] 当日扫描汇总：signal 股（代码/通道/分数/建议股数）、approaching 股（**精确标注差哪个条件**，如"差缩量"）
- [ ] signal 股是否经人工确认建仓；确认价 vs 建议价
- [ ] **滚动前瞻表**（逐日更新，喂周 Review）：

| 建仓日 | 代码 | 通道 | 确认价 | 3日浮盈% | 5日浮盈% | 得分变化 | 判定 |
|--------|------|------|--------|----------|----------|----------|------|
| 例 | - | 冰点/突破 | - | - | - | - | 成功/伪信号 |

- [ ] 假阳性标记：建仓后 3 日内跌回触发日低点下方，或综合得分骤降 ≥20
- [ ] 升级规则：signal 股 5 日胜率 <50%（滚动 10 笔）→ 周六升级建仓条件审查；连续 5 个交易日 0 signal → 升级信号密度审查

## §6 用户反馈模板（收盘后填写，~3 分钟）

```markdown
【日期】YYYY-MM-DD
【跟单】今天跟了系统的哪些建议？没跟哪些？为什么？
【加仓】今天手动加仓了吗？价位/数量/依据？
【建仓】扫描结果里有没有你认可但系统没推的股？或推了你不认可的？
【异常】飞书推送延迟/丢失？GUI 显示异常？
【其他】持仓变动预告、想法
```

## §7 KPI 日快照（自动段，喂周表）

K1 闭环净盈亏（虚拟口径）/ K4 滚动胜率（买/卖各 20 笔）/ K5 qty=0 拦截数 / 推送水位 / 底仓漂移（对照昨日快照，标注对账校准 or 交易漂移）

## §8 候选登记（只登记，不改参）

当日发现的所有优化想法统一写在这里，格式：`候选 | 针对问题 | 类别(建仓/加仓/做T/运营) | 预期收益`。周六周 Review 排序取舍。

## §9 复盘质量自检（写完必查）

- [ ] 事实 / 判断 / 动作分开写，不混
- [ ] 无越界改参（候选全部只登记）
- [ ] 同一异常只解释一次，口径前后一致
- [ ] 加仓/建仓两个滚动前瞻表已更新（哪怕当日无新增行，也要更新既有行的前瞻收益）
