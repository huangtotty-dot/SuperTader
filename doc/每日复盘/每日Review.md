# 每日 Review · 加仓 & 建仓质量

> **版本**：V2.3（2026-08-18）
> **唯一目标**：持续提升**加仓质量**与**建仓质量**。做T 不作为主目标，但自 V2.2 起增设「做T附章」——只记录"系统给了什么指引/用户实际做了什么/差在哪"，不逐条筛查信号质量。
> **V2.2 变更**：新增「六阶段逐一验收」结构（§0），每日报告先给阶段总览表再展开细节——解决"报告重点不突出、流程性故障（盘前/早盘段）无处安放"的问题。
> **V2.3 变更**：新增「§8 持续质量考量（跨日滚动层）」——六阶段管"当天每个时段是否合格"，§8 管"加仓/建仓质量是否在逐日变好"。前者是时间流视角，后者是质量演化视角；前瞻表停摆 10 天无人发现（08-08→08-18）就是缺这一层的直接教训。

## §0 六阶段逐一验收（每日必填总览表）

> 每日报告开头必须先给这张表，再按阶段展开。验收标记：🟢 通过 / 🟡 部分通过 / 🔴 不通过 / ⚪ 无产出（NA）。
> 🔴 阶段必须在正文给出：事实（trace/日志证据）→ 判断（归因）→ 动作（候选登记编号）。

| 阶段 | 时段 | 验收内容（合格线） | 数据来源 |
|------|------|--------------------|----------|
| S0 盘前地基 | 08:45-09:25 | reconcile 零分叉；竞价采集非空（amount/vol_ratio 有真实值）；preopen 产出焦点名单 | holdings 快照 diff、K2/K3、preopen_trace |
| S1 早盘窗口 | 09:25-10:00 | 大盘基调推送与开盘 5 分钟宽度不背离；持仓股高开急拉/急跌有预警 | 日志推送记录、preopen、分钟快照 |
| S2 盘中做T | 10:00-14:30 | 有波动的持仓股不全天 NO_SWING；高分信号被拦截时用户可感知；推送日志写真实拦截原因 | decision_trace、index_resonance、shadow_signals |
| S3 加仓 | 全天 | sizing_advice 逐笔可查；前瞻表既有行已更新；仓位水位有对照 | sizing_advice、signal_outcomes |
| S4 建仓 | 全天 | 扫描覆盖全池（无 unknown 股）；signal/approaching 精确标注缺口；signal 进入"待人工确认"出口 | position_builder、建仓扫描段 |
| S5 收盘归档 | 15:00 后 | daily_review/eod_sync 正常；异常（文件锁/数据源降级）逐条登记 | 日志、kpi JSON |

> 升级规则沿用：加仓次日浮亏>3% 占比>50%（周内）→ 周六审查；signal 5 日胜率<50%（滚动 10 笔）或连续 5 日 0 signal → 周六审查。**新增：任一阶段连续 2 日 🔴 → 周六列为强制议题。**

---
> **铁律**：每日只记录、不改参。候选变更写入当日报告「候选登记」，周六周 Review 统一走验证管线（离线筛查→全管线决赛→预注册闸门→上线）。唯一例外：P0 级故障（告警失效/数据缺失/reconcile 类运营事故）当日处理。
> **报告落档**：`doc/每日复盘/YYYY-MM-DD_复盘.md`；自动数据段由 `python t_io/validation/daily_review/daily_review.py --date YYYY-MM-DD` 幂等注入。

## §1 晨间 reconcile（开盘前，~3 分钟）

> 持仓准确性是加仓/建仓的地基——仓位基数错了，建议股数和建议价全错。

- [ ] 用户发双账户持仓截图 → 更新 `holdings.json`（qty/base/cost/pre_close）
- [ ] **t_qty 铁律**：t_qty=活动仓额度（can_t 闸门 + sizing 基数），**reconcile 不碰 t_qty**；做T股严禁清零；纯底仓股（当前 603667/002639）保持 0
- [ ] 校验：按 qty × pre_close 逐户验算市值与截图一致（差 >1 元即查）
- [ ] 注意 eod_sync 每日会把 t_qty 钳到 ≤qty——若需保留"首买空间"（t>q），须当日开盘前重设并知会 Agent
- [ ] commit（message 注明口径来源：截图/口头）

## §2 收盘后采集（Agent 执行，~10 分钟）

- [ ] 跑 `daily_review.py --date 今日`，注入数据段（加仓观察 / 建仓扫描 / 阶段看板）
- [ ] 推送通道健康：今日加仓/建仓相关推送是否正常发出（条数、有无延迟丢失）——只查通道，不评信号质量
- [ ] 异常扫描：崩溃/重启、数据缺口（腾讯超时 akshare 兜底次数）
- [ ] **前瞻表维护（V2.2 补）**：确认 forward_tracker 已当日结算（signal_outcomes.json 的 generated_at=今日）；若停摆，当日登记候选并手工补记到期行的前瞻收益

## §3 加仓质量跟踪（主焦点 ①）

- [ ] 当日加仓建议逐笔：代码 / 类型（接回 or 首加）/ 建议价 / 建议股数
- [ ] 对照日内 VWAP：建议价低于 VWAP 为优（买侧）
- [ ] 用户实际加仓操作：价格 / 数量 / 与系统建议的偏差及原因
- [ ] 仓位水位：加仓后个股市值 ÷ 总资金，对照仓位管理器目标比例（欠配/超配）
- [ ] **滚动前瞻表**（逐日更新既有行的前瞻收益，喂周 Review）：

| 日期 | 代码 | 类型 | 加仓价 | 当日VWAP | 次日浮盈% | 3日浮盈% | 判定 |
|------|------|------|--------|----------|-----------|----------|------|
| 例 | - | 接回/首加 | - | - | - | - | 优/平/劣 |

- [ ] 升级规则：加仓后次日浮亏 >3% 的占比 >50%（周内）→ 周六升级为加仓参数审查项

## §4 建仓质量跟踪（主焦点 ②）

- [ ] 当日扫描汇总：signal 股（代码/通道/分数/建议股数）、approaching 股（**精确标注差哪个条件**，如"差缩量"）
- [ ] signal 股是否经人工确认建仓；确认价 vs 建议价
- [ ] **滚动前瞻表**（逐日更新既有行的前瞻收益，喂周 Review）：

| 建仓日 | 代码 | 通道 | 确认价 | 3日浮盈% | 5日浮盈% | 得分变化 | 判定 |
|--------|------|------|--------|----------|----------|----------|------|
| 例 | - | 冰点/突破 | - | - | - | - | 成功/伪信号 |

- [ ] 假阳性标记：建仓后 3 日内跌回触发日低点下方，或综合得分骤降 ≥20
- [ ] 升级规则：signal 股 5 日胜率 <50%（滚动 10 笔）→ 周六升级建仓条件审查；连续 5 个交易日 0 signal → 升级信号密度审查

## §4.5 做T附章（V2.2 新增：只记录不对账式筛查）

> 定位：做T 不是主目标，但"系统指引 vs 用户操作"的落差必须可见。每日三问即可，不展开因子级分析（因子级归周六管线）。

- [ ] 系统全天做T信号清单：代码/方向/时间/价格/是否推送/未推送的真实原因（阈值/防重/共振——**禁止统一写"静默"**）
- [ ] 当日振幅 >3% 的持仓股：系统是否给过任何指引（信号/预警/面板），还是全天 NO_SWING
- [ ] 用户实际操作（含"没动"）：时间/价格/与系统指引的差异；若全天零操作，记录原因（没看到/不敢/不认可）
- [ ] 机会窗对照：当日最大的理论做T窗口（高点→低点时段与幅度）vs 系统与用户各自的覆盖情况

## §5 用户反馈模板（收盘后填写，~3 分钟）

```markdown
【日期】YYYY-MM-DD
【做T】今天手动做T了吗（含"没动"）？价位/依据？系统指引与你的判断差在哪？
【加仓】今天手动加仓了吗？价位/数量/依据？系统建议与你的想法差在哪？
【建仓】扫描结果里有没有你认可但系统没推的股？或推了你不认可的？
【异常】推送延迟/丢失？GUI 显示异常？
【其他】持仓变动预告、想法
```

## §6 候选登记（只登记，不改参）

当日发现的所有优化想法统一写在这里，格式：`候选 | 针对问题 | 类别(建仓/加仓/运营) | 预期收益`。周六周 Review 排序取舍。

## §8 持续质量考量（跨日滚动层，V2.3 新增 · 每日必填）

> 定位：六阶段回答"今天每个时段合格吗"，本层回答"加仓/建仓质量是否在逐日变好"。
> 三个机制保证"持续"：**①新鲜度闸（不更新就报警）②水位线（指标挂趋势，不只看当日）③转化漏斗（信号→确认→执行→结算，每环都算转化率）**。

### 8.1 新鲜度闸（每日第一查，不满足即 🔴 并登记候选）

- [ ] 加仓前瞻表：既有行中到期的（次日/3日）收益**已结算**——逐行核对，不允许"挂着不结算"
- [ ] 建仓前瞻表：同上（3日/5日到期行）
- [ ] `signal_outcomes.json` 的 `generated_at` = 今日（forward_tracker 当日已跑）
- [ ] 样本积累进度：signal T+5 已验证样本 **x/20**（距 08-08 起算）——**连续 5 个交易日 x 不增长 → 周六强制议题**（样本永远攒不够 = 验证制度空转）

### 8.2 质量水位线（每日滚动更新一行，趋势比单日值重要）

| 日期 | 加仓：滚动10笔次日胜率 | 加仓：浮亏>3%占比(周内) | 建仓：signal 5日胜率(滚动10笔) | 建仓：连续0 signal天数 | 建仓：approaching 缺口主因 |
|------|------------------------|--------------------------|--------------------------------|------------------------|----------------------------|
| 例 | - | - | - | - | 如"全卡差缩量" |

- [ ] 任一水位指标连续 3 日恶化 → 不等周六，当日升级为强制议题候选
- [ ] 升级规则汇总（触发即周六审查）：加仓次日浮亏>3% 占比>50%（周内）；signal 5日胜率<50%（滚动10笔）；连续 5 日 0 signal；样本 5 日零增长；前瞻表停摆 >1 日

### 8.3 转化漏斗（C18 待确认清单上线后启用，之前记 NA）

> 信号再多，不转化为建仓就是沉没（08-14 600176 +5.9% 未确认的教训）。

| 日期 | signal 推送数 | 人工确认数 | 实际建仓数 | 确认→建仓转化率 | 未确认/未建仓原因分类 |
|------|---------------|------------|------------|------------------|------------------------|
| 例 | - | - | - | - | 没看到/不敢/不认可/已满仓 |

- [ ] 加仓漏斗同理：系统建议 → 用户操作 → 偏差原因（§3 的当日记录在此沉淀为趋势）
- [ ] "不敢"类原因出现 ≥2 次/周 → 周六列为"信号可执行性"议题（信号再好，用户不敢跟 = 需要更强的背书信息或更小的建议仓位）

### 8.4 周六管线入口（周五收盘后整理）

- [ ] 本周候选清单汇总（编号/问题/类别/预期收益）+ 上周候选处置回收（上线/否决/挂起及原因）
- [ ] 本周水位线趋势小结：加仓/建仓各一句话（在变好/持平/恶化，证据是什么）

## §7 复盘质量自检（写完必查）

- [ ] 事实 / 判断 / 动作分开写，不混
- [ ] 无越界改参（候选全部只登记）
- [ ] 同一异常只解释一次，口径前后一致
- [ ] 加仓/建仓两个滚动前瞻表已更新（哪怕当日无新增行，也要更新既有行的前瞻收益）
- [ ] **§8 已填（V2.3 补）**：新鲜度闸四项全过或已登记 🔴；水位线新增今日一行；漏斗当日有记录（含 NA）
