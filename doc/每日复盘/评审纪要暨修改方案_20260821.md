## 二、批次 B：策略变更包（同日同批上线，捆绑红线见〇-5）

### B-1 指数缓存日期校验（timing_gate，P1 bug 修复）

- **问题**：`timing_gate.py:60-66` `_fetch_index_daily()` 只要 `INDEX_CACHE`（`t_io/cache/daily_kline/index_sh000001.json`）存在就直接用，不校验最后日期 → 盘中/盘前用昨日收盘判今日 regime。08-18 因此把唯一 trend_up 日（收 3990.30 > MA60 3980.94）误判 range，0 signal。
- **改法**：读缓存时校验 `rows[-1]["date"]`：
  - 缓存最后日期 < 最近交易日 且当前时间 ≥ 09:15 → 重拉；
  - 重拉失败回退旧缓存并在 trace 标 `index_cache_stale: true`。
  - 注意 15:00 前当日 K 线未完成：盘中判定用的"当日 close"是盘中价，`_regime` 语义保持不变（现状即用最新可得 close），只修"昨天冒充今天"。
- **验收**：手动把缓存最后日期改早一天，调用 `_regime("2026-08-21")` 后缓存自动刷新到最新交易日。

### B-2 C20 竞价现实校验（双条件与门版，议题 2，P0）

- **位置**：`main.py:630 _maybe_push_index_regime_morning`（09:26 推送）与 `main.py:492 _build_index_regime_card`。
- **触发窗口**：09:26 推送前，读当日 `auction_{date}.json` 最后一个 slot（通常 09:22）的 `pct_vs_preclose` 中位数 + `preopen_{date}.json` 的 `auction_summary`（A-2 修复后有值）。
- **判定（双条件与门，评审定稿）**：
  ```
  gap_med = 持仓 pct_vs_preclose 中位数（剔除 000988_B 等 _B 重复行）
  top20_bearish = (top20_down / (top20_up + top20_down)) >= 0.60   # top20_status=empty 时视为缺失
  Level1（降级标注）: gap_med <= -1.0% 且 top20_bearish
  Level2（推翻基调）: gap_med <= -2.5% 且 top20_down占比 >= 0.75
  数据缺失降级：top20 缺失时退化为缺口单条件（-1.0%/-2.5%），卡片标注"Top20缺失·单条件"
  ```
- **动作**：
  - 原基调为看多类（单边上涨/强势/震荡偏强）且 Level2 → 基调改为"震荡观察"，卡片顶部加红条："⚠️ 竞价现实与基调背离：持仓缺口 {gap_med}%，Top20 跌 {down}/{total}"；
  - Level1 → 基调不变，卡片加黄条标注同上；
  - 非看多基调不动作（只纠"乐观错"，不纠"悲观错"——悲观错的成本是少赚，乐观错的成本是实亏）。
- **证据**：08-19（缺口 -3.17%、3涨/17跌、推"单边上涨"、实际 -2.40%）本规则 Level2 命中；08-17（缺口 -2.45% 但 Top20 17涨/3跌、实际 +1.41%）双条件不触发，避免误伤。

- **验收**：用 08-19 数据回放 `_maybe_push_index_regime_morning` → 产出"震荡观察"+红条；用 08-17 数据回放 → 不触发；用 08-21 数据（缺口 -0.71%、10/10）→ 不触发。
