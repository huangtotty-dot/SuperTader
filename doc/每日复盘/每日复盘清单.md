# 每日复盘清单 · 做T报警系统

> **版本**：V1.0（2026-08-02 建立）
> **目的**：每日收盘后 15:30 执行，**只记录、不改参**；候选变更累积至每周统一优化。
> **配套**：用户反馈模板见 §2；诊断对照表见 §3；周度优化流程见 §4；遗留观察项追踪见 §5。
> **铁律**：每日复盘冻结参数。唯一例外是 P0 级 bug（系统崩溃、告警失效、数据缺失）。优化项一律进 §4 周度批次，走验证管线（离线筛查→全管线决赛→预注册闸门）后方可上线。

## §1 每日执行流程（收盘后 ~15:30，约 20 分钟）

### 第 1 步：系统自动数据项（Agent 执行）

- [ ] 读取 `t_io/traces/decision_trace_YYYY-MM-DD.jsonl`，统计当日每只股票：触发信号数（买/卖）、最大 buy_score / sell_score、日内振幅
- [ ] 读取 `t_io/traces/shadow_signals_YYYY-MM-DD.jsonl`，提取**接近阈值但未触发**的信号（阈值 ±3 分内）——漏单分析的核心素材
- [ ] **qty 冻结检查**：当日所有信号 qty 是否 >0（000988 历史教训：195 条信号全 qty=0 的"幻影簿记"冻结链，pct×t_qty < 100 起报单元即冻结）
- [ ] 当日闭环统计：成交对数、净盈亏、胜率
- [ ] 日型标注：当日每只股票属于 阴跌 / 盘整 / 上涨 / bull，对应信号胜率（阴跌日买入 wr 是已知洼地，单独跟踪）
- [ ] 飞书告警核对：信号触发与告警推送是否一一对应、有无延迟/丢失
- [ ] **KPI 日快照**（喂给周复盘 §1.5 周 KPI 表）：当日闭环净盈亏、各股持仓 cost 与底仓股数快照（对照昨日，记录漂移及原因）、当日 qty=0 拦截数（按股）
- [ ] **加仓条件逐股跟踪（用户 2026-08-06 升级，重点考察点）**：
  a) **四条件逐股状态**（GUI `加仓观察` 段自动产出：回踩支撑/支撑守住/收盘>MA5/VWAP确认），记录每只持仓股通过数（X/4）和未通过的具体条件
  b) **条件全满足股**：触及支撑且守住不破 + 收盘>MA5 + VWAP确认——若系统有买入信号（分数），记录分数；若无，登记"回踩到位但无买信号"（缺信号侧待 P2 优化）
  c) **盘中 GUI 报警核对**：全满足股是否在盘中触发了 ✅ 加仓条件报警；有无遗漏或多报
  d) 用户人工加仓操作（来自晨间对账或 §2 反馈）：与系统条件对照——系统判断可加仓的 vs 用户实际操作的，记录偏差原因
  e) 各股仓位水位（市值 ÷ 总资产）：标记是否超过个股最大仓位约束（待周六定具体上限）
  f) **加仓决策质量**：当日若执行了加仓，记录加仓价 vs 日内 VWAP、加仓后是否破位、加仓次日浮盈；纳入周复盘"加仓决策质量跟踪"
- [ ] **顶背离报警质量跟踪（2026-08-07 新增，严重顶背离≥2指标触发报警）**：
  a) 当日顶背离报警数（按股）+ 指标类型分布（MACD/RSI/KDJ/量价）
  b) **报警后 3 日验证**：严重背离报警后股价是否回调（背离兑现率）——兑现=3日最大回撤>3%或收盘破5日线；未兑现=报警后继续涨（误报）
  c) 累计背离兑现率 / 误报率 → 喂周复盘优化阈值
  d) 飞书推送核对：严重背离报警是否推送成功
- [ ] **建仓信号扫描（用户 2026-08-06 升级，量化为可跟踪指标）**：
  a) **逐股五条件通过表**：生成表格列出每只候选股的 MACD多头/BOLL中轨/RSI健康/缩量/回踩支撑 各自通过状态（●/○）+ 综合得分 + 判定
  b) 综合得分 ≥70 的 **signal** 股票（代码、分数、建议股数/价格/资金）→ 标记是否通过人工确认
  c) 40~60 分的 **approaching** 股票，**精确标注差哪个条件**（如"差缩量 8 分"、"差 RSI 健康 12 分"）——这是优化建仓条件的核心素材
  d) **在线拉取检查**：13 只非持仓 watchlist 股是否成功从腾讯分钟线在线拉取数据；有多少只因网络/接口异常仍无数据
- [ ] **建仓决策质量跟踪（2026-08-06 新增）**：
  a) **建仓后表现**：对 status=`confirmed` 的建仓股，按 `signal_history` 中确认价 vs 当日收盘价，计算浮盈/浮亏（金额+百分比）；建仓 >5 日仍未盈利的标为"建仓失败候选"
  b) **信号稳定性**：signal 股在后续 3 日内的综合得分变化——买入后得分骤降（≥20 分）说明"买入即恶化"，标记为伪信号
  c) **条件前瞻性**：对比建仓当天五条件通过情况与建仓后 3 天的实际走势——哪些条件"通过≠有效"（例：MACD 多头通过但 3 天后死叉），累积统计各条件的假阳性率，喂周复盘优化

### 第 2 步：用户人工反馈（模板见 §2，约 5 分钟）

### 第 3 步：分类诊断（对照 §3 表）+ 输出当日复盘报告

- [ ] 报告保存至 `E:\06_T\doc\每日复盘\YYYY-MM-DD_复盘.md`
- [ ] 发现的候选变更写入当日报告的「候选变更登记」段（**只登记，不实施**）
- [ ] 报告含「系统阶段看板」固定段（`daily_review.py` 自动读取 `t_io/validation/daily_review/stage_board.json` 注入，幂等标记替换；阶段变更只在验收事件发生时由周/月复盘维护该 json）

## §2 用户反馈模板（复制填写）

```markdown
【日期】YYYY-MM-DD

【信号命中】✓
- 代码 名称：信号时间 + 简要评价（如"卖得准"、"偏早"、"偏晚"）

【信号漏单】✗
- 代码 名称：你觉得该触发但实际没有的时间点 + 原因猜测

【信号误报】✗
- 代码 名称：触发了但你认为不该卖/买的时间点 + 原因

【开盘急跌】
- 代码 名称：开盘短时间内大幅下跌，你的实际操作 + 系统是否及时建议卖出/观望

【全天弱势】
- 代码 名称：价格全天在均线下方运行，低吸时机判断是否准确

【板块/大盘感受】
- 今天整体市场情绪（如"半导体很强"、"大盘死水"）

【其他】
- 系统异常、飞书告警问题、持仓变动、高抛低吸组合建议等
```

## §3 诊断对照表

| 反馈类型 | 诊断动作 | 输出 |
|----------|----------|------|
| 信号命中 ✓ | 确认触发路径与因子权重（decision_trace 因子贡献分解） | 记录成功模式 |
| 信号漏单 ✗ | 查 `stand_down_reason` + shadow_signals | 具体阻挡原因 + 调参建议（登记） |
| 信号误报 ✗ | 查触发因子和评分构成 | 阈值/门控调整建议（登记） |
| 开盘急跌 | 查 `preopen_trace` + 开盘后 5 分钟 decision_trace | 开盘响应灵敏度建议（登记） |
| 全天弱势 | 查 `daily_above_ma5`、vwap 偏离度、分钟线 MA 状态 | 均线过滤/低吸阈值建议（登记） |
| 分仓/次数 | 查 `_calc_trade_qty()` 分配和 cycle_count | 分仓比例、次数上限建议（登记） |
| 板块感受 | 查 benchmark_state 与用户感受是否一致 | 大盘敏感度建议（登记） |
| **qty=0 信号** | 查 pct×t_qty 是否 <100（min_unit 冻结链） | **当日处理**（运营项，勿拖） |
| **回踩支撑/加仓** | 查 daily_ctx 均线位置（MA5/10/20/60）+ 日内 VWAP + shadow_signals（回踩位置买信号分数）+ GUI `加仓观察` 四条件逐股状态 | 加仓候选登记（全满足股记录分数）；条件缺口股标注缺哪项 |
| **加仓决策质量** | 查加仓执行记录（用户反馈或系统成交）：加仓价 vs VWAP、加仓后是否破位、次日浮盈 | 单次加仓胜率、破位率、浮盈分布 → 喂周复盘加仓质量跟踪 |
| **建仓信号触发** | 查 `position_builder.py` 输出（五条件逐项状态+综合得分+建议仓位）；在线拉取成功率统计 | signal 股记录候选（人工确认后手动入 holdings）；approaching 股精确标注缺口条件 |
| **建仓条件前瞻性** | 对比建仓日条件与后续 3 日走势："通过但反转"的条件（假阳性） | 假阳性率统计 → 优化条件权重/阈值；标记伪信号股 |
| **建仓效果回测** | 查已确认建仓股的 signal_history（买入价 vs 当日收盘价）；建仓后 3 日综合得分变化 | 跌幅 >5% 或得分骤降 >20 → 建仓失败候选，周复盘审查 |

## §3.1 复盘质量自检要点（写完后必查）

- [ ] **状态是否一致**：同一事项在正文、§5、KPI、看板里是否同口径；已关闭的事项有没有残留“待拍板”。
- [ ] **事实/判断/动作是否分开**：事实、机制判断、下一步动作有没有混写。
- [ ] **有没有越界改参**：是否只登记候选，不夹带隐性改参或提前上线表述。
- [ ] **异常是否只解释一次**：同一机制问题有没有重复造新口径，导致前后打架。
- [ ] **候选/验收是否分清**：观察项、优化管线中、已验收三类状态有没有混用。
